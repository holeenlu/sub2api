# 前端完整验收用例

本目录是 sub2api 重构前端的版本化验收入口。用例已经编写不等于执行通过；完整验收在前后端实现完成、源码和镜像冻结后执行。开发期间继续执行与实际改动有关的单元、组件、合同和集成回归。

## 文件和唯一来源

- [cases.json](cases.json)：机器可读用例目录，包含唯一编号、优先级、角色、前置条件、步骤、预期结果、清理及证据要求。
- [CASES.md](CASES.md)：从同一目录生成的可阅读索引，按模块定位用例。
- [route-inventory.json](route-inventory.json)：实际注册页面、供应商 tab、重定向和 alias 的覆盖依据；不把组件文件数量当页面数。
- [FIXTURES.md](FIXTURES.md)：隔离环境、角色、数据和外部依赖准备要求。
- [EXECUTION.md](EXECUTION.md)：项目完成后的执行顺序、结果记录、阻塞与验收判定。
- [result-template.json](result-template.json)：单条执行记录模板。真实结果放在本地任务证据目录；不得把测试凭据、令牌或敏感请求体提交到仓库。

公共清理和证据要求由cases.json的defaults唯一声明；每条用例继承这些要求，局部字段如有提供则追加，不另复制维护。Schema仅校验结构，真实结果仍需审查证据。

用例的业务事实来自现有路由、组件和 API 合同；架构与编码要求继续以 docs/architecture-rebuild/ 为准，不在本目录建立第二套产品规则。根验证计划只需链接本入口。

- [result.schema.json](result.schema.json)：执行记录结构约束；没有步骤和证据的记录不能标passed。
- [catalog.schema.json](catalog.schema.json)：用例结构约束；定义状态与执行结果分开。

## 覆盖层次

1. 静态合同：类型、lint、领域依赖、翻译完整性、公开入口、默认品牌和下载制品。
2. 单元/组件：字段语义、事件载荷、错误处理、请求归属、取消、幂等恢复和生命周期。
3. 本地端到端：实际 Docker 前端、实际隔离 API/数据库，通过浏览器逐页操作。
4. 外部集成：获准的 OAuth、支付 sandbox、真实上游、邮件、对象存储等；必须独立标注环境和证据等级。

前一层通过不能替代后一层。使用替身的测试必须标明替身边界，不得记录为真实支付、真实推理或真实 OAuth 验收。

## 执行约束

- 主站和供应商门户均使用冻结的真实镜像。记录 UI/API 镜像 ID、源码摘要、浏览器、角色、语言和 viewport。
- 所有角色、账号、Key、资源、订单和文件均来自本机隔离 fixture；不使用生产数据，不访问真实用户账号。
- 不为测试放松权限、供应商 origin、证书、合规或幂等保护。供应商门户需要真实受信任的 HTTPS。
- 每个页面验证进入、刷新、返回及其真实存在的主要交互；空列表、成功 toast 或 HTTP 200 单独都不能证明完整流程正确。
- 取消、409、失败、迟到响应、登出、角色切换及权限撤回必须验证没有错误副作用或跨主体数据回写。
- 涉及不可自动代行的确认或缺少外部条件时，记录具体阻塞。不能将 blocked、not_run 或未经审阅的 not_applicable 计为通过。
- 不增加新的测试平台或依赖。本目录复用既有 Vitest、类型/lint、生成器、Docker 以及浏览器能力。

## 更新方式

路由、权限、公开 API、设置字段、异步流程或品牌输出变化时，修改同一用例目录并复核影响范围。路径变更需更新对应来源引用，删除已退休行为的专属用例；有依据保留的历史数据读取需明确注明理由和退出条件。

本文及初始结果模板均不声明当前项目已经通过完整验收。
