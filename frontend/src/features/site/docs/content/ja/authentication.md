## 基本URL

実際のこのプロジェクトのエンドポイントは、公開システム設定とコンソールから取得します。生の HTTP リクエストでは `{root}/v1/...` を使用します。OpenAI SDK は通常、`base_url` に `{root}/v1` を使用します。Anthropic SDK はルートを使用し、`/v1/messages` を追加します。

例では、`/v1/v1` になるのを避けるため、設定値を正規化しています。カスタムデプロイドメイン、プロキシパス、実行時設定はプレースホルダーより優先されます。

## 推奨ヘッダー

| プロトコル | ヘッダー |
| --- | --- |
| OpenAI 互換 | `Authorization: Bearer $API_KEY` |
| Anthropic Messages | `x-api-key: $API_KEY` |
| Gemini 互換 | `x-goog-api-key: $API_KEY` |

1 回のリクエストにつき、キー用ヘッダーは 1 つだけ使用してください。ゲートウェイは、2 つの互換性用ヘッダーより先に、有効な Bearer ヘッダーを読み取ります。生の Messages リクエストには、該当する `anthropic-version` も含めます。

## キー、グループ、安全性

キーのグループによって、モデルの許可リスト、ルーティング、レート、同時実行数、その他のポリシーが制御されます。公開一覧ですべてのキーが利用できることが保証されるわけではありません。検出には `GET /v1/models` を使用し、実際のリクエストで確認してください。

キーは、サーバー側の環境変数またはシークレットマネージャーで管理してください。URL、ブラウザーコード、スクリーンショット、リポジトリ、ログには決して含めないでください。キーが漏えいした場合は、直ちに無効化して置き換えてください。
