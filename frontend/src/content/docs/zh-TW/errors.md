## 錯誤結構

KDAN 保留入口協議的錯誤格式。OpenAI、Anthropic 與 Google 風格的欄位可能不同；用戶端應至少記錄 HTTP 狀態、錯誤類型、訊息和回應 request ID。

| 狀態 | 常見原因 | 建議 |
| --- | --- | --- |
| 400 | JSON、參數、模型欄位或請求體不合法 | 對照目前協議和型號參數，不盲目重試 |
| 401 | 缺少或無效 API Key | 檢查請求標頭、Key 狀態與接入地址 |
| 403 | 使用者或分組沒有所需權限 | 在控制台確認 Key 分組與授權 |
| 404 | 模型未對該分組開放、平台不支援端點或條件功能關閉 | 呼叫 `/v1/models` 並核對介面範圍 |
| 413 | 請求體超過閘道器限制 | 壓縮、改用 URL 或拆分請求 |
| 429 | Key、分組或上游速率限制／並行已滿 | 遵守 `Retry-After`，使用帶抖動的指數退避 |
| 5xx | 閘道器依賴或上游暫時失敗 | 保留 request ID；僅對冪等或可安全重試的請求退避重試 |

## 重試邊界

文字生成重試可能產生第二份輸出和費用。影像生成、編輯與工具副作用請求不應在連線斷開後無條件重複提交。用戶端應使用自己的冪等邊界，並把“是否收到回應”與“請求是否執行”分開判斷。

## 檢查順序

確認地址與鑑權 → 確認 Key 分組 → 確認模型在該分組開放 → 確認端點適用 → 記錄 request ID 和時間 → 再聯絡支援。
