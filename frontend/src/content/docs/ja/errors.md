## エラー処理

このプロジェクトでは、受信したプロトコルのエラー形式をそのまま保持します。OpenAI、Anthropic、Google 形式のフィールドは異なる場合があります。HTTP ステータス、エラーの種類、メッセージ、レスポンスのリクエスト ID をログに記録してください。

| ステータス | よくある原因 | 対応 |
| --- | --- | --- |
| 400 | 無効な JSON、パラメータ、モデルフィールド、またはボディ | リクエストを修正し、無条件に再試行しない |
| 401 | API キーがない、または無効 | ヘッダー、キーの状態、ベース URL を確認する |
| 403 | ユーザーまたはグループにアクセス権がない | キーのグループと認可を確認する |
| 404 | モデルが有効化されていない、エンドポイントに対応していない、または条件付き機能が無効 | `/v1/models` を呼び出し、エンドポイントのスコープを確認する |
| 413 | ボディがゲートウェイの上限を超えている | 圧縮する、URL を使用する、またはリクエストを分割する |
| 429 | キー、グループ、またはアップストリームのレート制限／同時実行数制限 | `Retry-After` に従い、ジッター付き指数バックオフを使用する |
| 5xx | ゲートウェイの依存先またはアップストリームの障害 | リクエスト ID を保持し、安全な場合にのみ再試行する |

再試行によって、2 回目の出力が生成され、請求が発生する可能性があります。画像リクエストや副作用のあるツール呼び出しは、切断後に無条件で再送信しないでください。アドレス、認証、グループ、モデル、エンドポイントの順に確認してください。
