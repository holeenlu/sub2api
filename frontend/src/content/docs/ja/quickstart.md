## 前提条件

コンソールで APIキーを作成し、そのグループを確認します。グループによって、使用できるモデル、レート、制限、アップストリームのルーティングが決まります。公開モデルページだけを見て、APIキーのアクセス権を推測しないでください。

コンソールからエンドポイントをコピーします。以下の `API_BASE_URL` は末尾に `/v1` を含まないルートです。設定値にすでにこのサフィックスが含まれている場合は、エンドポイントを連結する前に削除してください。

## プロトコルを選択する

| 既存のクライアントまたはタスク | 推奨エンドポイント |
| --- | --- |
| OpenAI Responses SDK またはツールワークフロー | `POST /v1/responses` |
| OpenAI Chat Completions クライアント | `POST /v1/chat/completions` |
| Anthropic SDK、Claude Code、または Messages ペイロード | `POST /v1/messages` |
| 画像生成または編集 | `POST /v1/images/generations`、`POST /v1/images/edits` |

## 実行と検証

以下の例では、現在のグループで有効になっているモデルを選択します。サーバーのリクエスト ID を保存し、プロトコル固有の結果を読み取り、レスポンスのモデル、使用量、キャッシュフィールド、コストをコンソールの使用量記録と比較します。

モデルが 404 を返した場合は、再試行する前に APIキーのグループ、正確なモデル ID、エンドポイントのスコープを確認してください。本番クライアントでは、タイムアウトを設定し、429/5xx レスポンスを処理し、キーをログに出力しないようにしてください。
