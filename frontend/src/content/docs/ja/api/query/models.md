## エンドポイントと認証

```http
GET /v1/models
Authorization: Bearer $API_KEY
```

モデル一覧は、APIキーのグループ、プラットフォーム、アカウント/チャネルのマッピング、およびモデルの許可リストによって異なります。推論を実行する際に使用するものと同じAPIキーでクエリしてください。

## 最小限のリクエストとレスポンス

```bash
curl "$API_BASE_URL/v1/models" \
  -H "Authorization: Bearer $API_KEY"
```

OpenAI互換グループは通常、次の形式で返します。

```json
{
  "object":"list",
  "data":[{"id":"YOUR_MODEL_ID","object":"model","created":1704067200,"owned_by":"openai","type":"model","display_name":"YOUR_MODEL_ID"}]
}
```

Anthropic形式の項目では、`type`、`display_name`、およびISO形式の`created_at`を使用できます。Grokの項目では、推論負荷に関するメタデータが追加される場合があります。安定した検出用フィールドとして`data[].id`を扱い、オプションのメタデータは防御的に読み取ってください。

## 表示されることと、利用可能であることは別です

ハンドラーはアカウント/チャネルのマッピングを収集し、グループの許可リストを適用します。ライブのマッピングが空の場合、一部のプラットフォームではコードで定義されたデフォルトにフォールバックします。また、複合グループではデフォルト候補を使用する場合があります。したがって、一覧に表示されたIDは統合候補として表示されていることを示すだけであり、スケジュール可能なアカウントの存在や、すべてのChat、Responses、Messages、またはImagesパラメータのサポートを保証するものではありません。

一覧を取得し、正確なIDを選択して、対象エンドポイントの最小限のリクエストを送信し、その後HTTPレスポンスと使用量を確認してください。`model_not_found`またはアカウントなしエラーが発生した場合は、短時間だけ保持するキャッシュを直ちに更新してください。

## 単一モデルのパスとCodexモード

`GET /v1/models/{model}`はModelsハンドラーを再利用し、パスパラメータでフィルタリングします。すべてのプラットフォームが公式のRetrieve Modelフィールドセットを返すとは限らないため、前提にしないでください。

ネイティブのGemini SDKでは、`GET /v1beta/models`と`GET /v1beta/models/{model}`という別々のルートを使用し、`models[]` / `models/...`形式で返します。通常のパスはGeminiグループに限定されています。ネイティブGeminiの検出にOpenAI形式の`/v1/models`エンベロープを適用しないでください。

`GET /v1/models`に`client_version`を追加すると、通常の`{"object":"list","data":[]}`出力ではなく、Codexモデルマニフェストのパスが選択されます。汎用SDKやアプリケーションのモデル選択UIでは省略してください。

## エラーとトラブルシューティング

401は通常、キーがないか無効であることを示します。403/404はグループまたは許可リストのポリシーを反映している可能性があります。5xxは、ゲートウェイの依存サービスまたはアップストリームの検出における障害を示します。ステータス、リクエストID、エラーボディを記録し、キーとベースURLが推論リクエストと一致していることを確認してください。グローバルなモデルマーケットプレイスは、このキーにスコープされた一覧とは異なります。
