## 错误结构

Tokensavy 保留入口协议的错误格式。OpenAI、Anthropic 与 Google 风格的字段可能不同；客户端应至少记录 HTTP 状态、错误类型、消息和响应 request ID。

| 状态 | 常见原因 | 建议 |
| --- | --- | --- |
| 400 | JSON、参数、模型字段或请求体不合法 | 对照当前协议和型号参数，不盲目重试 |
| 401 | 缺少或无效 API Key | 检查请求头、Key 状态与接入地址 |
| 403 | 用户或分组没有所需权限 | 在控制台确认 Key 分组与授权 |
| 404 | 模型未对该分组开放、平台不支持端点或条件功能关闭 | 调用 `/v1/models` 并核对接口范围 |
| 413 | 请求体超过网关限制 | 压缩、改用 URL 或拆分请求 |
| 429 | Key、分组或上游限流／并发已满 | 遵守 `Retry-After`，使用带抖动的指数退避 |
| 5xx | 网关依赖或上游暂时失败 | 保留 request ID；仅对幂等或可安全重试的请求退避重试 |

## 重试边界

文本生成重试可能产生第二份输出和费用。图像生成、编辑与工具副作用请求不应在连接断开后无条件重复提交。客户端应使用自己的幂等边界，并把“是否收到响应”与“请求是否执行”分开判断。

## 排查顺序

确认地址与鉴权 → 确认 Key 分组 → 确认模型在该分组开放 → 确认端点适用 → 记录 request ID 和时间 → 再联系支持。
