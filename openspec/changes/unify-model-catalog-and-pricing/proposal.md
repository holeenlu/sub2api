# 统一模型目录、能力与价格更新

状态：规划草案，尚未实施。审查日期：2026-09-30（Asia/Shanghai）。

## Why

模型发现、账号限制、分组授权、别名映射、能力说明和价格目前由不同入口拼装。项目已具备共享分组目录、上游模型同步和动态价格同步，但它们没有形成一个可持久化、可追溯、统一发布的结果。新型号仍可能受编译内置列表、名称识别规则、旧 Codex 模板和静态价格兜底限制。

目标是在已支持的协议内，厂商发布新模型后，通过数据同步自动完成发现、能力补充、定价和目录发布，无需为每个型号重新发版。普通页面继续快速读取本地结果。新协议、新认证方式或客户端不认识的工具能力仍可能需要适配，不能承诺任何新模型都无条件立即可用。

## What Changes

- 建立统一模型目录：持久保存来源快照、逐字段能力证据、账号可见性、版本与更新状态。
- 模型发现与权限解耦：账号管理可服务范围，分组管理用户可用范围；同步不覆盖白名单或映射。
- 保留固定账号发现，定位为目录数据源选择，明确失败回退；不把固定来源等同于业务调度账号。
- 建立独立官方价格记录；客户价由分组价卡、渠道价卡和倍率解析；账号采购成本单独保存。
- 统一 `/v1/models`、Codex manifest、模型广场、各管理选择器的数据基础，按身份和客户端协议投影。
- 后端按计划同步并在数据齐备后发布版本；前端页面不等待上游。新模型自动开放采用一次配置的策略。
- Codex 推荐模型由分组有效目录计算，逐型号代码表退为离线兼容资料；本地 JSON 文件提供明确更新机制。
- 新增分组目录解释功能，直接显示模型为何缺失、哪个字段未齐、当前采用哪条价格规则。

## Capabilities

### New Capabilities

- `model-catalog-registry`：统一发现、持久快照、字段来源、兼容数据包与版本发布。
- `model-catalog-publication`：新模型准入、后台同步、显式撤销与失败恢复。
- `official-price-registry`：官方参考价独立于销售价与采购成本，保留历史生效版本。
- `model-resolution-explain`：对指定账号、分组、密钥和客户端解释模型与价格结果。

### Modified Capabilities

- 固定账号模型发现与缓存：迁移到统一同步机制，保留已有选择和回退策略。
- 账号模型限制、分组白名单、渠道映射：共享同一条解析链，不再通过定价表决定模型存在性。
- Codex 配置和目录导出：使用已发布快照，校验客户端合同，支持本地更新指引。
- 模型广场与预览：直接呈现统一报价，明确官方价来源、单位及条件。

## Impact

首次实施需要后端、前端和增量数据库迁移。后续已支持协议的新型号、能力资料和价格更新走数据发布，无需发布 sub2api 新版本。复用现有 Go 服务、PostgreSQL、Redis 和任务设施，不新增独立微服务。

功能属于共享能力，实施先落 KDAN `main`，验证后普通 merge 到 `TapModels`，品牌文案和默认站点配置继续独立。规划阶段不调整业务代码、当前白名单、生产同步任务或客户端本地认证。

完整决策与代码依据见 [design.md](design.md)，实施顺序和验收清单见 [tasks.md](tasks.md)。本方案覆盖并扩展 `docs/CODEX_MODEL_CATALOG_REFRESH.md` 的局部建议：服务端自动同步是本次新增建议，使用密钥弹窗仍不触发后台上游刷新。
