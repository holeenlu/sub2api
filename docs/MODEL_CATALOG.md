# 模型目录与价格同步

共享功能，main（KDAN）和 TapModels 使用同一套实现。入口为 `/admin/model-catalog`。首次安装需要执行 `261_model_catalog_registry.sql`；本次开发不等于生产数据库已迁移。

## 更新与开放是两个动作

账号选择器读取数据库中的模型事实，不再从前端平台数组填充。刷新已有账号使用数据库中已保存的凭据；创建账号的凭据预览不写入已有账号。刷新只改变候选和能力资料，不会勾选新模型或覆盖固定名单。批量刷新保留逐账号失败详情，完整成功后才提供可显式应用的交集。

账号目录包含上游列出、管理员配置、资料候选、业务成功记录和已不再列出的条目。明确停服会退出新候选，旧选项保留失效提示，可显式清理。一次请求失败不会判定型号停服；完整合法空目录会撤销该来源的可见性。401/403、账号停用、凭据范围变化高于最后成功快照。

没有现成目录时显示未同步，不注入旧名单。新型号能力不足时仍可作为管理候选，不能伪造 Codex 必需资料。图片、音频、视频的能力保存不要求文本上下文窗口。

## 按分组启用

1. 在账号编辑页刷新模型资料，或在目录管理页按账号 ID 刷新。
2. 在目录管理页设置账号策略：保留旧限制、跟随已发现模型、固定列表；排除规则始终优先。跟随要求已经取得有效快照。
3. 在目录管理页输入分组 ID，对比旧目录和新目录，包括增删项、路由、缺失和定价状态。
4. 在分组模型白名单中选择“跟随”或“固定”，启用统一目录与价格准入。旧分组不被自动切换；切回“保留旧限制”恢复旧规则。
5. 先启用测试组，再启用内部组；品牌生产组的迁移与部署另行执行。

固定空列表表示拒绝全部。旧字段中的空列表/关闭限制保留旧语义。账号别名、渠道映射和 `RestrictModels` 仍作为兼容规则保留；本次不会删除价格限制从而意外扩大权限。新模式按较窄的通配价优先，旧模式保留原配置顺序。

普通模型目录、Codex manifest、广场和请求准入复用分组有效视图。模型被列出不代表所有账号具备相同能力；Codex 对实际可路由账号取能力交集，调度只选择已发布路线。复合组按平台和端点保留不同身份。

## 数据修订，不要求重新构建

补充模型资料是 JSON 数组。例如下面的名称只是演示，管理员应填写自己核实的真实资料：

```json
[
  {
    "id": "vendor-new-model",
    "platform": "openai",
    "kind": "chat",
    "metadata": {
      "id": "vendor-new-model",
      "display_name": "Vendor New Model",
      "reasoning": true,
      "supported_reasoning_levels": ["medium", "high"],
      "default_reasoning_level": "high",
      "input_modalities": ["text", "image"],
      "context_window": 200000,
      "max_output_tokens": 32000,
      "endpoints": ["responses"],
      "recommended_priority": 10
    }
  }
]
```

原生能力优先，补充记录只补缺。资料候选不产生账号权限。明确停服日期使用 `shutdown_date`（YYYY-MM-DD）；同名能力覆盖前要核对供给方和访问方式。推荐优先级越小越靠前；不要靠模型名称数字推断能力。原生 Codex 指令在候选路线一致时保留，缺失时使用无型号身份声明的兼容指令。

补充参考价使用按模型 ID 索引的 JSON 对象，只补远端价格源中缺失的型号；不会把完整远端价复制为销售覆盖。费用字段单位由字段名定义，下例为 USD/token：

```json
{
  "vendor-new-model": {
    "mode": "chat",
    "input_cost_per_token": 0.000002,
    "output_cost_per_token": 0.000008,
    "cache_read_input_token_cost": 0.0000002,
    "cache_creation_input_token_cost": 0
  }
}
```

零是明确价格，缺失是继承/未知。销售覆盖继续在分组、渠道及现有自定义价格文件中设置；账号采购成本单独核算。目录参考层保存原始价格与版本，不叠加销售覆盖或用户倍率。未核实为官方资料的价格显示参考价。新型号缺价时不发布为可销售模型，管理员完整价卡可以满足销售准入。

请求接纳时固定价格目录、渠道价卡、分组覆盖和个人倍率。WebSocket 按逻辑轮次固定，轮内重试保留该版本。价格变更只影响之后的请求。未知响应模型价格写入 `model_request_price_versions` 的 `pending` 记录，等待核算，不重发生成。管理员可通过 `GET /api/v1/admin/model-catalog/pricing-audit?pending=true` 查看最近 100 条，或按实际 API 前缀调用对应管理路由。

## 同步与故障

默认账号同步 300 秒，重点来源可设 60 秒，价格刷新 600 秒。首次定时扫描在启动后约一分钟；手动刷新返回任务 ID。模型源默认并发 2、超时 45 秒，快照最长使用 86400 秒，均可在管理页调整。模型新 ID 可触发下一轮优先检查价格，价格请求最多每分钟一次。来源只读接口不会触发收费生成。

同账号请求合并，账号发现范围相同的根/影子来源在进程内共用获取；数据库租约防止多实例同时发布同账号。不同凭据范围隔离，失败退避持久化并遵守 Retry-After。分页必须全部成功才发布。快照和版本持久化，重启读取数据库；账号策略变化通过既有调度 outbox/缓存失效链传播。

同步故障保留最后成功资料并显示时间，明确撤权立即失效。回滚只恢复当前凭据范围中的数据版本，不能把当前已撤销/停服型号恢复为可用。回滚不修改销售覆盖、历史账单、凭据或用户会话。

目录 API 保存逐字段来源、状态、修订和时间。同步任务保留一天；模型快照、价格和结算证据属于审计数据，未自动删除。

## 图片与票据

图片资料候选与账号获权分开。正常业务成功时保存模型、生成/编辑操作、驱动模型、凭据范围和时间；不会在刷新时自动发起收费探测。生成成功不证明编辑或蒙版权限。图片目录缺项不能直接判为停服，媒体专用模型不会进入 Codex 主模型选择器。

票据页候选从账号目录读取，再显示已有票据和指纹状态。缺少指纹的新会话型号可见，但不伪造打票成功；原有严格无票策略不变。

## Codex 本地目录

“使用 API 密钥”由该 Key 的服务端 setup profile 生成默认配置，弹窗不等外部模型同步。下载的 catalog 是数据快照；文件不会让正在运行的客户端必然热加载。

可从弹窗下载 `update-codex-models.py`，需要 Python 3.11 以上：

```bash
# macOS / Linux
python3 update-codex-models.py --check
python3 update-codex-models.py
```

```powershell
# Windows
py -3 update-codex-models.py --check
py -3 update-codex-models.py
```

更新器读取本机配置的 API Key，只请求目录，校验当前主模型与 review 模型仍有权限，验证成功后原子替换 `model_catalog_json` 指向的文件。失败保留旧文件。它不修改 config.toml、auth.json、会话、插件设置，也不把订阅 OAuth token 用作网关 Key。更新后重新启动客户端。生产账号权限、具体 Desktop/CLI 版本和 Windows 原生文件锁行为须在对应环境验证，不能由本机 mock 测试推定。
