# 模型目录与价格同步

共享功能，main（KDAN）和 TapModels 使用同一套实现。入口为 `/admin/model-catalog`。首次安装需要执行 `261_model_catalog_registry.sql`；本次开发不等于生产数据库已迁移。

## 更新与开放是两个动作

账号选择器读取数据库中的模型事实，不再从前端平台数组填充。刷新已有账号使用数据库中已保存的凭据；创建账号的凭据预览不写入已有账号。刷新只改变候选和能力资料，不会勾选新模型或覆盖固定名单。批量刷新保留逐账号失败详情，完整成功后才提供可显式应用的交集。

账号目录包含上游列出、管理员配置、资料候选、业务成功记录和已不再列出的条目。明确停服会退出新候选，旧选项保留失效提示，可显式清理。一次请求失败不会判定型号停服；完整合法空目录会撤销该来源的可见性。401/403、账号停用、凭据范围变化高于最后成功快照。

没有现成目录时显示未同步，不注入旧名单。新型号能力不足时仍可作为管理候选，不能伪造 Codex 必需资料。图片、音频、视频的能力保存不要求文本上下文窗口。

## 按分组启用

1. 在账号编辑页刷新模型资料，或在目录管理页按账号 ID 刷新。
2. 在账号编辑页的「模型限制」中设置开放策略：沿用原有限制、跟随已发现模型、固定列表；排除规则始终优先。跟随要求已经取得有效快照。固定列表就是同一处的模型白名单，以 `extra.model_catalog_policy.models` 为唯一权限来源；`credentials.model_mapping` 负责名称路由，不再作为新策略的授权名单。已有固定策略按原名单展示，不把旧白名单并入而扩大权限。策略、白名单和别名一次保存，校验失败则整次不保存。目录管理页只读显示策略，并保留资料版本恢复。
3. 在目录管理页输入分组 ID，对比旧目录和新目录，包括增删项、路由、缺失和定价状态。
4. 在分组模型白名单中选择“跟随”或“固定”，启用统一目录与价格准入。旧分组不被自动切换；切回“保留旧限制”恢复旧规则。
5. 先启用测试组，再启用内部组；品牌生产组的迁移与部署另行执行。

新建账号时，页面明确配置的普通白名单由创建接口客户端转换为固定策略并与凭据一起提交；别名保留，未配置名单、OpenAI 仅别名模式、透传及 Antigravity 平台默认规则不自动改义。服务端单个与批量创建都接收独立 `model_catalog_policy` 字段；新的固定策略账号在自动同步启用时立即排队刷新目录，在取得有效资料前不会绕过发布校验。跟随模式要求已经取得当前凭据和代理范围内的有效快照，不能通过请求伪造快照。

批量编辑的“模型白名单”统一写策略，保留各账号的名称路由；“模型映射”只修改路由，已有固定/跟随策略不变。策略和同次凭据修改先针对所有目标校验，再通过同一批量更新保存；校验失败不写入。此保证针对策略与凭据，分组绑定仍按原批量接口逐账号返回结果。

透传账号的固定/跟随策略仍生效，按原始请求模型名判断，不使用失效的旧别名。Antigravity 可独立编辑访问策略，原有映射编辑器保留。Grok、Gemini、Antigravity 中用于覆盖平台默认路由的显式同名映射也保留，它们不额外授予新策略下的访问权限。

未修改策略的存量账号保留旧语义。管理员主动将旧限制切换为固定时，已有显式允许的别名一起进入表单；加载已有固定策略时不并入任何旧映射。复制账号保留固定/跟随策略，不复制源账号的可见性快照；跟随模式副本需刷新自己的目录。

固定空列表表示拒绝全部。旧字段中的空列表/关闭限制保留旧语义。账号别名、渠道映射和 `RestrictModels` 仍作为兼容规则保留；本次不会删除价格限制从而意外扩大权限。新模式按较窄的通配价优先，旧模式保留原配置顺序。

分组「固定账号获取模型列表」（`codex_models_manifest_config`）已于 2026-10-01 退役：分组目录一律汇总全部成员账号的持久快照，请求路线由所有支持该模型的可用成员组成。该功能来自官方上游，代码与数据列保留以便同步上游；读取时（`RetiredCodexModelsManifestConfig`）强制关闭，已存账号 ID 仅供审计，界面不再提供入口。

普通模型目录、Codex manifest、广场和请求准入复用分组有效视图。模型被列出不代表所有账号具备相同能力；Codex 对实际可路由账号取能力交集，调度只选择已发布路线。复合组按平台和端点保留不同身份。

## 数据修订，不要求重新构建

补充模型资料是 JSON 数组。例如下面的名称只是演示，管理员应填写自己核实的真实资料：

```json
[
  {
    "id": "vendor-new-model",
    "platform": "openai",
    "kind": "chat",
    "metadata": {
      "id": "vendor-new-model",
      "display_name": "Vendor New Model",
      "reasoning": true,
      "supported_reasoning_levels": ["medium", "high"],
      "default_reasoning_level": "high",
      "input_modalities": ["text", "image"],
      "context_window": 200000,
      "max_output_tokens": 32000,
      "endpoints": ["responses"],
      "recommended_priority": 10
    }
  }
]
```

原生能力优先，补充记录只补缺。兼容中转可用 `upstream_namespace` 指定精确 Base URL，用 `source_account_id` 限定凭据来源账号；留空表示管理员明确对整个平台提供补充。资料候选不产生账号权限。明确停服日期使用 `shutdown_date`（YYYY-MM-DD）；同名能力覆盖前要核对供给方和访问方式。推荐优先级越小越靠前；不要靠模型名称数字推断能力。原生 Codex 指令在候选路线一致时保留，缺失时使用无型号身份声明的兼容指令。

补充参考价使用按模型 ID 索引的 JSON 对象，只补远端价格源中缺失的型号；不会把完整远端价复制为销售覆盖。费用字段单位由字段名定义，下例为 USD/token：

```json
{
  "vendor-new-model": {
    "mode": "chat",
    "input_cost_per_token": 0.000002,
    "output_cost_per_token": 0.000008,
    "cache_read_input_token_cost": 0.0000002,
    "cache_creation_input_token_cost": 0
  }
}
```

零是明确价格，缺失是继承/未知。实际用量出现未定价的缓存或图片维度时同样记录待核算，不将缺失单价当作零。销售覆盖继续在分组、渠道及现有自定义价格文件中设置：价卡字段留空保存为未覆盖，持续继承下层价卡或参考价；只有管理员填写或点击「以当前参考价填写」后才成为自定义价，此后参考价更新不再改变它。平时只调分组倍率，例外模型才设独立售价；渠道价卡可作为多个分组共用的模板。账号采购成本单独核算。目录参考层保存原始价格与版本，不叠加销售覆盖或用户倍率。未核实为官方资料的价格显示参考价。新型号缺价时不发布为可销售模型，管理员完整价卡可以满足销售准入。

请求接纳时固定价格目录、渠道价卡、分组覆盖和个人倍率。WebSocket 按逻辑轮次固定，轮内重试保留该版本。价格变更只影响之后的请求。未知响应模型价格写入 `model_request_price_versions` 的 `pending` 记录，等待核算，不重发生成。管理员可通过 `GET /api/v1/admin/model-catalog/pricing-audit?pending=true` 查看最近 100 条，或按实际 API 前缀调用对应管理路由。

## 同步与故障

默认账号同步 300 秒，重点来源可设 60 秒，价格刷新 600 秒。启用目录同步时由目录任务统一调度远端价格刷新，原价格服务只监测本地覆盖文件；关闭目录同步后恢复原远端价格调度。首次定时扫描在启动后约一分钟；手动刷新返回任务 ID。模型源默认并发 2、超时 45 秒，快照最长使用 86400 秒，均可在管理页调整。目录大幅减少的提醒阈值可配置；提醒不会恢复已撤销的访问。模型新 ID 可触发下一轮优先检查价格，价格请求最多每分钟一次。来源只读接口不会触发收费生成。

同账号请求合并，账号发现范围相同的根/影子来源在进程内共用获取；数据库租约防止多实例同时发布同账号。不同凭据范围隔离，失败退避持久化并遵守 Retry-After。分页必须全部成功才发布。快照和版本持久化，重启读取数据库；账号策略变化通过既有调度 outbox/缓存失效链传播。

同步故障保留最后成功资料并显示时间，明确撤权立即失效。回滚只恢复当前凭据范围中的数据版本，不能把当前已撤销/停服型号恢复为可用。回滚不修改销售覆盖、历史账单、凭据或用户会话。

目录 API 保存逐字段来源、状态、修订和时间。同步任务保留一天；模型快照、价格和结算证据属于审计数据，未自动删除。

## 图片与票据

图片资料候选与账号获权分开。正常业务成功时保存模型、生成/编辑/Responses 图片工具路径、驱动模型、凭据范围和时间；不会在刷新时自动发起收费探测。生成成功不证明编辑或蒙版权限。图片目录缺项不能直接判为停服，媒体专用模型不会进入 Codex 主模型选择器。

票据页候选从账号目录读取，再显示已有票据和指纹状态。缺少指纹的新会话型号可见，但不伪造打票成功；原有严格无票策略不变。

## Codex 目录

“使用 API 密钥”由该 Key 的服务端 setup profile 生成默认配置，弹窗不等外部模型同步。OpenAI 分组打开时默认选中 Codex CLI (WebSocket)、API Key Mode、macOS / Linux，每次打开都回到这组默认值。

配置只写 provider 内的 `model_catalog_url`（`<站点>/v1/models`，客户端带 `client_version` 请求时与 `/backend-api/codex/models` 走同一处理），复制配置即可使用，需要 Codex 0.156.0 及以上。「检查连接 / 查看此 Key 可用模型」只用于核对，不是使用前置步骤。服务端同步上游模型与客户端刷新本站目录是两个步骤。

2026-09-30 起停止支持旧版客户端：不再生成 `model_catalog_json`，也不再提供目录下载和 `update-codex-models.py`。已按旧配置写入 `model_catalog_json` 的用户需要重新复制配置并升级客户端。目录超过客户端 1 MiB 远程加载限制时只显示提醒，应在分组中减少开放的模型。
