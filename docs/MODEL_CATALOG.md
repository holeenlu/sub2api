# 模型候选清单与原生白名单

当前方案将分组的候选模型列表独立到管理页维护，不另建授权或调度规则。

| 入口 | 职责 |
| --- | --- |
| /admin/model-catalog | 维护候选模型 ID、显示名、类型及停用状态；同步账号返回的模型资料 |
| /admin/groups → 模型白名单 | 使用原有 enabled/models；关闭不额外限制，开启至少选择一项，支持原有通配符 |
| /admin/accounts → 模型限制 | 使用原有 credentials.model_mapping；同名项是白名单，异名项是路由映射 |
| /admin/channels 与分组定价 | 按原有渠道、分组和倍率规则计费 |
| /keys → 获取模型目录及下载 | 使用账号原生目录/配置生成客户端目录，不要求候选快照或参考价格齐备 |

## 候选维护

初始候选复用后端原有分组预设，叠加已保存的账号配置、账号发现结果和管理员维护项。前端不再维护另一份候选表。添加新 ID 复用现有 PUT /api/v1/admin/model-catalog/models 和 model_catalog_registry，保存后重新打开或刷新分组/账号选项即可选择，无需编译。

Kimi、Zhipu、DeepSeek 和 MiniMax 也使用后端同一份候选表。Qwen 不是独立账号平台，可在实际使用的 OpenAI 兼容平台清单添加型号。已退役/停用项不进入新候选，已有保存值继续回显；跨平台批量编辑仍提交同一份模型名称白名单，同名候选的元数据先按平台保留，再合并可选名称。

停用候选只影响下拉选项，不删除或改写已经保存的白名单、别名和调用权限。手工输入仍按原有白名单编辑器规则处理。目录同步失败、过期、能力不完整或参考价缺失，均不新增请求拒绝条件；实际调用仍执行账号状态、凭据、分组权限、渠道限制、配额、票据和并发规则。

模型自动/手工同步只更新模型资料。价格刷新恢复由原有 PricingService 独立调度；关闭模型同步不再停止价格更新。已有参考价格补充、价格版本和计费快照继续保留，提供资料与核算证据，不是新授权层。模型广场可展示缺价状态，候选页面不负责开放模型或设置售价。

## 账号与分组

账号编辑回显已保存的同名白名单和异名映射；保存使用原有 model_mapping 一次提交。批量编辑采用原有映射整体替换语义，不再独立保存 model_catalog_policy。普通账号的空映射按平台原有默认规则处理；OpenAI 透传忽略账号映射和账号白名单，分组白名单仍生效。

2026-10-05 移除随 OAuth 初始模板引入的额外别名模式，账号使用原有模型白名单/映射规则。已有具体映射和平台原生限制保留；旧别名模式账号的升级处理见 [清理说明](BPS_REMOVAL.md)。

分组关闭白名单后再次编辑不会自动开启。历史 enabled=true、models=[] 的分组仍拒绝全部模型；打开编辑器不会自动勾选全部候选。保存时需要明确关闭或选中至少一项。

## 一次性迁移

迁移 263_model_catalog_candidates_only.sql 将旧账号 model_catalog_policy 的具体名单转换为 model_mapping，并保留按原名单授权的别名，删除旧权限字段。已有分组配置不改动。旧客户端继续提交顶层 model_catalog_policy 会收到 400，避免旧表单的权限选择被静默忽略。

不能无损转换的复杂通配符、受限制的透传账号、平台默认映射及不限范围但带普通别名的组合，会报告账号 ID 并原子回滚整批变更。部署前应在备份副本上执行迁移预检，逐项决定原生白名单、分组限制或透传行为；不能为了升级成功自动清空限制。历史 null/legacy 策略保留原映射，重复执行不会产生新的更改。

该迁移属于下次部署范围，本次代码实现不执行任何生产迁移。

升级前可在候选二进制上运行 `--check-model-policy-migration`，使用现有配置文件或 `DATABASE_*` 环境变量连接数据库。命令只复制相关账号到会话临时表并执行同一份 263 SQL，随后回滚，不初始化应用、启动后台任务或写入业务表。成功返回 0；失败报告账号 ID 和需人工检查的策略组合。账号仍可能在预检后被修改，正式迁移保留原有原子校验。

历史分组 JSON 中的 `mode` / `excluded` 已无运行时消费者；正常保存时由 `{enabled, models}` 序列化去除。无需为不可见的历史附加键新建清理任务或改写已发布迁移。

上线时先停止旧版本应用，再迁移并启动新版本；不混跑会写入旧权限字段的进程。调度账号缓存切换到新版本键，旧权限投影不会在重建完成前被复用；已有粘性标识和最近使用时间保留。

## Codex 来源与隐藏模型

/admin/model-catalog 的固定 Manifest 来源选择器复用原有分组配置。启用时从选定账号实时拉取并按 slug 合并，保留原生描述和隐藏字段，再执行原有分组过滤；未启用时使用原有调度/配置生成路径。固定来源不改变推理调度或粘性账号。

模型广场及客户端列表补充已配置的无账号兜底链供应，沿用链的同平台、状态和循环限制。展示按原分组白名单及渠道限制筛选，报价仍归原分组；账号元数据来自对应供应账号。目录读取失败不增加请求拒绝条件，调度、会话粘性和实际使用记录仍走原有路径。

OAuth 目录来自账号对应的 Codex 上游，API Key 目录来自账号配置的 /models。models.dev、GitHub 价格资料可以补充能力或价格，不代表该账号拥有模型，也不增加权限。

codex-auto-*、gpt-reserve 和上游标记隐藏的模型继续参与获授权的服务间发现。普通 /v1/models 提供安全显示元数据用于级联；/keys 下载、计数、远程目录及更新脚本使用 catalog_view=client，排除这些后台条目。隐藏用途不能绕过账号/分组限制。升级后重新获取目录才能更新本地已下载文件。
