# 全站三语完整性与台湾本地化审查

## 范围与结果

本次基于已同步公开上游 v0.2.2 的公共层、KDAN、TapModels 源码，
以简体中文为内容基准，人工维护英文，使用 OpenCC 与项目术语规则生成繁体中文。
未改动线上设置、数据库、原始日志、用户自定义内容或邮件正文。

最终每种语言均有 8,332 条消息，三语键集合、非空检查、消息编译、
命名插值/位置插值及关联消息目标检查通过。
对 497 个生产前端 TS/Vue 文件解析脚本与模板，未发现未豁免的中文界面字面量。
这表示静态检查覆盖的范围内没有遗留，不等于逐页、逐状态人工验收全部线上内容。

## 防回归

- localeKeyCompleteness.spec.ts 检查三语键、非空消息、静态引用和插值/关联目标。
- taiwanLocalization.spec.ts 检查源码硬编码、生成物简体字、台湾术语与 Agent 指令占位符。
- audit-ui.mjs 使用 TypeScript 和 Vue 解析器扫描，不将注释当作界面文案。
- localText 与 labelZh/labelEn 的生产代码允许数量降为 0。
- 上述检查已加入 Makefile 的前端关键测试入口。
- 精确豁免：语言选择器原文名称、后端逐字校验的合规确认短语、
  公共品牌指向既有简体文档的 URL 锚点。不得将这些机器契约自动翻译。
- 原有 audit-locale.mjs 是候选提示工具；“用戶端”“生成”“演算法”等命中
  不代表翻译错误，不能为了清零候选词而全局替换。

## 运行时内容边界

模型名、API 参数、OAuth 控制台原文、日志和上游错误原文需要保持可诊断性。
用户设置的用户名、站名、公告、分组名、定制首页、条款和邮件正文不是静态语言包，
切换语言不会重写这些数据。新语言包也不会自动替换旧数据库中保存的简体自定义内容。

后端目前包含建置时繁中转换机制，不等于按每个浏览器语言动态翻译所有接口错误。
本次统一的是前端自有固定文案与本地生成提示；服务端动态消息和第三方组件的完整
三语行为不能凭本次源码扫描宣称全部通过，需要对应接口或第三方功能的独立验收。
