# 账号降智检测与定时监测

适用于 KDAN main 及其品牌分支。检测是 ModelTrace 响应指纹分类，不是推理能力评分或官方身份鉴定。

## 操作

账号操作菜单 → 降智检测：

1. 选择当前管理员自己的有效计费 API Key。
2. 候选列表来自所选 Key 分组已启用的模型白名单，保留名单顺序；缺少指纹或账号不支持的模型会显示不可选原因。通配条目只展开匹配的指纹模型，不把通配符作为请求模型发送。未启用分组白名单时提示先配置。最多选择 16 个可检测模型。
3. 保存设置；可开启“自动检测”，并填写间隔（1～168 整数小时，默认 1，可设 2、5 等）。首次自动任务在保存启用后经过所设间隔到期。
4. “保存并立即检测”保存当前设置并提交一次后台任务。关闭弹窗不取消任务。
5. 历史页按运行时间倒序展示逐模型详情；可取消等待中的任务或停止后续模型，正在执行的模型允许完成并保留结果。

候选模型不代表此刻一定可调度。请求仍通过正常网关执行账户状态、分组、配额、并发、票据和 IP 等检查。后台请求来自本机回环地址；限制客户端 IP 的 Key 可能被正常网关拒绝，不绕过该限制。

## 检测及显示

每个模型各发起一次独立随机挑战（292～332 个整数），最长 120 秒。固定目标账号，不允许切换到其它账号代测。使用既有共享 JSONL 模板和模型指纹库，HTTP/SSE 请求经过正常网关并按正常规则计费。

新监测流程以 80% 为保守的产品判定阈值，此数字不是经过生产样本验证的准确率：
- 匹配概率低于 80%：结果不确定。
- 达到阈值且预测模型等于目标模型：智力正常。
- 达到阈值且不匹配：疑似降智（应复测确认，不声称已证明替换模型）。
- 请求失败、响应不完整、样本不足：检测失败，不算降智。

整轮任一模型疑似降智则标记疑似降智；全部模型正常才显示智力正常；全部失败则显示检测失败；其余混合结果显示不确定。未检测、等待、运行、取消分别展示。账号名称下的徽标可打开检测窗口；已完成结果超过两个所设检测周期标为旧结果。更换 Key、管理员或模型清单后旧结论不再作为新配置的结论，但历史保留。仅开关定时器保留原结论。

只保存必要元数据：触发来源、计费 Key ID/名称（不保存密钥）、模型列表、配置版本、时间、各模型预测/概率/数字数量/耗时/HTTP 状态/错误码/指纹版本。不保存完整挑战响应、会话正文、账号令牌或票据。历史从升级后开始，旧的浏览器内存结果无法补回。每个账号只保留最近 10 次运行，超出的已结束记录自动清理；正在执行的任务不会被清理。页面始终最多显示 10 次，不提供无限加载。

“检测失败”的结果不会自动关闭账号或触发 BPS 配置变化。正常网关自己的限流、认证和 BPS 403 等状态处理仍然有效，检测不是旁路。

## 调度和并发

- 新配置默认关闭自动检测，仅管理员显式保存启用后才有周期性费用。
- PostgreSQL 持久化计划和任务。多实例通过事务、行锁、活动任务唯一索引和 worker token 避免同账号重叠。
- 数据库约束下最多两个监测任务同时运行；一轮内模型串行。
- 工作者每 5 秒扫描到期计划。队列繁忙时可以晚于预定时间；不补发停机期间错过的周期。
- 到期计划按配置间隔向后安排；手动检测不改变周期。无变化的重复保存不重置周期；修改间隔从保存时间重新计算。
- 每个模型开始前重新校验计划版本、取消状态、管理员资格、Key 所有权及状态、账号和模型授权。
- 单轮最多 35 分钟；40 分钟租约失效后记录中断，不自动重放该轮已收费请求。下一次正常到期任务是独立的新检测。
- 关闭定时器会阻止已排队自动任务和后续自动模型；取消按钮用于停止手动任务的后续模型。已发出请求可能产生费用。

## API 与存储

所有入口受既有管理员鉴权和审计中间件保护：
- GET /api/v1/admin/accounts/:id/codex-diagnostic — 设置和摘要
- PUT 同路径 — 保存 api_key_id / models / enabled / interval_minutes；owner_id 来自登录身份
- GET 同路径/models?api_key_id=... — 分组白名单及各项检测资格
- POST 同路径/runs — 根据已保存配置提交手动任务（409 表示已有活动任务）
- GET 同路径/runs — 最近 10 次运行
- GET 同路径/runs/:run_id — 单次详情（校验所属账号）
- POST 同路径/runs/:run_id/cancel — 请求取消后续模型

迁移 264 增加 codex_diagnostic_plans、codex_diagnostic_runs；账号列表批量读取摘要，避免逐行查询。核心执行器与原 codex-ticket-diagnostic 兼容接口共享。旧接口保留即时调用兼容，新页面及周期任务统一使用持久任务接口。

## 验证与上线边界

本次验证使用本地测试夹具和一次性 PostgreSQL/Redis，不对真实上游发起收费检测。迁移随正常应用启动执行；生产迁移、部署、批量启用自动检测需按交付规范独立操作。
