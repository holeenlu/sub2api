# 账号降智检测与定时测试

## 业务行为

账号操作菜单 → 降智检测，选择本人 API Key、分组白名单中的模型，保存后手动检测或开启周期检测。

- 检测间隔为 1～168 整数小时，默认 1 小时，支持 2、5 等。保存变化的间隔后重新计算下一次时间；无变化的保存不推迟原计划。
- 模型候选来自 Key 分组已启用的白名单，保留顺序；无指纹或账号不支持的条目显示原因并禁选。通配符只展开匹配的指纹模型。
- 最多 16 个模型，逐个发送真实计费请求。目标账号固定，不换号代测；Key、分组、并发、限额和 IP 等原生网关检查均生效。
- 手动检测可选单题或三题复核，默认单题；每个模型分别生成不重复长度的三道随机题，逐次走同一计费网关。题数只影响本次运行，定时检测始终为单题。
- 关闭窗口后后台继续执行；取消停止后续题目及模型，当前已发出请求仍可能收费。每题前重新检查授权、计划版本、计费 Key 和账号资格。
- 每账号只保存最近 10 次检测，包含活动运行；不清理正在执行的任务。展开可看预测模型、概率、耗时、HTTP 状态、错误码及指纹版本，不保存会话正文或密钥。

ModelTrace 是统计分类，不是能力测评或官方身份验证。达到 80% 阈值且预测型号一致才标记正常，不一致为疑似降智；低于阈值为不确定。80% 是保守产品阈值，不是已校准的准确率。网关/读取/超时/样本不足均为检测失败。整轮全部正常才标记智力正常，任一疑似降智则建议复核，其余混合结果不确定。结论超过两个配置周期标记较旧。

三题复核固定同一指纹库快照，对有效题目的原始分数求平均，再使用实际有效题数对应的校准系数；不平均单题概率。失败题不参与计算，全部失败为检测失败；有效题少于三题或预测不一致均为不确定，保留每题结果与错误供复核。历史仅增加 `samples` 证据，不存提示词、输出正文或分数向量。参考 ranxi `6a6a08993fa7762f11fa29290fe48d6ff764d977`，沿用现有 ModelTrace 解析、挑战和 MIT 许可证，不复制来源的独立 Pelican 测试入口或指纹库。

## 复用边界与新增结构理由

复用原有 ScheduledTestService、ScheduledTestRunnerService、scheduledTestPlanRepository，以及 scheduled_test_plans / scheduled_test_results。没有第二套计时器或独立监测服务。

原连通性测试直接使用上游账号，既没有计费 Key 所有权，也没有多模型指纹结果或持久互斥。不能直接调用它替代用户要求的计费检测：
- 计划增加 diagnostic_config JSONB：保存检测特有的 owner_id、api_key_id、models、interval_minutes、revision。
- 结果增加 diagnostic_run JSONB：保存模型清单快照、来源、逐模型证据和运行锁。状态、时间和计划归属复用现有列。
- RunCodexDiagnosticProbe 从原同步 handler 提取，成为唯一计费探针。专用执行逻辑作为 ScheduledTestService 的检测任务方法存在，而非新增服务层。
- 同一既有 cron 调度器执行普通连通性计划及检测任务。数据库互斥防止跨实例重复，同一账号最多一个活动任务、最多两个检测任务并行。普通连通性 CRUD 明确排除检测任务，避免被当作免费连通性测试执行。

规则只在后端声明，由设置读取接口的 rules 返回间隔边界、模型数量、历史保留和分类阈值。前端校验、说明文案使用返回值；仓储限额从同一组常量传入。旧同步诊断分支、32 模型兼容限制、旧分页参数和无调用方的详情接口已移除。

## 接口收敛

使用 POST /api/v1/admin/accounts/:id/codex-diagnostic，但其行为统一为按已保存设置提交后台任务，不再支持旧同步 payload/结果格式。

2026-10-19 该接口新增可选 `sample_count` 请求参数，仅接受 1 或 3，缺省 1；响应和既有结果 JSONB 保存本次题数。既有规则响应返回 `manual_sample_counts`，前端直接使用。原接口无法表达一次性三题复核，因此仅扩展此请求字段，不新增端点、计划设置、迁移或独立执行服务。

新增四个接口：
- GET 同路径：读取设置、摘要、规则；带 api_key_id 时同时返回候选清单。
- PUT 同路径：保存四项配置 api_key_id / models / enabled / interval_minutes，owner_id 取登录身份。
- GET 同路径/history：最近十次完整结果，展开无需额外详情请求。
- POST 同路径/:run_id/cancel：请求取消。

手动和定时两个触发来源共享入队、互斥、执行及结果记录链路。重启遇到过期任务时记录中断，不自动重放可能已收费请求。每题 120 秒；单题轮次总预算 35 分钟、锁租约 40 分钟，手动三题两者乘以 3。每题保存一次进度，不补发停机期间错过的周期。

## 迁移与退役

264 已发布，保持原字节及校验和。267 将 264 两张独立表的数据一次性转入现有定时测试表，保留最新十次结果；排队或运行中的旧任务标记中断，不恢复发送。随后删除 codex_diagnostic_plans / codex_diagnostic_runs。

这是迁移历史兼容，不是保留旧运行路径。部署时应用与迁移应配套升级，旧程序不能继续连接已经完成 267 的数据库；回退代码前需要恢复对应数据库备份。未迁移的历史收费请求不重放。正常连通性测试计划/结果保持原行为。

本次只在本机临时数据库验证迁移和并发，未在生产执行迁移、部署或自动启用收费检测。

## 原生网关恢复后的依赖

2026-10-05 进一步移除打票、票据 Cookie 绑定和专用准入后，检测仍经原生网关计费，复用同一模板解析器、指纹库与调度器。账号固定只约束本次检测目标，不绕过原生资格检查，也不切换到其他账号代测。指纹更新和模板编辑继续保留；历史接口名中的 ticket 不代表恢复打票能力。
