# TapModels AI 协作基准

本项目采用「Astra 协调、Sol 执行审计」作为本轮及后续文档产品工作的默认协作基准：

- **Astra（协调器）**：维护需求边界、项目真实接口与模型分组事实，拆分任务，合并结果，负责最终代码审阅、验收和发布说明。
- **Sol（执行审计）**：对指定范围做独立差距审计，优先检查 88api/Kie.ai 参考信息架构与本项目实际实现的差异，并提交可复现的修改与验证证据。
- **事实优先级**：运行代码、路由注册、公开分组接口、现有客户端配置生成器和测试高于外部参考页面；外部页面仅用于信息架构与用户教育方式。
- **安全边界**：涉及用户凭据、会话数据库或线上数据时，默认只读诊断；任何写入都必须先备份、提供明确 Apply 开关、限制到已核验目标，并执行写后完整性检查。
- **验收标准**：接口文档必须能对应真实 endpoint、请求头、请求体、响应、流式/异步行为和错误；模型与价格必须注明来源及核验日期；下载脚本和 Skill 必须能在干净环境完成语法或自检。

该基准适合作为项目协作约定，但每次任务仍须重新核对当前分支、路由、模型白名单、价格快照和部署配置，不能用历史审计结果替代当前证据。

## 审计闭环与交付门槛

1. 协调器向每个执行者指定文件写入范围、依赖、验收条件；并行任务不写同一文件。只读验收者不得自行修改被验收文件。
2. 独立任务不会自动把结论合并到协调任务。协调器必须取得正式 task ID，读取最终报告；`clientThreadId` 仅表示创建中，不能传给要求正式 ID 的等待/读取工具。等待失败时保留“未验收”状态，继续查明正式 ID。
3. 每个 P1/P2 记录原始证据、负责人、修复文件、复现或回归验证、复验结论。仅实现者测试通过时标记“待复验”，不能标记“已关闭”。
4. 下载包必须在源文件冻结后统一重建：`python3 tools/build_docs_downloads.py`。随后运行 `--check` 和解压安装测试，核对顶层目录、脚本权限、源文件内容及 SHA256。测试对象必须包括交付的 ZIP。
5. 协调器审阅修复后，向原独立验收任务发送准确目录和复验清单；取得结论后才能宣布原问题关闭。如复验又发现阻断问题，继续修复并复验。
6. 最终说明分别报告本地实现、自动化测试、独立验收和线上发布。尚未部署就不能声称“网站已上传”。所有未关闭的 P1/P2 必须明确列出；不能用测试总数或构建成功替代问题关闭证据。
