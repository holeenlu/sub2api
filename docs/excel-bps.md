# Excel / BPS 协议（OpenAI OAuth）

在账号管理 → 编辑现有 OpenAI OAuth 账号 → 打开“Excel / BPS 协议”并保存。使用该账号已有的 ChatGPT access token/account ID，不需要 GitHub 登录、sidecar 或新建 API Key 上游账号。原有凭据刷新逻辑继续生效。默认关闭；切换后新开 Codex 会话。

本入口面向 HTTP `/v1/responses` 和 `/v1/responses/compact`。强制上游 HTTP/SSE，优先于账号的自动透传、WS mode 和 Codex ticket 注入。保持原始模型名或显式账号映射，不因模型权限不足偷偷切换模型。现有调度、分组授权和并发额度继续生效；开关不会重新启用已停用的账号。

## 工具调用与并发

- 客户端 tools 转成 developer 消息中的目录. function 使用 `run_officejs.code` 内的 JSON 信封; custom 可使用显式 `codex2api.custom/<完整工具名>` 标记传递原始文本. 服务器只做协议转换, 不执行 OfficeJS 或客户端命令.
- 支持 function、custom、namespace、Lite additional_tools，保留 custom 原始文本与 JSON 大整数。
- 文本增量实时转发；工具等完整 response.completed 到齐后统一验证，失败、不完整或未知工具不会被提前发送执行。
- 完整原生 item 按账号、API Key、线程作用域缓存。回放保留上游 ID、summary、references 等内容；多个完整工具和乱序结果按 call_id 配对。
- 子线程优先使用 thread-id / x-codex-turn-metadata，不因共用父会话 session_id 混用缓存；没有设置全账号串行锁。并行子代理仍受账号并发数、调度及上游能力约束。
- 提示词仍要求每个 transport 内只放一个工具对象，响应声明 parallel_tool_calls=false。多工具转换与子线程隔离已有离线回归，不等于真实 Codex 多代理工作流已完整验收。
- 工具回放与目录缓存按账号、API Key、可信线程标识隔离；没有线程或显式会话标识时不跨请求缓存。客户端省略 tools 时继承目录，显式 tools: [] 清空目录，additional_tools 校验后原子合并；tool_choice: none 本轮禁用工具但不清空目录。并发增量基于最新快照合并，旧请求不能覆盖新版目录。
- 缓存仅位于当前进程。回放上限 1024 条 / 16 MiB，目录上限 512 个会话 / 16 MiB，单个目录最多 1 MiB；两类缓存均在访问时清理闲置满 2 小时的条目。回放 JSON 在全局锁外解码。重启或跨实例后，完整客户端历史可重建原生调用；仅有工具结果且缺少原始调用时仍会失败。
- 普通 function 参数按声明的 JSON Schema 校验，包括 required、类型、枚举、组合与数值约束；保留大整数，不读取远程或本地外部 schema。单个 schema 上限 1 MiB；校验前限制嵌套 128 层、单个数字文本 4096 字符、指数绝对值 4096 及累计数值展开预算，超限明确拒绝。整批工具验证后再提交回放缓存和发送工具事件，重复 call_id、显式禁用并行却返回多个工具时拒绝整批。
- 首次工具交互若只在响应末尾返回一个目录外的 run_officejs 调用，且尚未交付任何工具，允许模型纠正一次。复用同一账号、代理、模型、历史和已上传图片引用；这一未知工具纠错不适用于 schema 不合法、多个工具或已有工具历史；纠错仍失败时不会继续重试。已合入的已知工具封装纠正保留原来的最多两次规则。返回用量合并两次上游已报告的用量；上游断流未提供用量时无法推算其消耗。

### 账号工具探测

在账号管理的连接测试中，已启用 Excel / BPS 的 OpenAI OAuth 账号可选择「BPS 工具往返」。管理员主动运行后，通常发起三次实际上游请求；首轮工具命中受限纠错条件时最多四次请求：先校验随机 nonce 的完整文本响应，再要求调用一次无外部副作用的 echo 工具，最后回传该工具结果并核对完整响应。每一步固定使用所选账号和模型的 BPS 路径；协议关闭、模型不在 BPS 范围、错误终态或工具参数不符时立即失败，不切换到普通 Codex 重试。每个服务实例最多同时运行 3 个探测，同账号只能运行 1 个；其他账号连接测试不受此限制。

此测试不自动定时运行，也不写入持久能力判定。通过仅证明测试时该账号的基础文本与所声明 echo 工具完成了一次 BPS 往返，不代表 Codex Desktop 默认工具集、多代理协作或所有业务模型均已通过。

### 下游转发与错误定位

- 模型将单个工具写成 `functions.shell({"command":"pwd"})` 时, 适配器按完整调用解析工具名和一个 JSON 字面量参数. 允许可选的 `await` / `return` 和末尾分号, 工具必须已在客户端目录中声明. function 参数必须为 JSON 对象; custom 参数必须为 JSON 字符串, 解码后原样交给客户端. 此处不运行 JavaScript.
- 不从脚本, 多调用, 数组, 未闭合调用或带尾随内容的字符串中截取工具对象. 这类返回会产生 `basispoints_protocol_error`, 不会先发送其中一个工具执行. 未带明确工具身份的原始代码仍会被拒绝.
- `basispoints_request_invalid` 的内容错误附带分叉接收到的字段位置, 例如 `path=input[2].output[1]; type=input_file`. 位置同时覆盖消息内容和 function/custom 工具结果. `input_image` URL 校验失败也附带位置.
- 错误仅显示固定的已知协议类型名称; 任意未知类型归类为 `unknown`, 缺失类型或非对象内容分别标记. 不回显正文, 图片字节, URL 或任意自定义 type 值. 不支持的文件, 音频或其他内容仍返回明确错误, 不会静默丢弃或伪装为文本.
- `supports text and HTTPS input_image content only` 表示内容分块类型不被支持, 单凭这条错误不能判断为 base64 转换失败. 下游应保留完整错误消息及请求 ID, 以便定位字段而不需要保存客户正文.

## 缓存创建计量

- 在账号编辑中勾选现有的缓存创建转普通输入选项后, 实际走 BPS 的请求同时调整本系统记账和返回下游的 `usage`. 默认仍关闭, 不需要修改下游原版 Sub2API 或 Compose 配置.
- 返回下游的缓存创建/写入字段及 5 分钟, 1 小时明细归零. 总输入已包含这部分 token, 因此不额外增加 `input_tokens` / `total_tokens`; 缓存读取, 输出和推理明细保持不变. 例如总输入 1000, 缓存读取 100, 缓存创建 200, 开启后下游得到普通输入 900, 缓存读取 100, 缓存创建 0.
- 同时覆盖流式事件和非流式 Responses/compact 响应, 包括顶层 `usage` 和 `response.usage`. 本系统在响应改写前读取原始上游用量, 继续使用既有计费逻辑.
- 该选项改变计量分类, 不会关闭上游实际缓存. 未开启选项或实际未走 BPS 的请求保持原有行为; 下游独立配置的强制缓存计费规则不受此选项控制.

## 能力限制

`max`/`ultra` 映射 `xhigh`，`none`/`minimal` 映射 `low`，实际 effort 出现在响应/用量中。拒绝强制指定工具与仅 previous_response_id 的增量历史。结构化输出通过提示和本地终态校验实现，详见协议包 README。不要把 HTTP 200 当作模型能力证明。

支持 HTTPS 图片 URL 和已有 file_id，二者必须只选一个。未启用旧图片中转时，Base64 图片默认使用下述原生附件上传；明确开启旧中转的部署继续使用旧路径。原生上传失败不会自动改走公网中转。

## 原生图片附件

客户端直接发送消息或 function/custom 工具结果中的 input_image。网关先校验整批图片，再用本次调度账号的认证与代理向固定 BPS attachments 接口流式上传 multipart file，将返回的 openai_file_id 写入 file_id。图片不落盘、不生成公网下载地址，不压缩、不改 detail；支持 auto/low/high/original，原样保留精度，由上游模型决定是否支持。

单图 20 MiB、每请求 20 张、解码后总计 32 MiB、单图 64 Mi 像素，支持 PNG/JPEG/GIF/WebP。每进程最多 16 个附件处理操作；网关原有请求体限制仍生效。multipart 流式读取 Base64，不建立解码后整图缓冲。同请求重复图片只上传一次；不假定上游文件保留时间，不跨请求缓存附件 ID。

上传使用禁用重定向的既有出站传输。任何上传失败都不发起模型生成，不回显上游正文、图片或凭据；此前已成功上传的附件可能仍留在上游，本实现没有删除接口。403/429 沿用账号已有的自动禁用/冷却策略。

本次测试使用模拟上游，覆盖 multipart 原始字节、认证与路由、文件引用、错误边界、流式及非流式网关；尚未使用真实 OAuth 账号验证附件上传或模型识图，也未部署。上线前必须验证真实图片与工具截图往返。

## 旧版 Base64 图片中转（显式兼容模式）

1. 打开管理员后台的 `系统设置 > 功能开关 > Excel / BPS 图片中转`.
2. 开启 `启用图片中转`, 在 `公网 HTTPS 访问地址` 中填写当前服务的公网地址, 例如 `https://your-api.example.com`. 只填写 HTTPS origin, 不附加 `/v1`, 查询参数或账号密码.
3. 点击页面底部的保存按钮. 配置存入数据库并立即生效, 无需修改 Compose `.env` 或重建应用容器. 默认关闭; 关闭并保存后停止公网中转和临时图片访问，新请求改用原生附件上传，已填地址保留.
4. 保持账号的 Excel / BPS 协议开关开启. 客户端继续发送 `input_image.image_url=data:image/png;base64,...`, 无需调用额外上传接口.
5. 确保域名证书有效且 `/api/bps-images/` 转发到接收 BPS 请求的同一实例. 允许上游免登录 GET/HEAD 临时图片路径, 禁止 CDN 缓存, 并在 Nginx/CDN 访问日志中屏蔽该路径的 token. 应用日志和 BPS 上游错误日志会自动脱敏 token.

- 自动转换用户消息中的图片和 `function_call_output` / `custom_tool_call_output` 中的截图. 原有 HTTPS URL, 相邻文本及工具参数保持原值.
- 仅接收 PNG, JPEG, GIF 和 WebP. 校验 base64, 图片格式, 声明 MIME 和图片尺寸. 每张最多 20 MiB, 每个请求最多 20 张且解码后合计不超过 32 MiB, 单张最多 64 Mi 像素. 网关已有请求体限制仍生效.
- 图片以私有临时文件保存在现有数据目录的 `bps-images/session-*` 下. 沿用已有 `DATA_DIR`, 未设置时使用 `./data`, 不需要新增环境变量. 目录权限 0700, 文件权限 0600. 图片解码后流式写盘, 下载时流式读取, 不把完整图片保留在 Go 堆中.
- 每进程当前会话的已存图片与正在写入的文件共用 1 GiB / 512 张配额. 写文件前预留配额; 校验失败或重复图片会删除临时文件并释放预留. 容量用尽或存储不可写时返回 503, 不淘汰仍在有效期内的图片. 数据目录须位于磁盘, 使用 tmpfs 会重新消耗内存.
- 临时链接按账号, API Key 和线程隔离, 使用进程密钥生成不可猜测的 token. 相同作用域再次提交同图时复用链接并续期, 最后一次提交后 30 分钟立即失效; 读取链接不会续期. 后台每分钟清理过期文件, 正常关停删除当前会话目录. 异常退出的目录空闲超过 31 分钟后由运行实例的扫描回收; 服务停机期间不会执行清理.
- 链接持有者可在有效期内读取图片. 服务重启后链接失效; 客户端在下一次请求中重发原始 base64 图片即可重新生成. 多实例部署必须将图片下载请求固定到创建链接的实例.
- 服务端不会读取客户端文件路径, 不开放匿名上传接口, 不将原始图片写入数据库或对象存储.

### 并发与内存边界

- 启用图片中转后, 在 API Key 鉴权之后, 读取请求体和模型白名单校验之前执行共享准入. 作用于 OpenAI/Composite 分组的 Responses, Chat Completions 和 Messages HTTP 入口, 包括对应别名和 compact. 账号选择发生在读体之后, 因此纯文本及最终选择非 BPS 账号的请求也受该限制. 关闭中转后恢复原有入口限制.
- 管理员可设置请求体上限 (1–128 MiB)、估算资源预算 (512–2048 MiB) 和每进程最大在途请求数 (1–128), 默认分别为 64 MiB、512 MiB 和 32 个. 预算必须至少为请求体上限的 8 倍; 已配置的更小网关上限仍生效. 已知长度按请求体大小的 8 倍预留, 最小按 1 MiB 计算; 未知长度的未压缩请求随读取量增加预留, 压缩请求在解压期间按配置的请求体上限预留. 正文读取完成后, 未知长度和压缩请求按实际大小保留预算至请求结束. 大请求可用并发低于配置上限.
- 预留持续到整个 HTTP 请求结束, 包括调度等待和上游流式响应阶段. 没有预算时在读体前返回 503 和 `Retry-After: 1`, 不建立应用层等待队列. 超大请求返回 413. 图片下载另有每进程 32 个并发上限.
- 请求准入预算是估算值, 不是进程 RSS 或容器的硬上限. 提高预算会增加内存压力; JSON 解析, Go 运行时, 文件系统页缓存, 反向代理及其他业务仍消耗资源. 磁盘配额也不包含其他进程会话和待清理的崩溃遗留目录. 本功能不保证 200 人同时上传大图全部成功, 更不等同于整机不会 OOM.

验证范围: 自动化测试覆盖 HTTPS 测试服务器取图, BPS 请求转换, 普通/compact 与流式/非流式分支, 工具截图, 文件权限, 过期和异常退出清理, 磁盘预留与失败回滚, 非法输入, 日志脱敏, 后台设置及即时生效. 200 并发准入回归使用受控请求验证拒绝发生在读体之前, 以及在途上限和资源释放; 不属于真实上游或生产服务器的容量压测. 真实 BPS 视觉结果和部署容量需由部署方另行验收.
