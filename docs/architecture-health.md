## 已接受债务

### API Key 无限配额使用 `quota=0`

接受原因：当前代码、数据库和缓存已经统一使用该语义。API/UI 可以派生明确的 `unlimited_quota`，无需立即引入第二字段。

重新评审：需要区分“未设置”“继承”和“明确无限”三种状态时。

### Key 独立并发延后到 P1

接受原因：当前用户和 Account 并发门禁有效，Key 实时并发已有统计。先完成配额和日志闭环，减少同时修改认证/并发热路径的风险。

重新评审：出现单 Key 长期挤占用户并发，或产品需要不同 Key 服务等级时。

## 健康复核节奏

- 每个 M/L 功能完成后更新受影响热点；
- 每完成三个跨模块功能进行一次全局健康复核；
- 每次合并 `upstream/main` 后检查状态所有权、重复功能和兼容层；
- 不以文件行数阻断交付，以重复状态源、不可回滚迁移、部分保存和未验证计费路径作为阻断条件。
