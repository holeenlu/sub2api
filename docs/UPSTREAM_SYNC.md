# NewAPI 上游同步规范

## 目标

NewAPI 只维护重构后的项目实现，同时继续吸收此前约定的上游修复和协议方案。每个正式同步批次都以最新官方上游 `main` 为唯一父提交，把当前有效的 NewAPI 重构、已采用定制和本批次修改整理为一个完整定制提交；目标不是恢复旧项目的品牌分支、兼容层、发布矩阵或历史目录。

## 默认来源

默认来源保持此前约定的选择范围：

| 来源 | 默认采用范围 | 默认处理 |
| --- | --- | --- |
| `Wei-Shaw/sub2api` | 官方 `main` 的通用修复、协议和安全变更 | 优先审查 |
| `ranxi2001/sub2api` | 已验证的生产修复 | 逐项选择性采用 |
| `QuantumNous/new-api` | 网关、协议和数据处理相关变更 | 只移植适用部分 |
| `zyycn/codex-proxy-rs` | Codex 协议、代理、流式和恢复方案 | 对照合同后移植 |
| `dofasted/vm2api` | 授权、调度、供应商和运行时修复 | 对照当前权限/数据合同后移植 |

`MACOS-DO/sub4api` 不在默认同步范围内。新增来源或扩大来源范围必须单独记录授权、用途和风险。

## 每批同步步骤

### 1. 冻结输入

记录：

- NewAPI 当前 HEAD、工作树状态和远端 `refs/heads/NewAPI`；
- 每个来源的远端 URL、分支、冻结 SHA 和抓取时间；
- 当前未提交工作、其他工作树、共享缓存和本地联调资源；
- 本批次的主题、影响领域和明确排除项。

来源或 NewAPI 在同步期间推进时，候选失效，必须重新冻结和复核，不能依赖旧 SHA 继续推送。

### 2. 审查实际差异

先读源码和真实消费者，再按以下四类记录每项变化：

- **采用**：NewAPI 尚未覆盖，且行为与当前架构、权限和数据合同兼容；
- **已覆盖**：NewAPI 已有等价实现，补充来源位置和回归证据；
- **排除**：会引入旧品牌、旧部署、额外权限、已退役路径或不兼容语义；
- **延期**：需要新的合同、迁移、真实上游或页面验收，当前批次不具备条件。

不能只用 commit message、patch-id、文件名或“能编译”判断已覆盖。协议变化必须检查 HTTP JSON/SSE、客户端 WS、Native/BPS/Cloud、续接、工具轮、取消、授权、计费、限流/恢复和跨实例状态的真实调用链。

### 3. 形成 NewAPI 方案

每项采用变更必须说明：当前行为、上游行为、NewAPI 目标行为、受影响接口/数据/配置、迁移和回滚策略、具体写集、测试和未覆盖限制。优先复用已有领域端口和合同；不新增只为“兼容”而存在的平行解释器或 wrapper。

保留 NewAPI 的以下边界：

- 项目和部署身份由配置决定，网站品牌不进入核心执行语义；
- 一次执行只有一个执行/预算所有者；适配器不能暗中换账号、续费或重置预算；
- 未知用量保持未知，不写零；已交付输出不自动另起生成；
- 上游授权、撤销、租约、冷却、取消和跨实例保护必须在发送前及异步交接时复核；
- 旧广告、赞助、旧品牌发布矩阵、自更新安装器和已退役入口不重新引入。

### 4. 实现和验证

实现使用隔离工作树；前端只由 frontend owner 修改 `frontend/**`，后端、根目录、部署和共享同步资料由后端集成者维护。公共合同、来源记录和 Git 索引由单一写者处理。

验证至少包含受影响的消费者和失败路径。若修改协议或网关，默认检查 HTTP JSON、SSE、客户端 WS 以及 Native/BPS/Cloud 的路由、续接、工具、取消、授权、账务、冷却和跨实例行为；若修改前端接口，还必须由前端实际构建和浏览器验收。真实上游、生产部署、生产数据和外部 OAuth 条件不足时明确记录 `blocked`/`not_run`。

### 5. 记录和交付

同步记录建议写入 `docs/bps/upstream-changes.md` 或对应领域的审查文档，至少包含：冻结 SHA、差异摘要、采用分类、代码落点、删除的旧路径、测试命令、结果、未验证项和回滚材料。

全部受影响验证完成后，基于冻结的最新官方上游 SHA 重新生成一个累计 NewAPI 定制提交。提交必须满足：该上游 SHA 是唯一父提交，且 `git rev-list --count <upstream>..<candidate> == 1`；提交正文和 `docs/CUSTOMIZATION_RELEASE_NOTES.md` 包含完整累计变更说明。只允许推送 `holeenlu/sub2api:NewAPI`，使用精确 lease；不修改、合并或推送 `main`、`TapModels`、`tokensavy`。

## 发版边界

同步完成不会自动发版。发版由人工 `workflow_dispatch` 单独触发，按当前 NewAPI workflow 的版本输入和产物范围执行。每次发版只更新当前 NewAPI 的最新发布指针和对应产物；不批量重打旧分支标签，不把推送事件当作发版授权。

## 复核清单

- [ ] NewAPI 和所有来源 SHA 已冻结并记录
- [ ] 工作树、其他工作树和联调资源边界已核对
- [ ] 每项变化已分类为采用/已覆盖/排除/延期
- [ ] 真实消费者、旧入口和无用代码删除范围已核对
- [ ] 协议、授权、账务、恢复、取消和跨实例场景已验证或明确未运行
- [ ] 前端接口变化已有前端 owner 的构建和页面证据
- [ ] 同步记录、完整 Release Note、回滚 bundle 和验证回执已保存
- [ ] 提交和推送目标只有 `NewAPI`
- [ ] 候选提交唯一父提交为冻结的最新官方上游，且上游到候选只有一个提交
- [ ] 未误触发发版、生产部署或生产数据迁移
