# BPS 移除与升级说明

> 后续范围已扩大为恢复 Wei-Shaw 原生能力，仅保留已确认的降智检测及品牌/安全/升级约束。下文是 BPS 阶段记录；打票、绑定、额外准入和独立目录的最终处理见 [当前恢复说明](FORK_FEATURE_RETIREMENT.md)。

2026-10-05 的清除同时覆盖 OpenAI OAuth Excel/BPS 和旧 `openai_bps` 独立平台。

## 保留的能力

Codex **降智检测**完整保留：账号列表入口、模型选择、诊断 API、ModelTrace 挑战、检测模板、结果判定和检测历史均不属于删除范围。普通账号连接/compact 测试、OAuth 凭据刷新、原生 WS、手动 HTTP 桥接、Grok、原生图片 API、模型映射及计费继续保留。

按进一步确认的范围，原 BPS 页附带的“新建 OAuth 账号自动套用映射模板”及独立页签也已移除。原作者的账号级模型映射、白名单及原有计费倍率保留。

## 已删除的运行逻辑

- Excel/BPS 请求转换、OfficeJS 工具信封、工具回放/纠错、结构化输出适配和专用 JSON Schema 依赖。
- HTTP/WS/Images 的 BPS 分流、SSE→WS 专用适配、BPS 模型能力限制、计费修正、429 冷却、HTTP/2 降级、403 移组/关闭/自动恢复。
- BPS 图片附件上传、自动图片压缩/预警、临时图片链接、磁盘中转、图片准入预算与图片策略 Redis 缓存读写。
- BPS 账号选项、状态徽章、默认模板 API、图片设置、专用探测模式、前端翻译/测试与旧使用说明。
- 同批引入的 OAuth 初始映射模板、额外“映射仅作别名”模式、独立成本倍率及其自动同步。更早已有的上游计费倍率探测、原有倍率同步和历史账单保留。
- 旧独立平台专属代码。未知平台现在使用通用 `unsupported_platform`/`UNSUPPORTED_PLATFORM` 校验，不能落入其他上游。

旧数据由一次性迁移清理。旧编辑器或导入文件再提交已删除字段时，账号仓储统一返回 `UNSUPPORTED_ACCOUNT_FIELD`，拒绝整个写入，不再接受后静默丢弃。字段清单只由现有 `account_repo.go` 的私有校验函数维护；前端、DTO、模型目录和准入指纹不再维护旧字段兼容逻辑。

## 迁移 265

新增 `backend/migrations/265_remove_bps_protocols.sql`；已应用的历史迁移不改写。

1. 清理账号 `openai_excel_bps*` / `openai_bps*` 键及全局 `excel_bps*` / `openai_bps*` / `auto_bps*` 设置。
2. 原先显式启用 Excel/BPS 的 OpenAI OAuth 账号暂停调度、设为 disabled，保留其 OAuth 凭据。管理员核验原生模型权限后，可显式重新启用。原先 BPS 已关闭的原生账号继续保持状态。
3. 旧独立平台账号/分组复用已有 `deleted_at` 软删除和 disabled 状态，清空仅旧独立平台使用的账号凭据，保留 ID、账单引用和历史用量。原平台名称只留在历史行，不新增 `archived` 平台值，也不转换成原生 OpenAI 账号。
4. 删除旧平台的分组绑定、Composite 路由、监控配置/模板、平台配额、模型发现来源和待执行模型目录任务；对应临时模型快照通过既有外键清理。
5. 旧 BPS 自动规则复用 enabled/auto_recover/next_run_at 停用，去除协议动作；保留测试结果、质量判定历史、其他质量规则及 Codex 检测设置。配置保持非 NULL，沿用既有历史隔离机制，不新增 retired 标记，不能误变成普通连通性测试。
6. 从原有四类 provider/platform CHECK 约束中移除旧平台，保留其他允许值。先移除旧质量规则的 scope 唯一索引，再清理动作，避免同账号两类历史规则冲突；已退役的质量规则写入入口不需要新索引。账号和分组更新写入 scheduler_outbox，软删除账号的事件携带原分组以清除调度缓存。

这是代码内的升级迁移。提交或推送不代表它已在生产执行；正式部署前仍需独立确认数据备份、暂停账号的处置名单与迁移范围。

`266_remove_companion_account_extensions.sql` 删除 `oauth_initial_model_mappings` 和已退役的 `priority_scheduling_v1` 全局设置，清理账号的 `credentials.model_mapping_mode`、`extra.cost_multiplier`、`extra.cost_multiplier_auto_sync`，并发出调度缓存刷新事件。

账号里已经保存的具体 `model_mapping` 不被删除或猜测性还原；无法从现有数据准确区分自动模板写入和管理员后续编辑。OAuth 凭据、原有 `rate_multiplier`、上游计费倍率探测及其倍率同步、账单、降智检测/ModelTrace 模板与结果继续保留。更早已有的上游计费倍率探测始于 `0765d10c1`（2026-07-15），不属于这批新增的独立成本字段。

旧客户端或导入文件再次携带这些额外字段时会收到明确错误，需要刷新编辑器或清理导入文件后重试。测试覆盖写入拒绝且不产生部分修改、原生映射仍有效、旧内存快照中的别名 mode 不扩大模型范围、迁移重复执行、暂停范围及计费/检测数据保留。

## 多实例及外部状态收尾

- 升级时停止所有旧版本实例，再启用新版本；旧实例的 403 自动恢复任务仍可能改写配置，不能混跑。
- 新版本不再维护临时中转文件。停掉旧实例后，盘点并清理该部署数据目录中的 `bps-images/` 专属子目录；不要删除整个 DATA_DIR，也不要触及其他图片/用户文件。
- `bps_image_policy:*` 是旧图片策略缓存，正常 TTL 为 7,200 秒。可等待过期，或在确认 Redis 实例与命名空间后精确清理；不清空数据库或共享 scheduler/billing 缓存。
- 旧独立平台更早版本的 Redis 状态需要按实际部署盘点，本版本没有其读写代码。不要按含糊的 `*bps*` 模式删除不明数据。
- 旧进程的工具/附件缓存、冷却和传输降级状态随进程退出释放。历史账单、请求审计、已应用迁移记录及上游存储的附件不由本次代码删除改写。

### 必须保留的小型函数及迁移

- `validateAccountWriteFields` 是现有账号仓储内的私有函数，6 个既有写入边界复用。原 `SanitizeStoredCredentials` 只负责丢弃临时敏感凭据，不返回错误，也不覆盖 extra 或仓储直接写入，不能承载“拒绝废弃输入且不改变其语义”；因此在仓储集中校验，避免各入口重复字段清单。
- `abortUnsupportedPlatform` 是现有网关文件内的私有函数，合并 3 处响应。现有 `OpenAIErrorWriter` 固定输出 `model_not_found`，直接复用会返回错误的错误码；这里没有扩建通用错误框架。
- 265/266 是仅有的两个新增执行文件，用于清除已落库的协议和同批扩展数据；历史已应用 SQL 及校验和保持不变，不能用改写历史迁移代替。
