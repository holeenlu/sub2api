# 管理员用户归属与余额转账

2026-10-23 用户确认：采用充值时转账，不采用消费时扣上级资金池。

- 超管创建管理员并为其充值；超管 Key 继续沿用无需个人余额的计费规则。
- 普通管理员只能创建普通用户。管理员即使保留旧 `staff.manage` 授权，也不能创建、提升或管理管理员。
- 创建人写入 `users.created_by`，不由客户端提交，不能通过用户编辑修改。普通管理员只能查看、编辑、禁用、删除自己创建的普通用户。用户详情、余额历史、密钥、订阅、订单、用量和相关审计读取受归属过滤。
- 超管在管理员角色权限中授予“经营财务 → 计费 → 调整余额”，依赖“用户管理 → 查看”。已有全站二次验证规则继续生效。
- 管理员充值：扣自己的余额、增加下属用户余额。扣回：扣下属用户未消费余额、退回管理员余额。管理员不能通过 `set`、用户编辑余额或新建用户初始余额绕过资金来源限制。
- 两边余额、两条关联流水和审计在同一事务内完成；按 ID 顺序锁定双方，余额不足、归属变化或流水失败时全部回滚。复用原充值接口幂等处理，提交后失效双方余额与授权缓存。
- 用户消费仍只扣自己的余额。管理员转出后余额为零，不影响已获资金的用户继续消费。

## 已移除的功能

用户兑换、管理员卡密生成/编辑/导出、邀请码注册及管理、邀请链接绑定、邀请返利、返利提现、相关设置、权限、页面和 API 均移除。第三方登录保留普通注册、验证邮箱、密码、绑定及资料采纳流程；优惠码和在线支付保留。Claude 上游重置额度和 Codex 上游邀请能力是独立账号能力，不属于本站钱包兑换/邀请返利。

`redeem_codes` 表及精简后的内部服务仍被在线支付幂等入账、管理员余额/并发调整流水和历史查询使用；不再提供公开兑换或卡密管理入口。`user_affiliate_ledger` 只用于历史余额记录查询，历史返利配置、关系、未转换额度及旧流水不自动删除或重新结算。退出条件是这些现有账务读取方和支付幂等记录完成另行授权的数据迁移。已应用迁移及生成 ORM 的账务模型保留，不伪造历史清理。
