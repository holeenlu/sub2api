# SLA 请求体与账号池分类

本修正按 ranxi2001/sub2api PR #439 的两项行为适配，固定来源为
`b355662bdede5352671fc0f39c2e589959e326ab`（合并提交
`be82ae7f7a8b0cb4577aa6f58c01e7a61aabeed8`）。它适用于三个品牌的共享 Ops
统计，不修改网关响应、重试、选号、账号健康、用量或计费。

## 分类规则

1. 明确出现 `request payload is too large`，且有效错误状态为 400、413、422，
   归为 `client/request/context_limit`，从 SLA 异常中排除。
2. 平台路由阶段的账号池耗尽计入 SLA。历史 `platform/routing` 429/503
   即使保存了旧的业务限制标记，也按平台异常读取；明确的 `model_not_found`
   不受此纠正影响。新的请求中，本地模型拒绝标记优先于残留容量标记，容量
   标记优先于残留用户限额标记。
3. 保留用户余额、额度、并发和明确本地模型不支持的现有排除规则。不把所有
   400/413 统一排除，也不把所有 429/503 都判为平台容量故障。
4. 上游实际 4xx/5xx 优先于网关包装状态。例如网关 502 包装上游 413
   可以识别；真实上游 503 不因含有超限文案而排除。SSE/WS 在 HTTP 2xx
   握手后发生的已记录逻辑失败，使用逻辑失败状态分类，保留原上游 HTTP 状态。
   成功或已恢复的记录不因此改为失败。账号授权阶段错误不按请求体超限排除。

## 生效范围与数据

- `backend/internal/service/ops_sla.go` 统一日志写入和 SQL 查询规则。现有
  service 同时负责日志准备和实时指标采集，仓储复用该规则，避免分别维护词表。
- 错误列表、详情、责任筛选、请求明细、仪表盘、趋势、分布、重新生成的
  小时汇总和后续实时指标使用修正口径。日汇总继续由小时汇总生成。
- 历史原始行不重写。状态码、发生来源、原始消息和上游尝试证据继续保留，
  并沿用现有脱敏与长度限制。
- 已生成的小时/日汇总与指标快照不会自动全面回算。需要统一旧时间段时，
  单独执行现有运维重算流程；回退二进制也不会自动恢复已有聚合数据。
- 账号池耗尽不再被排除后，SLA 可能降低，属于统计口径修正。

## 渠道监控边界

渠道监控的实际成功率继续按实际成功请求计算，保留原错误总数、去重方式和
管理员忽略类别配置，不把 SLA 排除项算成成功。仅在原有 context-limit
分类位置识别新增标准化 `context_limit` 类型，Go 与 SQL 保持一致；既有
文本分类顺序不变。不引入源文件中的额外模型能力归因或跨 Pod 去重规则。

## 配置与上线

无需配置，部署后自动生效。无新增接口、配置项或数据库迁移。部署、历史
重算与版本发布属于独立操作，不随代码实现或提交自动执行。
