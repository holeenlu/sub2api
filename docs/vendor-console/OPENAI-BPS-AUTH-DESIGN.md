# 供应商 OpenAI 原生 / BPS 并行授权方案

日期：2026-10-17。适用：KDAN / TapModels / Tokensavy 共享业务。

状态：已实现供应商模式权限、双授权生命周期、调度校验、页面和实际模式用量记录；验证证据及尚未进行的真实上游验收见 [实施验收](OPENAI-BPS-AUTH-ACCEPTANCE.md)。与 [V3 统一平台方案](UNIFIED-PLATFORM-PLAN.md) 配合使用；BPS 网关行为继续遵守 [BPS 要求](../bps/REQUIREMENTS.md) 和 [Responses 恢复契约](../OPENAI_RESPONSES_RECOVERY.md)。生产部署及数据库迁移未执行。

## 1. 已有能力与接入缺口

网关已经支持原生 Codex OAuth、以 Excel OAuth 为主凭证的 BPS 账号，以及原生账号附加独立 Excel 授权。两种授权均属于 OpenAI，继续使用 `platform=openai`、`type=oauth`。

实施前供应商入口存在以下缺口，本次据此扩展现有实现：

| 当前实现 | 依据 | 接入要求 |
| --- | --- | --- |
| 供应商策略只有平台、分组等权限 | `backend/internal/service/vendor.go`、`vendor_hierarchy.go` | 增加 OpenAI 授权模式权限，纳入父子继承与撤销 |
| 供应商 OpenAI 只提供 OAuth / Refresh Token | `backend/internal/handler/vendor.go`、`frontend/src/features/vendor/components/AccountForm.vue` | 分开“授权模式”和“授权录入方式” |
| 供应商授权、刷新、导入按原生 client 处理 | `vendor_oauth.go`、`vendor_account_credentials.go`、`vendor_account_transfer.go` | 使用服务端固定的原生 / Excel profile，保留可信身份核验 |
| 独立 BPS 凭证已有加密存储、刷新锁和并发更新保护 | `openai_excel_oauth.go`、`backend/migrations/272_excel_bps_grants.sql` | 复用实际表 `openai_excel_grants`，避免再造凭证仓库 |
| BPS 表单使用管理员接口 | `frontend/src/components/account/ExcelBPSAuthorization.vue` | 复用交互组件，通过供应商范围内的服务端流程完成授权 |
| 用量已有供应商归属快照，合同按分组计价 | `backend/ent/schema/usage_log.go`、`vendor_settlement_contract.go` | 增加实际执行模式记录，保持两条结算边的归属与防重 |

因此不能仅在表单加一个 BPS 选项，也不能通过传入任意 `client_id` 或打开 `extra.openai_excel_bps` 绕过授权。

## 2. 平台、授权模式与录入方式

界面层次为：平台 → 授权模式 → 录入方式 → 分组与代理。

| 平台 | 授权模式 | 录入方式 |
| --- | --- | --- |
| Claude | 沿用当前授权模式 | 沿用 OAuth / Token 流程 |
| OpenAI | 原生授权（Codex） | OAuth 登录、原生 Refresh Token 导入 |
| OpenAI | BPS 授权（Excel） | BPS OAuth 登录、经过真实验证的 Excel 授权材料导入 |

`oauth`、`refresh_token` 描述录入方式，`native`、`bps` 描述授权模式。BPS 不是第三个平台，也不是一种新的供应商角色。导入材料的具体必填项由对应 profile 的后端验证器决定；普通原生 Token 不能转换为 BPS 授权。

供应商页面使用统一的能力描述：可用平台、有效授权模式、各模式允许的录入方式。管理者编辑下级时同时看到“已授予”和“因上级限制而不可用”，避免将隐藏选项误认为已授权。

## 3. 超管、一级、二级的授权关系

在新增 / 编辑供应商的 OpenAI 权限下增加两个可独立勾选的子项：“原生授权”“BPS 授权”。启用 OpenAI 时至少选择一个模式。后端保存模式白名单，并与平台和分组一起校验。

| 一级有效权限 | 一级可添加 | 可以授予直属二级 |
| --- | --- | --- |
| 只有 Claude | Claude | Claude |
| OpenAI 原生 | 原生 OpenAI | 原生 OpenAI |
| OpenAI BPS | BPS OpenAI | BPS OpenAI |
| OpenAI 原生 + BPS | 两种，可绑定同一账号 | 原生、BPS 或两种 |

二级有效模式 = 二级配置模式 ∩ 一级有效模式；平台和分组也分别求交集。创建、重新授权、导入、授权撤销和实际调度均使用同一后端规则，前端不维护第二份权限规则。

父级撤销某模式后，直属二级相应模式立即不可用于新授权和新调度；失效未完成会话及相关调度缓存。保留账号、凭证关联、归属和历史，显示“上级已撤销 BPS 权限”等具体原因。正在处理的请求沿用项目现有策略撤销语义；撤销后的重试、下一次 WS 请求和重新选路必须复核，不把旧连接视为永久授权。

一级查看二级账号时，只能查看授权状态、归属和历史用量，不能触发授权、刷新、探测、撤销或凭证导出。超级管理员沿用现有供应商范围内的管理权限。

## 4. 一个账号、两份独立授权

以经过可信验证的上游账号身份保留一条资源记录。同一所有者可以给这条记录绑定原生授权和 BPS 授权；两种凭证独立保存、独立刷新、独立显示状态。

- 原生单授权、BPS 单授权、双授权都计为一个账号，使用同一账号 ID、归属供应商、分组关联及总并发额度。
- 双授权仍分别遵守原生 / BPS 的模型条件、速率限制和冷却；不能因持有两份凭证就假设上游有双倍额度。
- 给已有原生账号附加 BPS 时，验证上游 workspace、user 等身份一致，写入现有加密授权表，不覆盖原生凭证。
- 给 BPS 主凭证账号补充原生授权时，需要显式确认目标账号，并原子完成“原 BPS 凭证转独立加密存储 + 保存新原生凭证”。并发冲突或验证失败全部回滚，保留原账号和授权。此转换不能直接套用目前拒绝主 Excel 账号的独立授权导入接口。
- 同一上游身份已属于其他供应商、平台或归档账号时，返回归属冲突，不能另建一条不同模式的账号规避。身份占用键继续基于平台与可信上游身份，不增加授权模式维度，也不单凭邮箱判断归属。
- 暂停某模式只停止该模式供给；解除授权须说明影响范围。失去最后一个可用授权后账号停止调度。账号“删除”仍为归档，整条账号停止供给并保留历史和身份占用。

## 5. 授权会话与凭证验证

复用现有供应商 OAuth 会话流程，扩展 `authorization_mode` 和明确的授权操作（新建、补充、重新授权），目标账号沿用 `target_account_id`。

服务端会话绑定：当前登录授权、资源所有者、父子有效策略版本、固定 OAuth profile、目标账号及指纹、分组、代理版本、state、PKCE 和到期时间。完成换码时重新核验，不能仅在打开授权页时检查权限。

原生模式映射到原生 client / redirect；BPS 映射到项目已有 Excel client / redirect。浏览器不能自选 client 或回调目标。OAuth 完成后后端直接持久化，只返回脱敏账号与授权状态，不把 Access Token / Refresh Token 返回供应商浏览器。

BPS 导入、重新授权和平台身份基线核验使用相同的 profile。供应商归属通过固定 OpenAI JWKS 的 RSA/RS256 签名核验，检查 issuer、client/audience、工作区、用户、有效期及可选新 ID Token 的关联。公开 JWKS 连通性已验证，签名及攻击场景由测试覆盖；尚未使用真实用户凭证完成 OAuth 换码。不能取得可靠身份的材料禁止认领和调度。已保存授权的旧 ID Token 不作为新一轮刷新证明；无 Refresh Token 的有效 Access Token 可使用至到期，随后需重新授权。

代理继续使用账号所有者获准的出口。更换代理不清空两种授权；任何代理变更需遵循现有会话并发保护。父级只读视图不展示代理密码或完整凭证。

## 6. 账号池与交互

新增账号选择 OpenAI 后，显示“原生授权”“BPS 授权”并列选项，仅展示当前有效权限。授权卡片说明用途、可用录入方式和分组，用户无需理解内部 client 名称。

账号池在名称附近显示“原生”“BPS”或“双授权”标记，筛选增加授权模式；上级视图继续常驻“归属供应商”列。双授权账号匹配任一模式筛选，统计总账号数时去重。

详情中的“授权管理”分别展示两种模式的未授权、正常、需要重新授权、已停用、权限被撤销等状态。原生和 BPS 各自提供对应的授权维护入口。上级只读视图隐藏写操作，服务端同样拒绝。

需区分四件事：供应商有模式权限、账号已有有效凭证、该模式已启用、当前请求满足模型与调度条件。“BPS 已授权”不能直接显示为“所有请求正在走 BPS”。

模型选择、BPS HTTP/SSE、WebSocket 桥接及显式图片能力复用当前网关。图片不能因为勾选 BPS 就自动切换所有图片流量。授权失败、导入失败和到期状态给出可操作说明；语言和浅色 / 深色 / 系统模式沿用控制台设置。

## 7. 调度与故障恢复

候选路径须同时满足：资源未归档且可调度、供应商及上级有效、平台 / 模式已授权、请求分组匹配、相应授权有效，以及原模型与速率限制。授权条件进入原调度快照与实际转发检查，共用原数据库、Redis、并发控制和调度器。

对双授权账号，BPS 与原生的选择沿用模型配置及现有恢复契约。BPS 失败不意味着可以无条件换用原生；原生回退候选也必须具有当前有效原生权限和凭证。BPS 单授权账号本身不能冒充原生账号。跨账号恢复仍需符合消费分组、会话连续性、输出边界和重试限制。

父级撤销 BPS 仅收回受影响的 BPS 路径；仍具有原生权限与凭证的账号按原生条件参与调度，不擅自把原来仅允许 BPS 的请求改走原生。所有入口采用同一模式判定，不能出现 HTTP 被限制而 WS、导入或探测绕过的情况。

后台刷新同样按实际主授权模式检查权限，不用“任一模式可调度”替代刷新授权。等待限流后再次检查，持久化时以原凭证、代理、授权版本及实时策略作为条件。永久失效只停用对应模式，瞬时失败沿用有限重试，均不因单份授权故障阻断另一份有效授权；刷新后的缓存使用数据库当前状态，不能清除其他暂停或调度限制。

## 8. 用量与两级结算

用量保存实际执行模式 `native` / `bps` 的不可变快照，与实际供给账号、直属供应商、root / parent、计量分组、实际模型和成本一起记录。该字段来自实际转发结果，不从账号当前开关推算。历史没有可信模式信息的记录显示“历史未记录”，不能依据现配置回填。

同一双授权账号的用量可以分别统计原生和 BPS，也可以合并查看。客户扣费继续归消费用户 / API Key；供给采购归实际供给账号，保持平台→一级、一级→二级两条独立结算边，每个计量事实在每条边上只能结算一次。

重试、压缩或工具修复如产生已有计费规则认可的多段实际用量，应保留各段真实模式和归属，沿用原计量与防重规则；不能把全部费用标成最后成功的模式，也不能因双授权重复计费。下游兼容响应中的 Token 表达不代替项目现有的计费事实。

本次授权接入沿用已存在的默认 / 分组合同单价，增加按实际模式核对用量。两种模式在同一分组需要不同采购单价时，应另行扩展两条结算边的模式价及合同快照，不能用账号统计倍率临时替代。也不能假定将分组命名为“BPS”就能强制协议；是否限定执行模式必须有相应后端规则。

## 9. 最小数据与接口调整

| 调整 | 现有实现不能承载的原因 | 复用方式 |
| --- | --- | --- |
| 供应商新增 OpenAI 模式白名单 | `platforms` 无法表达仅原生或仅 BPS | 原供应商编辑、层级求交、策略版本和缓存失效 |
| 账号输入 / OAuth 会话新增模式及操作 | 当前 `method=oauth` 无法确定 native / Excel，也不能区分补充与替换 | 原会话创建 / 完成 / 代理重绑及导入验证链 |
| 账号 DTO 增加两种授权的脱敏状态 | 原账号状态无法表达双授权独立过期、撤销 | 现有账号详情、列表和 Excel 授权状态服务 |
| 用量增加实际执行模式快照 | `platform_snapshot=openai` 无法区分两种真实路径 | 原用量写入、查询及结算快照 |
| 按模式撤销授权的受限操作 | 账号归档影响整条资源，不能代表解除一份授权 | 增加一个按模式撤销的语义操作，复用现有授权服务、归属校验和审计 |

现有供应商 CRUD、OAuth start / complete、账号列表 / 详情及导入 API 扩展参数即可；不向供应商直接开放 `/admin/openai/*`。按模式撤销作为独立资源操作设计，例如 `DELETE /vendor/accounts/:id/authorizations/:mode`；超管入口使用相同服务并经过既有管理范围校验。字段名称及最终路由须在实施时与现有 DTO 一并定稿。

迁移既有供应商时，已有 OpenAI 授权默认映射为原生权限，不自动给全部供应商开通 BPS。先清点真实存量 BPS 账号，存在例外则显式制定映射，避免静默停供。仍复用 `accounts`、`account_groups`、`openai_excel_grants` 和现有 Redis 命名空间。数据库迁移只在实施并验证后安排，不在设计阶段执行。

## 10. 实施顺序与验收

1. 实测 Excel 可信身份核验，完成原生单授权、BPS 单授权、双授权和身份冲突的后端数据闭环。
2. 加入授权模式策略、父子继承、会话绑定、导入验证与调度撤销；补全供应商与超管的范围控制。
3. 接入供应商开户权限、账号新增 / 补充授权、列表筛选和详情维护，复用原生组件与主题 / 多语言。
4. 增加实际模式用量快照及统计，核对双边结算和重试防重，再做页面与真实 API 验收。

必验场景：

| 维度 | 验收要求 |
| --- | --- |
| 权限 | Claude-only、原生-only、BPS-only、双模式四种父子组合；伪造平台 / mode / client、导入和旧会话不能越权 |
| 归属 | 同一所有者补充授权保持账号 ID；其他供应商、平台既有身份和归档身份不能重复认领；一级对二级始终只读 |
| 凭证 | 原生 / BPS 刷新互不覆盖；并发补充与撤销保护；BPS 主凭证转双授权失败可回滚；代理更换保留有效授权 |
| 调度 | 共享账号总并发，模型条件和独立冷却有效；BPS-only 不走原生；父级撤销后新 HTTP / WS 请求和恢复路径都受限 |
| 计量 | 原生 / BPS / 混合恢复的真实用量与归属正确；两条边各计一次；当前模式变化不改历史 |
| 页面 | 新增、重新授权、导入、筛选、详情、撤销、只读及错误状态；两种语言、三种显示模式；对照正式原型及已提供参考布局 |

最终接口、迁移、代码规模及验证边界以 [实施验收](OPENAI-BPS-AUTH-ACCEPTANCE.md) 为准。界面保留同一账号内两张独立授权卡片；供应商专属凭证操作不能直接复用管理员授权组件的 API，因此新增供应商范围内的 `AccountAuthorizations.vue`，使用既有表单、抽屉、主题和多语言组件。
