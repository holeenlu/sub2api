## 当前实现：V3 统一供应商平台

当前以 [统一平台方案](UNIFIED-PLATFORM-PLAN.md)、[本轮真实验收](UNIFIED-PLATFORM-ACCEPTANCE.md) 和 [接口说明](API-ROUTES.md) 为准。一个后端和一套数据库/Redis，客户域名与供应商域名分开；供应商站按真实登录身份展示超管、一级、二级工作区。

客户运营后台已移除旧供应商平台菜单，旧 `/admin/vendors` 页面返回运营首页；超管统一使用供应商域名 `/vendor/platform`。后端 `/api/v1/admin/vendors` 继续复用。独立域名的 Caddy / Nginx 配置与 404 排查见 [入口路由说明](PORTAL-ROUTING.md)，该规则替代下文历史记录中的旧后台入口。

专用角色、原子密码开户、直属二级只读资源、双边结算及原生账号调参已经实现。开户默认 1000 / 1000 / 15 / 1；头像保留个人设置，供应商侧栏不再提供独立审计/安全页。旧 [交互原型](prototype.html) 保留为 V2 设计历史，不能用于验证 V3 真实权限、开户或结算。

## V1 已实现基线

需求登记：VC-2026-10-15 · 更新于 2026-10-16 · 共享能力（KDAN / TapModels / Tokensavy）。

当前已实现 Go 后端、原项目 Vue 管理界面及独立供应商门户，完成本地真实 API 联调；本轮界面还原和本地验收不代表生产站点已更新。供应商登录账号及供给策略只能由超级管理员创建、配置、停用和管理；普通管理员不能通过既有用户、账号、代理或批量接口绕过。供应商在授权范围内管理自己的 Claude / OpenAI 上游账号、专属代理和历史用量。

## V1 功能基线（层级规则由 V2 替代）

1. 超级管理员后台：供应商管理、供应商账号、供应商代理、供给用量、结算对账、分组供给、操作审计；支持新建普通用户或关联已有用户开通、范围/限额/默认值配置、停用及启用。
2. 账号添加：名称、备注、平台、专属代理、授权分组多选、原项目支持的 OAuth / Token 方法；并发、优先级和统计倍率使用平台默认。
3. 账号池：概览、筛选、故障分布、密集表格、独立分页；配额窗口显示使用率、重置时间及未知状态。
4. 账号维护：详情、用量、编辑、重新登录、探测实例、同步信息、暂停/恢复、删除；删除仅归档并停止供给，仍在账号池列表，保留账号资料、授权关联、历史用量与审计。
5. 代理修改：更换绑定、修改端点均保留账号授权。未完成 OAuth 会话由后端原子更新出口，已开始换码则提示冲突，不删除已有凭证。
6. 授权导入/导出：显式确认、文件/JSON 输入、逐行预览、重复处理与代理映射；原型仅接收 DEMO 数据，正式实现复用项目原生数据格式与敏感操作校验。
7. 代理工作台：四项概览、多条件筛选/排序/分页、绑定与引用详情、标准/快捷/文件导入、连接与手动质量检测、引用保护批删、CSV/JSON脱敏清单导出；供应商与超级管理员共用。修改代理保留账号授权。
8. 统计与详情：账号/平台/时间筛选、四项汇总、日表/账号表；用量详情提供七类用量指标、固定 5 小时/7 天/30 天快照、趋势切换、模型与结果分布。

## 当前实现边界

OpenAI 原生 / BPS 并行授权已接入供应商权限、账号池和用量链路。见 [授权设计](OPENAI-BPS-AUTH-DESIGN.md) 与 [实施验收](OPENAI-BPS-AUTH-ACCEPTANCE.md)；本次实施不代表已部署生产或完成真实用户 OAuth 登录。

复用现有用户认证、授权会话、账号池、代理、调度、计费和审计。供应商使用独立 vendor_level1 / vendor_level2 角色；一级可以管理直属二级身份及合同，但其供给资源只读。不创建第二套网关或登录系统。

最新需求已将多供应商费用对账、结算单和线下付款登记纳入首版；统计消耗通过已确认的合同计价规则形成应付金额。自动转账、提现、公开供应商注册、自动登录 Worker、Cookie/票据接入及其他退役运营扩展仍不在范围内。

## 历史原型：后台扩展（2026-10-15）

- 多供应商：可搜索、分页、按状态筛选；联系资料与结算资料分开管理，账号、代理、用量均可按供应商查看。
- 对账结算：按供应商、账号、实际计量分组、请求日期筛选，支持供应商/账号/日期/分组聚合及明细导出；结算草稿、确认锁账、部分/全额付款登记、未付款作废与审计形成闭环；已确认账单冻结收款与计价快照。
- 独立入口：供应商在专用子域名登录，只进入自己的工作区；复用现有认证服务，后台与供应商入口隔离会话及权限。原型用同源独立入口模拟，不配置真实 DNS；正式实现沿用原 Token 认证并按 Origin 隔离存储。
- 共享分组：供应商账号加入系统原生分组，超级管理员、管理员、普通用户创建的 API Key 均可按 Key 所属用户的原有分组授权使用；供给管理权限与消费权限独立。
- 结算口径：截图中的收款联系人、结算邮箱、币安 ID 映射为结算档案；原型仅使用虚构信息。默认/分组合同系数、换算价与币种明确展示，结算不直接采用消费者扣费；系数与账号统计倍率分开。截图单位暂作明确假设，正式合同需核定。

原型入口：主页面切换“超级管理员”查看后台，点击“独立入口设置”打开专用登录页面；供应商通过“我的结算”查看本人已确认账单。完整单位、并发防重、账期截止与晚到数据规则见 [方案](DESIGN.md)，本轮验证见 [后台结算复核](IMPLEMENTATION.md#admin-settlement-review)。

遵守 [原生能力边界](../FORK_FEATURE_RETIREMENT.md)、[BPS 要求](../bps/REQUIREMENTS.md)、[Responses 恢复契约](../OPENAI_RESPONSES_RECOVERY.md) 和 [需求交付规范](../CHANGE_DELIVERY.md)。后续获授权实现与交付时，共享代码先落 main，再普通 merge 至品牌分支。设计、业务实现、推送、发布、部署及生产迁移分别记录，互不等同。


## 历史原型：代理管理补全（2026-10-15）

- 入口：供应商 → 代理管理；超级管理员 → 供应商平台 → 供应商代理。独立供应商入口使用相同工作台。
- 对照新截图补齐总数/占用/占用异常/未占用、协议/状态/地区/使用情况/创建日期、创建者/私有范围、账号占用、延迟/质量、有效期和分页；批量操作明确已选/筛选全量范围。
- 新增手动质量报告、逐项检测/取消、账号/备用/OAuth引用保护删除、文件导入与脱敏清单下载。快捷代理和账号内联添加继续复用；更新出口或代理认证不清除账号授权。
- 清单导出不含代理密码，回导需补认证。连接/质量结果全部为虚构演示，不调用真实网络；普通管理员仍无权管理供应商资源。
- 详细规则见 [代理方案](DESIGN.md#proxy-workbench)，当时原型证据见 [代理专项复核](IMPLEMENTATION.md#proxy-workbench-review)。原型阶段拟定接口由50项调整为53项，当时尚未新增业务接口；当前已落地清单和数量以 [接口说明](API-ROUTES.md) 为准。
