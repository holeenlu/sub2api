# 供应商平台 V2：独立角色、两级供给与双边结算

> **2026-10-17 V3 当前规范**：[统一平台方案](UNIFIED-PLATFORM-PLAN.md)和[本轮真实验收](UNIFIED-PLATFORM-ACCEPTANCE.md)已替代下面涉及普通用户身份、邀请/无密码开户、独立审计/安全菜单和单边结算的旧决定。以下保留历史原型与历次验收证据；不代表 V3 尚未实现，也不代表已经生产部署。

状态：最新需求设计与可操作原型；后端仍为 V1，未经迁移不得宣称已支持两级权限。适用于 KDAN、TapModels、Tokensavy 的共享业务，品牌、域名和渠道各自保留。

## 1. 最新决策与边界

本方案取代 V1 的「普通用户附加供应商能力」「所有供应商仅超级管理员创建」「单层结算」三个假设。供应商是独立角色，不由侧栏、前端标签或客户端传入的 vendor_id 授权。既有网关、原生分组、消费者 API Key 资格、OAuth、MFA、Passkey、会话与计费路径继续复用。

| 角色 | 真实角色值（待实现） | 可管理身份 | 资源 | 财务 |
| --- | --- | --- | --- | --- |
| 超级管理员 | super_admin | 创建/配置/启停一级；全局治理及紧急停用二级 | 全部供应商账号和代理列表/详情；凭证操作单独鉴权 | 平台向一级应付；全链路审计 |
| 一级供应商 | vendor_level1 | 仅创建/配置/启停直属二级，不能创建一级 | 管理自有账号池、专属代理；直属二级账号和代理只读 | 向平台应收、向二级应付，两本独立账 |
| 二级供应商 | vendor_level2 | 不可创建下级或改变上级 | 仅自己的账号池、代理 | 仅上级对自己的合同、账单和收款记录 |
| 管理员/普通用户 | admin / user | 不可创建或伪装成供应商 | 按原授权使用消费侧分组与 API Key | 不得进入供应商账本 |

当前版本限定两层；不允许二级再创建三级。平台直接合作的供应商即一级，即使没有下级。一级既可自供，也可汇集下级供给。账号和代理只有一个直接所有者；查看下级不等于获得其授权密钥。父级不可编辑、删除、启停、重授权、刷新、探测、同步下级账号/代理，也不可通过详情弹窗、批量接口或凭证导出来绕过只读限制。父级不得导出子级 OAuth/Refresh Token、代理密码。需要代运营时另行明确授权，本次不加入隐式代登录。

## 3. 身份创建、授权与上下级

### 创建向导
1. 身份：名称、登录邮箱、联系人、结算档案。角色和上级由服务端从操作者确定，界面只读说明。根管理员创建一级；一级创建直属二级。
2. 供给范围：开放平台、原生分组多选、允许的授权方式、直连策略、账号/代理/子级数量上限、默认并发/优先级/统计倍率。二级范围必须是一级当前有效范围的子集。
3. 结算合同：币种、计费基数、默认价、分组覆盖价、结算倍率、生效时间、时区、账期、付款期限。一级给二级定价与平台给一级定价相互独立。
4. 复核：展示身份、权限差集、资源配额、合同版本、通知对象。原子提交身份+关系+策略+初始合同；唯一邮箱/配额并发冲突返回明确错误，不留下半开通用户。

邮箱不是登录凭证。沿用无明文初始密码的创建界面，但新身份必须处于待激活状态，通过单次、短时、哈希存储的激活令牌自行设置密码；邀请失效可重发并作废旧令牌。邮件不可用时允许管理员取得一次性激活链接，复制前二次验证、审计且不记录令牌。不得用用户看不到的随机密码假装已可登录，也不得把旧账号静默改为供应商。激活、找回密码、MFA继续复用原认证基础设施。

有效能力 = 平台边界 ∩ 根供应商策略 ∩ 直属供应商策略 ∩ 账号状态。自身停用与祖先停用分别记录；父级停用立即禁止该树的新登录、管理写操作与新调度，保留在途处理、授权、历史、账单。父级恢复不能解除子级自身停用/账号暂停/平台封禁。配额包含一级自有与下级总量，子级上限另设；通过事务锁/原子计数防止并发创建突破树级总量。

权限变更提升策略版本并失效会话范围缓存。禁止客户端修改 parent_id/root_id/tier/owner，禁止跨根移动。确有转移需求须另行实施生效日切换和双人审核，旧用量永远按事件时归属结算。V2本次不开放组织转移入口。

## 4. 两层合同与结算

每条请求只产生一份供给事实。同一份二级供给可参加两条不同方向的结算：平台 → 一级（platform_to_l1），一级 → 二级（l1_to_l2）。一级自有供给仅参加第一条。两条账单不合并成一个应付，也不让平台绕过一级重复支付二级。

### 计价口径
固定公式（V2首版）：应付 USDT = Σ(可结算基数 USD × 合同单价 CNY/USD × 合同结算倍率) ÷ 账期换算价 CNY/USDT + 调整 USDT。基数使用项目后台经核对的原始官方成本（含缓存项），不能再乘已经计入统计成本的账号倍率。账号统计倍率、消费者实际扣费、结算倍率必须分别命名、分别记录。若历史只保留倍率后成本且不能复原，标记不可自动结算，人工对账，禁止猜测。

所有数字为定点 decimal / 整数最小单位；中间保留高精度，在合同规定分组/合同版本行四舍五入至 USDT 分，汇总这些行，不在请求级反复舍入。API以十进制字符串传金额。调整单独成行、必填原因、关联原单；已有付款不可直接作废。

例如虚构基数 1,000 USD、换算价 6.7：平台给一级单价 1.8、倍率 1 → 268.66 USDT；一级给二级单价 1.6、倍率 0.95 → 226.87 USDT；该二级供给毛差 41.79 USDT。这些是交互样例，不是实际汇率/市场价。一级自有供给不可计入「下级毛差」。未锁账为预计金额，已锁账才能计入应收应付；收付款分别登记、不可用应收抵应付假装完成付款。

合同按 payer/payee/分组/生效区间版本化，同优先级区间不重叠；具体分组价覆盖默认价。使用请求发生时间选择版本，账期跨版本拆行；费率调整默认未来生效，不修改已经发生的供给，也不改写冻结账单。币种/汇率、费用基数、合同版本、拥有者和上级快照随结算固化。费率、倍率允许 0（有明确免费供给确认），禁止负数、NaN、无穷或超精度。下游报价超过上游预计收入只提示预计负毛差，不擅自禁止正常商业定价。

### 状态和流程
合同：草稿 → 待生效 → 生效 → 失效/被新版本替代。账单：草稿 → 待对方确认 → 异议/已确认 → 部分付款 → 已结清；未付款可作废并保留审计。价格更新/重新预览不能自动确认。付款登记只能由该结算边的付款方操作，收款方可核对/异议，审计记录双方身份。

平台只有第一条边的付款权限；一级对第一条是收款方、第二条是付款方；二级只看自身第二条。平台为必要财务治理可审计全链但不能冒充一级确认或代付第二条。其他一级和兄弟二级不可见。下游不可见上游采购价和毛差。

## 5. 数据模型与后端变更清单（待实现）

复用 users 认证主体，但 role 必须扩展 vendor_level1/vendor_level2；这不等于继续 role=user。所有判定「不是管理员就是普通用户」的逻辑须改显式允许列表。users、vendors创建放入同一服务事务；普通用户、管理员、供应商分别进入匹配的站点和路由。

| 现有实体 | 必需变化 | 原因 |
| --- | --- | --- |
| users / claims / DTO | 独立角色，身份状态，真实密码设置状态；JWT与缓存重新签发 | 原 role=user 无法表达两级权限 |
| vendors | tier、parent_id、root_id、child_limit、树级配额、关系版本 | 原 user_id 唯一绑定没有组织链 |
| vendor_groups / policy | 子集校验、祖先版本及有效停用原因 | 防止策略扩大和旧 Token 越权 |
| accounts / proxies | 保留直接 vendor_id；账号原生 extra 记录归档时间；下级只读投影，创建者来源单独记录 | 原生资源逻辑可复用，避免重复账号表；归属不等于创建者 |
| usage_logs / durable supply fact | leaf_vendor_id、root_vendor_id、关系版本、实际服务分组、原始成本/倍率快照、请求时间 | 归档/改名/后续关系变化不能改写历史 |
| vendor_contracts / contract_rates | payer/payee/leg、生效区间、版本、分组价、倍率、币种和账期 | vendors单一default_coefficient无法表达两份合同和时点 |
| vendor_settlements / lines | leg、payer/payee/root/leaf快照、合同版本、基数、价、倍率、换算价、确认和异议 | 复用既有账单与付款，不新增第二套财务引擎 |
| vendor_settlement_allocations | active唯一约束改为(source_fingerprint, leg)及(usage_log_id, leg)，账单内仍唯一 | 当前全局唯一会错误阻止第二层结算；只放宽唯一却不加leg会重复付款 |
| audit / invitation | actor、effective role、root、owner、leg、对象、前后版本；令牌与密钥不入日志 | 支持跨层管理与激活且不泄漏秘密 |

索引以真实查询计划验收：root_vendor_id + occurred_at + id、leaf_vendor_id + occurred_at + id；合同 payer/payee/leg/time；账单 payer/payee/leg/state/period；排他约束/事务检查合同区间。枚举层级和parent/root一致性由数据库约束+服务事务共同保证，不信任payload。

### 接口归属
扩展现有 /admin/vendors 一级管理；新增 /vendor/children 集合（列表、创建、详情、修改、启停、邀请）；复用 /vendor/accounts、proxies、usage，scope=self/tree/child 仅允许对应只读聚合，资源写接口继续直接所有者；扩展 /vendor/contracts 与现有 settlements 以 leg 与方向选择。统一 VendorScope携带 actor角色、本人、根、允许子集、策略版本，供所有repository约束使用。具体 OpenAPI/DTO以实施PR为准，不把本文当成已部署接口。

旧 users 创建/改role、admin accounts/proxies、批量导入导出、认证刷新、测试、OAuth回调、下载任务、报表、缓存、异步任务都执行同一授权服务；不能仅保护新菜单。后台管理员不得通过旧用户接口创建supplier角色或修改其所属关系。所有返回及导出禁止包含下游消费者个人资料/API Key秘密，账号授权导出限资源所有者并二次验证。独立Origin+服务端角色/租户校验同时生效。

## 6. 查询、运营报表与历史保留

- 总览分别显示自有/下级/全部供给，账号可用率、最近60秒RPM、5小时/7天/Fable分布；未知配额保持未知，时间标注来源与时区。
- 报表按一级、二级、账号、请求日期、模型、实际服务分组聚合；保留故障过滤、日期快捷范围、列选择、排序、分页与导出。多分组账号只按请求实际分组计一次。
- 财务列明确「原始成本USD」「账号统计消耗USD」「结算基数USD」「上游应收USDT」「下游应付USDT」「下级供给毛差USDT」。不同币种不直接相加，缺合同/缺汇率的行显示待配置，不补0。
- 列表、总计、图表、CSV共享标准化过滤器、范围和快照；CSV取全筛选范围，不只导出本页；大范围使用异步任务，游标/稳定排序，下载重新鉴权。
- 点击「删除」仅归档账号并停止新供给，不从数据库或账号池列表移除。保留账号资料、原始健康状态、授权、分组、代理关联、身份占用、用量、账单和审计；详情与历史用量可读。代理修改/切换只改网络配置，不清空 OAuth。敏感字段不混入通用 PATCH。
- 每条事实在每一结算边最多被一个有效账单占用；重试幂等、锁账事务、并发生成冲突、迟到用量调整都单独验证。原始日志清理不能删除结算所需持久事实。

### 账号归档与查看边界（2026-10-17 补充）

归档是资源生命周期，与正常/异常的健康状态分开。列表名称下显示「已归档」和归档时间，原健康状态继续展示；归档账号保留在默认账号池、历史选择器、全部供应商列表及父级只读列表，可筛选全部/未归档/已归档。实时可用数、调度候选和实时负载不包含归档；累计消耗、日期报表和结算包含归档前事实及真实在途请求完成的事实。列表总账号数不能冒充可供给账号数。

复用现有 DELETE 路径执行原子归档：记录首次归档时间，设为不可调度，停用关联后台任务但保留配置与历史；重复请求幂等。保留凭证是留存要求，不等于允许导出或再次使用。归档后拒绝编辑、暂停/恢复、换码、刷新、探测、同步、导入覆盖和凭证导出；异步或在途管理写入须在提交时再查归档标记。旧 admin 单条、批量及资源服务入口适用同一规则。父级恢复、供应商重新启用或身份导入不能复活归档账号；本次不新增恢复入口。

原始账号/影子账号一并停止供给并失效调度缓存；代理关联仍计入引用，不能因归档误删被引用代理。身份唯一占用保留，防止重新导入绕过归属。历史已被旧逻辑置 `deleted_at` 且清空凭证的账号继续保留历史可读，不尝试伪造恢复丢失的授权；其「历史已删除」与新「已归档」状态区分。

| 操作 | 超级管理员 | 一级：自有资源 | 一级：直属二级资源 | 二级：自有资源 |

### 运营报表与资料逻辑（按用户参考表补充）

同一查询提供「运营明细」「模型成本」两种视图，超级管理员覆盖全部树，一级覆盖自有与直属二级，二级仅自有。支持供应商、账号、账号×日期、日期、实际服务分组、模型维度；按成本降序为默认，支持请求数/日期/Token 等服务端排序并以稳定 ID 破除并列。日期采用所选时区的 `[开始日00:00, 结束日次日00:00)`，时区在筛选、总计、图表、CSV和账单均明确。

| 字段 | 展示/数据规则 |
| --- | --- |
| 账号 | 名称、稳定 account_id；改名/归档不换主键，历史账号无资料时显示 ID 与已知名称快照 |
| 当前状态 | 原健康状态和归档状态分列/分标识；不能把今天状态当成历史请求结果 |
| 所属供应商 | 直接所有者名称、供应商 ID、级别、上级；报表归属优先请求时 leaf/root 快照，不按当前名称猜测 |
| 创建来源 | actor ID、角色快照、来源（控制台/API/授权导入/平台代建）、创建时间；「二级供应商创建」须有真实记录，不能由所有者角色推导。缺失显示「未记录创建来源」 |
| 请求数 | 相同过滤和水位下持久供给事实数量；成功/失败仅在后端有可靠记录时展示，未知不补零 |
| Token | 输入/输出分两行；缓存写入/读取另两行。总 Token（含缓存）= 输入 + 输出 + 缓存写入 + 缓存读取；不得重复计缓存 |
| 缓存命中率 | 缓存读取 ÷（输入 + 缓存写入 + 缓存读取）；先汇总分子分母，再求率；分母为零显示 —，不平均各行百分比 |
| 账号统计消耗 USD | 沿用后台 `AccountStatsCostSQL` 的历史统计成本；包含缓存项，明确账号统计倍率；不是当前模型价格重新估算 |
| Opus/Fable 消耗 USD | 复用后台原生模型归一规则与实际发出的模型（upstream_model 优先），不按请求别名/前端字符串猜测。命名为金额消耗，不用「已用额度」暗示上游配额 |
| 其他/未分类消耗 USD | 总统计消耗 − Opus − Fable，高精度 Decimal 计算；包括其他平台/模型和无法分类记录。缺分项或分项超过总计时标记不可核对，禁止负数或补零掩盖异常 |
| 总计/结算基数 | 所有筛选结果合计，非本页合计；统计成本与原始成本、结算基数、应收/应付分开。未知原始成本不可由倍率后的统计金额反推 |

模型视图须满足 `Opus + Fable + 其他/未分类 = 总统计消耗`；汇总和行保持精确 Decimal 字符串，界面小额保留有效精度，导出不截断。原型金额以 1/10,000 USD 整数虚构演示，正式实现沿用现有后台十进制精度。平台→一级和一级→二级两份合同分别计价，不能把两条结算金额再次相加当消耗。

账号创建审计、资源归属、请求事实、价格合同和付款资料各有独立来源：创建者≠所有者≠消费者≠付款方。按事件快照存 root/leaf、account_id、实际服务分组、模型、原始/统计成本；查询时显示的账号健康/归档状态注明为当前状态。权限过滤先在服务端完成，再聚合/分页；总计、筛选项、详情、导出和异步下载都要同范围鉴权，禁止通过下拉选项泄漏兄弟树。

复用现有 usage 接口、聚合 SQL、金额工具、索引与快照水位。不从账号列表逐条发 N+1 统计请求；源字段缺失先扩充同一安全投影，不另建平行报表事实表。有限查询直接返回；大范围异步导出设时间/数量边界与审计。按真实 EXPLAIN 验证时间与归属复合索引，不能只给前端加分页。原日志归档后仍需保有可核对的持久供给事实，账单冻结后补记/冲正独立留痕。

### 账号池与代理交互（2026-10-17 补充）

账号行操作使用项目原生图标。信息按钮打开右侧全高、桌面最大 576px 的详情抽屉，正文内部滚动；基本信息、运行指标、状态、冷却、配额、模型限制顺序稳定。调度信息在打开时获取，注明快照语义；来源、所有者、权重和优先级各自使用真实字段，缺失显示未知。出口可复制协议/主机/端口，禁止在详情或复制内容中拼入代理认证信息。关闭后返回触发按钮焦点；归档/下级只读详情不能出现管理入口。

代理连接测试作为轻操作，点击行图标直接执行并在该行显示加载状态，以延迟/错误和 Toast 反馈。批量按钮明确显示选中数量或全筛选范围，开始前收集完整分页并检查后台限制；执行期间固定范围，最多并行 2 项，可停止尚未发出的请求。结果分别计有效、无效、跳过、未执行，跳过原因使用后端实际结果，不将所有跳过项都解释为停用/过期。切换角色/供应商、资源版本变化和页面卸载时取消或丢弃过时结果，禁止误写其他范围。

质量检测继续独立确认与展示目标平台报告；连接成功不等同于平台质量通过。刷新检测结果保留原列表和滚动位置，深色使用原生表面与文字变量。桌面固定状态/操作列，窄屏保留操作列并让表格容器横滚；主要工具栏、状态和反馈使用统一四语目录，账号名和地区等业务数据按后台事实展示。

以上交互已分别应用于原型与现有正式工作台；层级权限的服务端落地仍依赖下述 V2 实施和验收，不能仅靠按钮隐藏保证隔离。

## 7. 迁移与发布关卡

1. 先盘点：旧供应商、关联users角色、API Key/余额/订阅、账号、代理、未结账单和邮件可用性。输出待人工确认映射：旧vendor → 一级或二级+上级。禁止凭名称或现有示例「二级」标签猜层级。
2. 先加可空字段、合同表和历史边legacy；旧账单不可重价。回填可证明的历史归属，未知历史隔离为legacy仅按原单结算，不生成第二层账。
3. 对含消费身份的用户，提供分离身份/邮箱迁移流程，保留消费余额、Keys、订阅，不能直接替换role使用户丢失入口。迁移核对完再开放新角色登录。
4. 双读对账，禁止双写财务事实。分配唯一索引与leg回填必须在一项受控迁移中切换，验证有效分配无重复。
5. 角色矩阵、越权、金额和UI验收全通过后分品牌灰度启用；线上数据库迁移和部署需另行明确授权。回滚先关新创建/结算，保留新增事实与账单，不降级抹掉二级关系。

## 8. 验收矩阵

必须覆盖：root创建一级；一级创建自己二级且无法改父级/扩大分组；二级/普通用户/管理员被旧新接口一致拒绝；跨根/兄弟ID替换；子级停用后父级恢复不解封；多语言和三种主题刷新持久化；个人中心真实身份；代理变更保留授权；授权导入导出隔离；账号删除后仍在列表且授权/关联/历史保留；一级查看下级详情不出现编辑/删除/测试；请求时归属与创建者来源分离；Opus/Fable/其他合计及加权缓存命中率；日期/分页/总计/导出一致；两条结算独立占用；同边并发重试不重复；跨合同版本分行；零价/负价/缺汇率；下游不可读上游价；到账与应付不互相抵销；手机和键盘可操作。

原型的身份、数据、合同和付款均为虚构内存交互，不发送邮件、不连接数据库、不支付、不修改线上权限。正式后端V2只有完成上述迁移与接口验收才能标记已实现。
