# 参考网站实测记录

调研日期：2026-10-15（Asia/Shanghai）。需求：`VC-2026-10-15`。

## 1. 方法与证据边界

使用用户指定的电脑工具，在 Chrome 中进入两个已有登录态的页面，实际打开导航、添加账号向导、编辑窗口、代理新增/导入窗口、用量页面和账号详情，并查看页面截图。仅检查界面与现有数据，没有创建账号/代理、生成授权链接、提交凭证、执行测试、刷新 Token、改变启停状态或删除资源。

页面可见功能不等于服务端隔离已经正确实现；没有进行越权探测、源码获取或跨供应商验证。未将站点中的真实邮箱、代理地址、认证材料、会话标识及业务金额复制到项目。

来源入口：

- S1：[供应商后台](https://www.ccmax.club/vendor-console)。资源和统计在同一 URL 内切换。
- F2：[账号池](https://f2.ccmax.club/admin/accounts)。另实测 `/admin/proxies`、`/admin/archived-accounts`、`/admin/vendor-usage`、`/usage`。

公开网页抓取无法读取登录后业务内容：S1 仅返回页面外壳，F2 无法通过该抓取工具访问。因此下面的功能结论来自电脑工具中的已登录 UI，不来自搜索摘要。

## 4. 初版采用、调整与排除（历史决策）

| 决定 | 内容 | 原因 |
| --- | --- | --- |
| 采用 | 独立导航、自有账号/代理、受限字段、OAuth、健康/配额、用量、归档 | 直接服务第三方供给与维护 |
| 调整 | 平台概览改为仅自身；成本命名沿用本地定义；归档不释放他人历史；未知显示未知 | 防止信息泄露和口径混淆 |
| 调整 | 自有代理默认私有，不照搬“共享代理池” | 用户要求专属代理，归属不能由前端筛选保证 |
| 排除 | 自动 OAT、SI、SK 转换、CC 伪装、Session Slots 等参考站专有机制 | 未获用户需求授权，且可能触及现行退役边界 |
| 排除 | 一键测试后清理失败、供应商清除全局错误/限流 | 瞬时故障不应造成资源丢失或解除平台保护 |
| 后续可选 | 大批量导入、长区间异步统计、脱敏导出、多成员供应商 | 先交付完整的开通—上号—调度—用量闭环 |

## 5. 未验证与本地设计的区别

- 两站当前登录身份均未展示可操作的 OpenAI 新建流程；不能据此认定站点不支持 OpenAI，也不能声称已经实测。我们的 OpenAI 接入来自用户明确需求和本地已有实现。
- 管理员如何开通供应商、调整授权、处理归属，以及后台数据库/API 越权防护，本轮没有对应管理员权限证据。设计方案独立补足这些必要流程。
- 没有提交真实凭证，所以不声称已经验证授权成功、自动续期、重复账号覆盖、代理测试、跨归属替换或归档效果。
- S1 的 `oa授权2` 只是当前页面标签，不用于推断 OAuth 协议或 OpenAI 支持。
- 未做参考站性能压测；设计中的响应时间、容量和分期均为本项目待验收目标。

## 6. 第一轮用户反馈后的页面复核（2026-10-15）

本轮结合用户提供的两张截图，并通过电脑重新查看 S1 账号池与用量统计。只记录界面结构，没有保存或复用参考站账号邮箱、代理认证信息和业务金额。

- 账号池：我的账号概览含总数/可用/冷却/异常/停用、RPM/TPM/并发/高负载；下方是筛选、故障分布和名称/状态/分组/配额/并发/权重/今日及累计消耗/备注/缓存命中/创建时间/操作表格。
- 用量：账号与日期范围筛选，四列汇总，按日趋势表和按账号明细表分别分页；用户截图补充今天/昨天/近 7 天/近 30 天/本月/上月、双月日历及清空/取消/确定。
- 添加：用户截图显示代理、授权链接生成、授权结果、名称与备注；分组、并发和权重不照搬为供应商可编辑字段，遵照本轮指示改为平台分配/系统默认。
- 本地方法映射以当前创建组件及其 `show-*` 属性为准：Claude `oauth` / `setup-token` / `setup-token-manual`，OpenAI 原生 OAuth 与 Refresh Token；隐藏的 AT 和管理员其他导入路径不自动下放。
- 原型的统计数字、名称和 `.invalid` 主机均重新构造，只用于检查联动与对账。

## 7. 最新需求对初版决策的覆盖（2026-10-15）

以下来自用户后续九项要求及“仅超级管理员管理供应商”，优先于第 4/6 节的初版取舍，不反向声称参考站具有同样权限实现：

- 账号操作改为删除，保留历史计量与身份占用；不提供恢复旧授权。
- 更换账号代理或修改代理端点不能清空账号授权；未完成 OAuth 的出口更新需服务端原子保护。
- 账号授权导入/导出进入首版，复用本项目格式、安全校验及重复处理。
- 添加账号提供平台允许范围内的多选分组，其他系统参数仍使用默认。
- 代理快捷多行输入、完整账号/用量详情、重新登录/探测/同步、配额重置时间纳入原型和验收。
- 供应商登录身份及策略管理只允许 super_admin；普通 admin 的旧管理入口必须一起限制。
- 七张新截图作为页面内容和交互依据；不保存其中的真实账号、代理认证或业务金额。原型全部采用虚构数据。

## 最新用户输入：多供应商后台与结算（2026-10-15）

用户追加独立供应商子域名、后台管理众多供应商、按账号/日期等对账结算，以及供给分组可供三类用户创建的 API Key 使用。提供的两张账表截图包含微信昵称、结算邮箱、币安 ID 和分池金额/倍率/USDT 换算列；原型不复制其中个人资料，全部使用 example.invalid 与 DEMO 字段。

截图可复算 6,994.09 × 1.8 ÷ 6.7 ≈ 1,879.01；2,036.31 × 1.6 ÷ 6.7 ≈ 486.28，逐笔两位取整合计 2,365.29。截图未充分定义倍率和金额单位，方案暂用 CNY/消耗USD 合同系数及 CNY/USDT 换算价演示，正式启用前核定单位；不将 6.7 当成实时汇率。club/coding/F2 不硬编码到原生平台列表，按本地实际服务分组对账。

本轮继续核对本地 APIKeyService.canUserBindGroup 与 Create 的目标用户检查、auth store 的 localStorage token 会话，设计复用原有消费授权与认证链。新增结算流程依据用户本轮需求，不声称已在参考网站实测到相同功能；此前外站实测范围保持不变。


## 2026-10-15 代理管理截图补充

本轮依据用户两张代理管理截图及项目当前 ProxiesView.vue、api/admin/proxies.ts、admin/proxy_handler.go 的既有能力补全设计；没有在参考网站执行任何测试、删除或导入操作。

- 截图一提供四项概览、状态/地区/使用/导入日期筛选，以及创建者、范围、占用账号、测试时间等信息结构。
- 截图二提供项目原生协议/状态筛选、选择、连接/手动质量检测、导入/导出、有效期、详情与编辑/删除入口。
- 采用两者互补结构，供应商端统一为同归属私有范围，不照搬管理员/多级供应商共享层级。已有原生检测与质量服务继续复用，不将手动检测扩展成自动质量运营。
