## 1. 产品目标与默认决策

仅超级管理员（`super_admin`）为第三方创建和管理供应商登录账户与供给身份；供应商登录独立工作区，将自己持有的 Claude / OpenAI 账号加入现有号池、维护专属代理、处理授权和出口故障、查看自己贡献的用量。终端客户继续使用现有 API Key、分组、网关和计费路径。

默认方案不需要新增一种管理员角色：供应商是普通用户附加的供给身份。首版一个供应商对应一个登录用户，不预建企业多成员 RBAC。第三方无权更改价格、全局分组、优先级、并发、客户信息或其他供应商资源。

| 决策 | 首版默认 | 依据 |
| --- | --- | --- |
| 品牌归属 | 三品牌共享，UI 使用现有品牌入口 | 能力没有品牌专属商业政策 |
| 开通方式 | 仅超级管理员创建、管理；普通管理员不可授权代管 | 用户最新明确限定 |
| 平台 | Claude（内部 `anthropic`）、OpenAI | 本次明确需求 |
| 接入方式 | 两平台原生 OAuth；按平台授权的 Claude OAuth Token / setup-token、OpenAI Refresh Token | 以现有创建组件实际开放能力为准；当前 AT 输入隐藏，不因底层存在处理函数而开放 |
| 入池策略 | 超级管理员预先授权平台/分组/限额；验证成功直接入池 | 不额外增加逐号人工审批；无有效分组则禁止完成 |
| 代理 | 自有私有代理；是否可直连由超级管理员明确设置，默认不允许 | 第三方出口需要隔离与可控 |
| 调度参数 | 管理员设定，供应商只读 | 防止供给方改变服务优先级或成本 |
| 统计金额 | “账号统计消耗”，默认可看自己部分 | 复用现有账号成本口径，不等于结算金额 |
| 生命周期 | 暂停、恢复、删除；删除清除授权、保留历史统计 | 用户明确改为“删除账号”，复用原生删除生命周期 |
| 开关 | `vendor_console_enabled` 默认关闭，首批超级管理员灰度开通 | 避免升级后自动开放入口 |

API Key 型账号、自定义上游 base URL、多供应商转移、平台共享代理授权和多成员非首版。最新需求已将多供应商对账、结算单、线下付款登记、独立供应商域名和原生分组共享纳入首版；不包含自动转账、提现或外部站点账目抓取。OpenAI Excel/BPS 独立授权继续保留在原管理流程；供应商首版不自动获得该授权，不能将 Codex OAuth 当作 Excel 授权。

全局开关关闭时，供应商管理入口和供应商账号的新上游派发均停止，平台自有账号不受影响；关闭不改写逐号暂停/平台禁用状态，重新打开仍需完整资格检查。

## 2. 初始项目基线与复用位置

下列结论由本地源码核对，路径相对仓库根目录。

| 领域 | 现有依据 | 必要增量 |
| --- | --- | --- |
| 身份与权限 | `backend/internal/domain/constants.go` 有 super_admin/admin/user；`backend/internal/authz/policy.go` 管理权限目录；`jwt_auth.go` 校验实时用户/会话 | 普通用户附加 vendor 身份；增加明确的对象范围校验，不把 user 伪装成 admin |
| 生命周期授权 | `authz/lifecycle.go` 的 Lease；Claude/OpenAI OAuth 都调用 `CheckLease(..., accounts.authorize)` | 扩展为区分 admin/vendor 的有范围授权租约，防止跨用户换码/撤权后提交 |
| 管理路由 | `backend/internal/server/routes/admin.go` 注册账号、OAuth、代理等完整管理入口 | 独立 `/api/v1/vendor/*` 限权入口；不得给供应商复用全量 admin Handler |
| 账号 | `backend/ent/schema/account.go`，`service/admin_account.go`，`repository/account_repo.go` | 在原 accounts 增加供应商归属、供应商暂停；删除复用原生生命周期，复用更新与 outbox |
| 代理 | `schema/proxy.go`、`service/proxy_service.go`、`handler/admin/proxy_handler.go` | 原 proxies 增加归属；查询、绑定、备用、过期回退都验证同一供应商 |
| OAuth | `service/oauth_service.go`、`openai_oauth_service.go`、`openai_excel_oauth.go` | 复用协议/PKCE/换码；只补 scope、原子消费、服务端凭证交接和结果脱敏 |
| 用量 | `schema/usage_log.go`、`service/usage_log.go`、`repository/usage_log_repo_stats.go` | 日志写入时固化供给归属；供应商安全投影及聚合，不用消费者 user_id 过滤 |
| 调度 | `service/scheduler_snapshot_service.go` 与原生账号资格路径 | 将供应商可供给状态合入原生资格谓词和快照失效，不新建调度器 |
| 审计 | `service/audit_log_service.go`、现有管理审计中间件 | 记录供应商作用域与操作结果，复用脱敏和会话机制 |
| 前端 | `router/index.ts`、`stores/auth.ts`、`views/admin/AccountsView.vue`、`ProxiesView.vue`、账号授权组件 | 新增轻量 VendorLayout、页面与 API 适配；复用展示组件，不复制整个管理员页 |

初始调研时 accounts/proxies schema 没有供应商归属；现有 Admin RBAC 是能力授权，不是逐供应商资源隔离。仅隐藏菜单或增加一个前端 owner 筛选不足以承载此需求。OAuth 已有授权租约，不能为支持供应商跳过该校验；应在同一 authz 模块中增加范围语义。

### 3.1 账号池

- 顶栏：账号池、刷新、更多操作（授权导入/导出）、添加账号。参考 S1 的“概览 → 筛选与故障分布 → 明细表”顺序，保持紧凑，不以四张大卡片替代完整账号信息。
- 概览：自有总数、可用、冷却、异常、停用；第二行 RPM（60 秒）、TPM（含缓存）、TPM（不含缓存）、实时/最大并发、配额高负载。可收起；显示采集时间与“仅我的账号”；不随列表筛选/分页变化。
- 配额分布：5 小时、7 天、Fable 独立窗口，区分正常、接近上限、已满与未知；百分比、窗口类型和重置时间必须取原生上游数据，OpenAI 不伪装成 Claude Fable 窗口。
- 筛选：名称/ID/自身邮箱搜索、平台、状态、授权分组、授权方式、消耗排序；故障分布支持认证失败、权限拒绝、代理连接、上游故障等现有脱敏分类。全量概览、筛选结果数和分页条数分开。
- 默认表格列：名称/平台/账号类型、综合状态与供给开关、账号分组、配额窗口、并发、优先级、今日消耗、累计消耗、备注、缓存命中率、创建时间、操作。沿用本项目 `priority` 语义而不复制参考站“权重”的数值语义；列表展示分组；添加/编辑可在授权范围多选分组，并发上限、优先级只读。代理显示在名称副行及编辑/详情中。窄屏允许表格横向滚动，名称和操作保持可定位。
- 行内操作：账号详情、用量详情、编辑、更多；更多含重新登录、探测实例、同步账号信息、授权导出、暂停/恢复及删除账号。探测使用原受控测试；同步调用原资料/套餐/配额能力，不能清除平台封禁、暂停或配额冷却。删除二次确认并说明授权清除、历史保留和代理不删除。
- 错误引导：凭证过期→重新授权；代理连接失败→代理管理；限流→等待预计恢复；平台禁用→联系管理员。401/403 原文先分类脱敏；不得一键忽略安全封禁。
- 状态同时区分“供应商暂停”“平台禁用”“配额冷却”“凭证异常”“代理异常”“已删除（仅历史）”。展示主原因优先级，详情保留所有阻断原因。

### 3.2 添加账号：完整单页弹窗

按用户本轮反馈，取消只有说明文字的四步演示。单页顺序为“平台 → 名称/备注 → 代理 → 分组多选 → 授权方式及对应输入 → 完成”，底部操作固定可达。名称和备注直接可见，不埋在高级设置。

| 供应商字段 | 对应现有能力 | 展示和提交规则 |
| --- | --- | --- |
| 平台 | `CreateAccountModal.vue` 的 `form.platform` | 仅管理员允许的 Claude / OpenAI；重授权固定平台 |
| 账号名称 | `form.name` | 必填，去首尾空格；不使用邮箱作为唯一身份 |
| 备注 | `form.notes` 的输入形态 | 可选，供应商端写 `vendor_notes`；平台内部 notes 不回传 |
| 专属代理 | `ProxySelector`、`form.proxy_id` | 自有代理下拉与内联新增；不展示平台/其他供应商代理或原始认证 URL；直连仅策略允许时出现 |
| Claude 授权方式 | `addMethod` 的 `oauth` / `setup-token` / `setup-token-manual` | 分别为 OAuth 授权、OAuth Token 授权、手动 setup-token；仅返回管理员开放的方式，前两种需要生成链接与回填授权码 |
| OpenAI 授权方式 | `OAuthAuthorizationFlow` 的 `manual` / `refresh_token` | OAuth 授权或 Refresh Token；当前创建页 `show-access-token-option=false`，首版不开放 AT；其他导入分支不因管理员可用而自动开放 |
| 授权链接 | `useAccountOAuth` / `useOpenAIOAuth.generateAuthUrl` | 生成、只读显示、复制、新窗口打开、重新生成；服务端持有 session/state/PKCE，链接本身不作为已授权凭证 |
| 授权结果 | 原组件授权码解析与换码能力 | Claude 支持其原生授权码（含 `code#state`）；OpenAI 接受带 code/state 的完整回调或原生支持的码格式，state 必须绑定会话；正式实现复用/抽取解析，不另造协议 |
| Token 输入 | `handleAnthropicSetupToken` / `handleOpenAIValidateRT` | 只在对应方式出现；单账号写入，普通表单不回显；专门的自有授权导出流程可导出；取消/完成/方式切换后清空临时输入 |

### Claude 三种授权共用业务契约（2026-10-22）

管理后台与运营角色使用同一账号页；供应商及管理端代运营供应商使用同一供应商表单。角色入口保留各自的账号、分组、代理和策略权限，授权协议、令牌归一化、身份/凭据声明复用现有 OAuthService 与供应商共用核验逻辑。

- **Auth**：完整 OAuth scope，生成链接、PKCE/state、换码，保留上游给出的刷新令牌和到期时间。身份来自服务端换码响应；必要时可调用 profile。
- **OAuth token**：浏览器 inference-only scope，同样执行换码；保留真实返回的到期参数。不能因缺少 user:profile 拒绝保存。
- **Setup Token**：直接导入 `claude setup-token` 输出，接受原始 Token 或 export 赋值。与原生导入契约一致，仅校验输入格式；连通性通过现有账号测试确认，不额外发起计费推理。不调用 profile、不换码、不续期、不沿用旧刷新令牌/到期时间或旧身份字段。

服务端换码后的身份通过现有 Redis 保存一个绑定 Token 摘要、操作者和会话的短期交接记录（沿用 OAuth SessionTTL）；不接受浏览器提交的 UUID 作为身份凭证，不保存原始 Token 到该记录。供应商换码与保存发生在同一服务流程内，可直接使用上游身份。

**身份能力边界**：只有上游实际返回/验证的 account/org 才建立账号身份声明。手动长期令牌没有这些资料，使用独立 `credential:` 命名空间防止同一令牌重复入池或被其他所有者领取；不会把令牌摘要标记成上游账号身份，也无法判断两个不同的长期令牌是否来自同一个上游账号。这替代了此前对所有 Claude Token 强制 profile 的不兼容准入。新旧令牌声明均保留所有者；重新授权只修改已经获授权的目标账号；已知上游身份之间仍不得静默更换。数据库复用已有声明表，无迁移。

切换授权方式必须清空旧链接、授权码和临时 Token；晚到的生成链接响应不得回填到新方式。重新授权采用新凭据字段的独立快照，避免合并旧配置时把旧刷新材料补回。

**分组是供应商可编辑白名单字段。** 复用现有 GroupSelector 多选交互，仅返回当前供应商、当前平台允许的有效分组；默认预选当前平台第一个有效授权组，至少选一个。添加、编辑、导入和 OAuth 完成统一校验 group_ids，重复项去重；授权撤销后旧表单提交返回冲突并重新加载。禁止提交其他供应商/平台分组或自行建组。

**其余系统参数不下放。** 并发、优先级、倍率、价格、RPM、路由、模型映射及到期策略由超级管理员策略叠加系统默认，在服务端统一解析。供应商表单只包含名称、备注、平台/允许方式、分组、代理与必要授权材料，不能靠 disabled 输入做权限控制。

内联和独立新增代理均有“标准添加 / 快捷添加”选项卡。标准方式填写名称、协议、主机、端口及可选认证信息，先作为自己的代理保存并选中；取消账号不会删除已保存代理。首次没有代理时直接展示新增入口。默认不提供“自动分配”或平台代理选项；需要自动分配时也只能在管理员明确定义的同归属策略内处理。

授权流程：生成链接 → 打开上游授权 → 回填结果 → 完成登录。只切换平台/授权方式或明确重新生成链接才清空临时授权。更换代理、修改代理端点/认证、修改名称/备注/分组均不清除已保存账号凭证，也不自动重新登录。

未完成 OAuth 会话的出口变更通过受控重绑定更新 proxy_id/version，保留 state/PKCE/回填结果；在领取换码前原子核验归属与新出口。换码已经领取后禁止并发替换出口，返回冲突，可重试而不擦除原账号有效凭证。原授权只在新凭证验证并成功提交后被替换，失败保留旧授权。

同号重新登录固定目标 ID 与平台，保留供应商暂停、平台禁用和历史。已删除账号没有“恢复”按钮；本供应商再次提供同身份授权时按显式新增处理，旧用量仍关联原记录，身份 claim 在同归属事务内重新指向新账号；跨供应商不能借删除抢占身份。

原型仅用 .invalid 链接和 DEMO 材料展示，不执行真实授权。

#### 账号授权导入 / 导出（首版）

- 复用原 `AccountsView.vue` 的导出选择/确认及敏感操作二次验证，复用 `ImportDataModal.vue` 的逐文件 type/version 校验；正式格式沿用 `sub2api-data/sub2api-bundle` 版本 1。只适配供应商安全字段，不另造生产凭证格式。原型另用明确的 `sub2api-vendor-demo` 标记以拒收真实文件，不能直接作为生产导入包。
- 导出只允许本人账号或明确选择集合，不包括平台代理密码、下游身份、管理备注及路由策略；跳过影子账号和无凭证/已删除记录并报告数量。确认敏感性后绑定本次操作者、范围与操作进行 step-up，服务端 no-store，短期结果不能跨会话读取；审计只记录 ID/数量/结果。现有 admin-only step-up 需在同一机制加入有范围 vendor 操作，不能冒用 admin 权限或绕过验证。
- 导入支持文件/粘贴 → 解析预览 → 分组/自有代理映射 → 逐行创建或显式更新。禁止信任文件 owner/vendor_id/role、原资源 ID、优先级/倍率等保留字段；原格式中的系统配置不应用，预览明确提示采用当前策略默认值。未知版本、超长材料与未经核验的身份拒绝。
- 重复默认跳过；只有本人同身份可显式更新原授权，保持 ID、暂停、平台禁用、历史。跨归属一律拒绝，不能从错误信息探知归属；单批重复与并发限额由原身份占用/幂等规则统一处理。失败行不影响成功行，不自动删除已有资源。
- 新导入账号按策略默认暂停，核验通过后供应商可启用。代理不匹配必须选择本人代理；若当前策略允许直连，须在导入预览明确选择直连。文件中 proxy=null 不构成直连授权，不可静默直连；预览逐行显示最终出口。凭证预览只显示类型和校验结果；输入在关闭/完成后清空；关闭旧弹窗的延迟事件不能清空随后新开的表单。

### 3.3 代理管理（供应商与超级管理员共用工作台）

本轮按用户两张代理管理截图补全信息与操作，复用项目原生 ProxiesView 的连接测试、手动质量检测、导入导出、到期和引用检查能力，不恢复自动质量运营，不创建代理调度器或批处理任务平台。供应商只能看到本人资源；超级管理员通过“供应商平台 → 供应商代理”查看全部合作方或指定一家。普通管理员无此入口，也不得通过旧接口绕过。

#### 列表、概览与范围

- 顶部四项：**总代理数、已占用、占用中异常/不可用、未占用**。按当前身份与供应商归属范围统计，不受表格搜索或分页影响。已占用只计算仍绑定的活跃账号；占用中不可用包括异常、停用、过期。未占用不等于无引用或可删除。
- 筛选：名称/ID/主机/IP 搜索、协议、状态、国家/地区、已占用/未占用、导入/创建日期；后台额外选择供应商。日期含首尾日，查询转换为实例时区的半开区间。未知地区独立筛选，日期倒置给出错误，不改变已应用条件。
- 表格：选择、ID/名称、协议、脱敏地址/认证状态、国家/城市及来源、创建者/归属范围、占用数/账号 ID、延迟/质量、有效期、导入/创建时间、状态/最近测试、操作。点击占用数打开账号/备用/OAuth 引用详情。占用不是并发上限，不凭空显示 1/1 容量。
- 支持名称、协议、占用数、延迟、有效期、创建时间排序；未知延迟置后。10/20/50 条分页，空集有明确反馈。宽表在内容区横向滚动，操作列不得遮挡其他可点击内容。
- 当前页全选可累积跨页选择；改变筛选或供应商范围会清空选择，防止误操作隐藏对象。批量操作首先显示范围：有勾选采用已选集合；无勾选时测试/导出采用当前筛选全部结果，不只处理当前页；批量删除必须显式勾选。刷新列表不触发检测。
- 供应商专属代理只允许同供应商内复用，不提供共享等级编辑。平台自有 vendor_id=NULL 代理不默认开放，跨供应商共享仍属于后续显式授权需求。

#### 添加、编辑和认证保留

- 标准添加：名称、服务器支持的协议、host、port、可选认证、国家/城市标签、到期时间、备注、启用开关。沿用现有解析器处理 IPv6、转义密码和分隔符。原型仅允许 .invalid 与 DEMO_ 材料，实际格式不受此演示限制。
- 密码写入后只返回 has_password；表单空白不等于清除。认证控件明确“保留 / 更新 / 清除”，未传保留，清除须显式提交；列表、复制、预览、错误和审计不回显用户名密码。复制的是不含认证的端点。
- 所有新增归属由当前供应商会话决定；超级管理员新增必须选择供应商，编辑时不可转移归属。创建者和归属分别记录，不把超级管理员创建的资源误标为供应商上传。
- 快捷添加与账号内联添加支持多行 HTTP/HTTPS/SOCKS5 URL；使用已有解析器及同归属去重规则。原型限制100行/32 KB；正式上限复用现有限额并通过能力响应返回。输入后显示有效数量、重复/非法行和“导入 N 个代理”，明确提交后逐行结果；只新增，不覆盖重复端点，失败不删除资源。
- 内联新增代理必须启用且未过期；导入多个时明确选用首个有效代理。取消账号不回滚已保存的代理。新绑定以及授权完成前再次核验出口，不能静默直连；账号原有被停用出口仍可展示并提示修复，不能悄悄换绑。
- 编辑先展示受影响账号。修改端点/代理认证只更新出口，**保留账号 Token、逐号暂停、平台禁用、分组与历史用量**。事务检查对象版本，旧连接池失效，新请求用新出口，在途请求用固定快照完成；网络失败不回退到未授权直连。仅名称/备注/地区变更不抹去检测快照；端点或认证改变将检测标为待重测。
- 到期/停用独立于健康状态：列表优先展示停用、过期，再展示异常/未测试/可用；可在详情查看历史测试。到期按带时区的 expires_at 判断，不依赖浏览器时钟。保留原生 fallback_mode/backup_proxy_id，默认 none，备用必须同归属；供应商表单不下放平台回退策略。sweep、revert、OAuth、刷新和运行时出口解析统一校验范围。

#### 手动连接测试和质量检测

- 单条/批量连接测试与质量检测分别提供入口；质量报告显示评级、各固定目标可达性、延迟与采集时间，明确是快照。质量评分复用项目原生算法，不引入供应商自己的评级规则；原型 A/C/D 均为虚构样例。
- 复用现有 test/quality-check 服务与固定目标，不接收任意测试 URL。服务端在连接和重定向阶段执行原生安全检查及供应商出口约束，同一供应商限流、限制并发与超时。列表不逐行访问上游；测试不自动启用、换代理或清除账号阻断。
- 前端有界队列逐项调用同一服务，显示等待/检测中/成功/失败/跳过/取消，异常对象不影响其余项；停用、过期或权限变化项跳过。取消停止后续请求，已完成结果保留，在途结果按版本核验后决定是否应用；原型取消后未完成项不应用任何结果。端点变更后的旧结果不可覆盖新配置。
- 原型明确“不访问网络”，不把演示延迟/地区/目标可达性写成真实检测结果。正式质量请求可能产生网络流量，提交前明确范围；不新增定时质量运营、自动更换出口或自动登录服务。

#### 删除、文件导入与清单导出

- 删除前列出账号绑定、备用代理、未完成 OAuth 会话和在途租约引用；存在引用则保留并解释原因。批量只删除无引用项，返回逐项成功/引用冲突/权限失效；提交时在事务内再次检查并与新绑定互斥，不能只相信 UI 预检查。正式执行软删除，不允许强删并自动解绑，不清理历史统计或结算证据。
- 文件导入沿用现有原生 type/version 与代理解析能力，预览和提交复用既有供应商 import 两个入口。原型仅接受 sub2api-vendor-proxy-demo v1，100 KB/100条，不能接收真实原生凭证文件。统一协议/主机大小写后在同归属去重，校验真实日历日期、端口、长度、协议；未知保留字段不落库，文件中的 owner/vendor_id/ID/状态/检测报告不能覆盖当前策略或旧记录。
- 导出 **CSV 脱敏清单 / 可回导 JSON 清单**。下载时再校验范围，返回全部已选/筛选对象，均不带代理认证或账号凭证。CSV 为 UTF-8 BOM、固定列、标准转义及公式注入保护；JSON 白名单仅包含名称/协议/host/port/国家/城市/有效期/备注，不含他人归属或内部网络错误。此次清单导出不增加代理密码备份功能；账号授权导出仍走既有独立的显式敏感流程。
- 清单回导只恢复资料，认证需重新填写，初始未测试；不凭文件把已有代理变成可用。部分成功显示逐行结果与“完成”，关闭不回滚成功项。输入修改后必须重新预览；关闭后文件异步读取不得写进另一个表单。
- 审计记录操作者、供应商、对象 ID、操作、范围数量及逐项结果，不记录输入原文、认证或授权 Token；超级管理员审计页区分供应商本人和平台操作者。

### 3.4 用量统计

页面布局直接参考 S1：标题及说明 → 筛选卡片 → 一行四列汇总 → 按日趋势表 → 按账号明细表。首屏默认近 7 天、全部自有账号；账号下拉含已删除账号的历史记录，历史用量详情明确标记“已删除账号 · 历史记录”，不展示恢复授权或编辑入口。平台可作附加筛选，模型扩展不挤占首屏。

- 时间范围：今天、昨天、近 7 天、近 30 天、本月、上月；双月日历选择起止日期，提供清空、取消、确定。日历修改为草稿，确定才联动全部汇总/表格；快捷项明确应用范围。清空恢复默认近 7 天。
- 四列汇总：消耗总额（USD）、总请求数、Token 消耗（输入+输出，下列分别展示）、缓存（写+读，下列分别展示）。不能把缓存再加进普通 Token 消耗；不把统计消耗称为分成/收入。
- 按日趋势使用表格，不以空图表替代：日期、请求数、Token 输入/输出、缓存写/读、消耗，日期升序；独立分页与条数选择。
- 按账号明细：账号、当前状态、请求数、Token 输入/输出、缓存写/读、缓存命中率、消耗；按区间消耗降序，独立分页。当前账号状态不代表每条历史请求的当时状态。
- 筛选变动同时更新四项汇总和两张表，重置两个页码；翻页只影响所属表，不改变汇总。日表汇总、账号表汇总、顶部汇总在同一快照/时区/范围下必须对账。配额窗口不与消费统计混用。

原型中的输入字段已定义为非缓存输入；演示缓存命中率为 `read / (input + write + read)`，分母为零显示“—”。正式实现须先复用项目现有平台用量规范化路径，确认 DTO 是否已经扣除缓存，避免重复扣减或将 OpenAI 原始输入与 Claude 非缓存输入直接相加。派生指标集中在统计服务，浏览器不另行实现平台修正规则。

金额标题必须带 USD 与“统计消耗，非应结算金额”。日期展示用用户/实例时区，API 明确 `timezone`；查询区间统一 `[start, end)`，不能依赖浏览器本地隐式时区。零请求显示 0，未采集/读取失败显示未知与更新时间，不伪造为 0 或 100% 可用。

首版不给供应商开放客户端 IP、下游用户/API Key、请求内容、原始错误包、内部利润或用户实际扣费。按模型明细使用现有模型映射后的明确口径，保留 requested/upstream 区别但不暴露内部路由链。

### 3.5 超级管理员供应商平台

**只有实时身份为 super_admin 的操作者可创建、查看列表、配置、启停或管理供应商登录账户。** 普通 admin 即使拥有 users.manage/accounts.manage/proxies.manage 或历史 vendors 权限也无权代管，不把该能力放入可委派权限目录。供应商只管理自己供给的上游账号，不管理供应商登录身份或合作策略。

后台沿用现有布局，新增“供应商平台”入口与七个页签，供应商管理支持服务端搜索、状态筛选和分页，其他模块提供一致的供应商范围筛选：

| 页面 | 主要内容 | 交互与权限 |
| --- | --- | --- |
| 供应商管理 | 名称、登录账号、状态、平台/分组、资源数/上限、策略版本、联系人、结算邮箱、脱敏币安 ID | 搜索/状态筛选/分页；创建、详情、供给与结算配置、启停；全部 super_admin |
| 供应商账号 | 原账号列表增加供应商归属筛选；状态、分组、代理、配额 | 复用原详情/用量/资料组件；归属只读；不允许任意跨供应商转移 |
| 供应商代理 | 原代理列表增加归属、绑定影响与状态 | 复用原代理维护，修改不清账号授权；保留引用保护 |
| 供给用量 | 供应商/账号/实际计量分组/平台/请求日期筛选；五种聚合；包含删除历史 | 汇总、钻取、完整明细 CSV、生成结算草稿；消费扣费与供应商应付分开 |
| 结算对账 | 账期、分组消耗、合同系数、换算价、调整、收款快照、应付/已付/未付 | 预览、批量草稿、确认锁账、部分/全部付款登记、无付款作废、明细导出 |
| 分组供给 | 系统原生分组、多供应商/平台自有供给、账号可用性 | 展示原生 API Key 资格规则；不新增供应商专属消费门槛 |
| 操作审计 | 操作者、供应商、操作、时间、结果/变更字段 | 记录开通、策略、启停及敏感操作；不记录凭证原文 |

创建表单：选择“新建普通用户 / 关联已有普通用户” → 供应商名称与登录邮箱 → 允许平台、当前开放授权方式（只读说明）、可选分组（首个作为添加默认） → 账号/代理上限、直连策略、并发/优先级/倍率默认值 → 结算档案（联系人、邮箱、币安 ID、默认及分组计价系数）→ 确认开通。原型展示当前允许的授权方式，不开放额外管理端方法。登录账户始终为 user；现有用户安全流程负责密码设置、MFA、重置与会话撤销，不直接发送明文密码。新建用户和开通身份复用两步 API；第二步失败保留普通用户以便重试，不能重复创建或自动删除。

配置需要 version/If-Match 防止覆盖他人策略。默认参数仅影响以后新建账号；批量更新已有参数必须走明确的既有账号操作。撤销平台/分组立即约束新建和新派发，仍有合法分组的账号只在该范围可用；失去全部合法分组的账号停止新供给，授权与历史保留。

停用弹窗显示受影响账号数与后果；停用后管理会话/任务和新供给失效，在途正常完成。重新启用不解除逐号暂停、平台禁用、配额冷却或删除状态。仅停用供应商不会删除同一用户已有消费者账单。供应商登录账户的密码重置、状态修改、删除及角色调整只能由超级管理员从现有用户安全流程执行；有关联资源时优先停用并按引用规则处理，不提供连带强删。

原型包含“供应商 / 超级管理员 / 普通管理员”身份预览；这是设计评审控件，不是正式产品的角色切换或登录功能。

### 3.6 完整账号与用量详情

账号详情包括：基础资料、来源、分组、代理端点/地区、授权方式、只读并发/优先级、创建时间、请求/Token/消耗；最近 60 秒 RPM/TPM（含/不含缓存）、今日/累计成功率与分子分母；当前综合状态与所有阻断原因、账号冷却、动态配额窗口、重置时间和模型级限制。普通详情不返回原凭证。

用量详情默认全部历史，支持日期起止及快捷范围，展示七类指标：请求（成功/失败）、统计消耗、成功率、输入/输出 Token、缓存写读/命中率、平均延迟和首字时间。趋势可切请求/Token/金额，附模型分布、结果分布和分页日明细。固定 5 小时/7 天/30 天历史消耗以服务端 snapshot_at 计算，不受详情或全局筛选影响，也不冒充上游额度。参考截图的下游 API Key 分布不直接开放，以自有账号结果聚合替代，不泄露客户标识。

列表与详情的每个适用配额窗口都展示 utilization、reset_at 和采集时间；重置时间统一实例/用户时区，悬浮信息含完整时间和时区。未返回的 reset_at 显示“重置时间未知”，不能编造 Fable 或 OpenAI 的固定周期。

### 3.7 多供应商费用对账与结算

供给用量的筛选区固定放供应商、账号（含已删除）、平台、实际服务分组、日期起止和时区；查询应用后联动四项汇总、聚合表与导出。支持按供应商、账号、日期、分组、账号×日期聚合，以及超级管理员专属的逐请求使用记录。分页不改变总额，导出覆盖整个筛选集而非当前页；从供应商管理行直接进入其账号、代理、用量或结算，从报表账号进入完整历史用量详情。已停用供应商和已删除账号的历史仍参与对账。

结算台账按供应商、状态、账期搜索分页；列出单号、供应商、账期、基础消耗 USD、应付/已付/未付 USDT、状态和操作。流程为筛选用量 → 选择账期与换算价 → 预览逐供应商/分组金额 → 批量保存草稿 → 复核并锁账 → 登记站外付款 → 供应商查看自己的已确认账单。

- 结算档案：微信昵称/联系人、结算邮箱、币安 ID（字符串，不能截断前导零）、默认合同计价系数及可选分组覆盖系数。登录邮箱与结算邮箱分别保存。列表脱敏币安 ID，完整档案仅本人和超级管理员可见；供应商不能自行修改收款信息，变更由超级管理员核对后留痕。
- 使用原生分组作为计量池维度。截图中的 club/coding/F2 仅为用户原有账表示例，不硬编码为本系统平台，也不自行连接其他站点或导入其账号。
- 同一供应商不同分组可采用不同合同系数；未配置覆盖的分组使用默认值。每条用量只归属实际承载请求的一个计量分组。账号多选分组不能乘份数重复结算。
- 草稿即预留用量，避免多个管理员重复创建。预览显示可结算/已占用数量、按组消耗、系数、换算价、应付及调整原因；全部供应商模式逐家生成，不跨供应商合并收款单。前端参数变化立即废弃旧预览，保存时后端再次核验。
- 状态为草稿、待付款、部分付款、已付款、已作废。未闭合账期可以预览/存草稿，但不能确认锁账；默认结束日为昨日。已付款或部分付款单不直接作废。未付款作废必须填原因，保留快照与审计并释放预留。
- 锁账固化收款档案、账号名称、归属/分组、消耗口径、合同系数、换算价、精度、调整和数据截止点。后续修改资料、账号倍率、分组、代理或删除账号都不重算旧账单。草稿需要改变条件时作废重建，不静默更新。
- 登记付款填写金额、日期、凭据编号并确认已在线下支付；支持部分付款。禁止超额登记、重复凭据、并发双付和过期版本覆盖；付款登记不调用交易所或钱包转账。误登记通过有原因的冲正记录处理，不删除原付款。
- 已锁账后的漏记、差异或扣回用关联原单的调整单处理；需金额、依据、原单和申请人/确认人记录，并防重复调整/超额扣回。正式实现已包含付款冲正和关联调整；前期原型仅演示新草稿调整和付款登记。
- 供应商“我的结算”只显示自己的已确认账单及付款状态，可查看明细和导出；不出现平台全量台账、编辑系数、锁账或付款按钮。下载时再次检查本人范围与实时身份。停用或用户冻结后的查看政策须沿用有效登录要求，不为旧下载结果放行。

### 3.8 独立供应商子域名

正式入口使用部署配置的独立 Origin，例如 `https://supplier.example.invalid`；后台 Origin 保持原站点配置。该占位域名不是实际部署地址。门户只呈现登录、个人安全和供应商工作区，无公开注册或管理员身份切换；账户由超级管理员开通。

现有 `frontend/src/stores/auth.ts` 将 access/refresh token 放在 localStorage。首版复用该认证链、MFA、会话撤销与实时身份校验，利用 Origin 隔离浏览器存储；不把“现有 Cookie 已是 HttpOnly”写成事实。不得在 URL、跨站 postMessage 或父域 Cookie 中传递管理会话。若后续统一迁移为 Cookie，由共享认证机制实施 Host-only / Secure / HttpOnly / SameSite 与 CSRF 防护，不给供应商另造登录协议。

供应商入口的反向代理仅放行静态资源、必要认证/个人安全以及 /api/v1/vendor；禁止转发 /admin。后端仍以实时角色和 vendor scope 授权，不能信任 Origin、Host、前端菜单或不同域名本身是权限。CORS 使用精确白名单，无带凭证通配符；只信任现有配置允许的代理头。上游 OAuth 回调从服务端固定配置/允许清单产生，不接受用户提供任意 redirect_uri；复用原 OAuth 租约，不混用 Excel/BPS profile。

原型 `prototype.html?portal=vendor` 是同源页面分支，只演示登录和专属工作区；没有真实 DNS、TLS、跨域会话或生产鉴权。入口配置的演示域名仅作为界面展示值透传，各标签页数据仍各自独立。

### 3.9 分组供给与 API Key 消费

供应商加入的就是系统原生 groups。一个分组允许平台自有账号与多个供应商共同供给；供应商的 vendor_groups 限定其可加入哪些组，不能将该授权误当作 API Key 消费授权。

超级管理员、管理员和普通用户创建的 API Key 都可以绑定其所属用户已有资格的分组。`APIKeyService.canUserBindGroup` 已对订阅组检查有效订阅，对其他组调用 user.CanBindGroup；创建服务核对的是 Key 所属用户。继续复用这条规则，管理员代建 Key 也不能凭创建者角色替目标用户越权。供应商身份不授予额外消费权，消费用户也不需拥有 vendor_id。

请求路径仍为 Key 鉴权 → 原生分组资格 → 原生调度与供给状态检查 → 原网关计费 → 请求归属/分组快照。供应商停用只使其供给不可选，不删除共享分组或其他供应商供给；组内无可用账号沿用原网关错误。普通管理员可以按既有权限管理消费者 Key，但不能借组成员查询/批量解绑等入口枚举或变更供应商资源。

## 4. 权限矩阵与单一规则来源

| 操作 | 供应商 user + vendor | 普通管理员 admin | 超级管理员 super_admin |
| --- | --- | --- | --- |
| 创建/管理供应商登录身份及策略 | 禁止 | 禁止，不可委派 | 允许，实时身份校验 |
| 自有上游账号、分组选择、代理维护 | 自己的授权范围 | 不能从管理入口管理供应商资源 | 允许并遵守归属/引用保护 |
| 账号详情与用量 | 自己及自己的历史 | 不能枚举供应商资源/管理统计 | 允许，复用原统计 |
| 账号重新登录、探测、同步、暂停/删除 | 自己的账号；不能解除平台限制 | 禁止管理供应商资源 | 原安全流程内执行 |
| 授权导入/导出 | 本人资源 + 显式确认/step-up | 禁止 | 原敏感机制 |
| 优先级/并发/倍率/路由/授权组范围 | 不可覆盖平台策略 | 不可借原管理 API 覆盖供应商策略 | 集中维护 |
| 结算档案、合同、锁账、付款登记 | 本人已确认账单只读；档案变更联系平台 | 禁止 | 允许，复核与审计 |
| 创建 API Key 使用供给分组 | 按 Key 所属用户原有资格 | 同左，不等于供应商管理权 | 同左，代建不越权 |
| 跨供应商转移、强制抢占身份 | 首版禁止 | 禁止 | 首版无任意转移入口 |

后端复用 `authz/routes.go` 的 `RouteRule.SuperOnly`（已核对现有实现），所有 /admin/vendors 注册均标记 SuperOnly，并在服务层检查实时 actor.role；不新增可委派 vendors.read/manage。前端路由与菜单使用现有 isSuperAdmin；前端隐藏不是权限证明。

**旧入口防旁路：** 对原 /admin/users、accounts、proxies 的详情、更新/删除、复制、授权、导入导出、批量操作和关联查询补对象级判断；目标属于供应商时普通 admin 拒绝，列表/count/export 在 SQL 层排除这些对象。供应商登录用户的密码/会话/角色变更也执行同一规则。分组变更若会改变供应商授权范围，须超级管理员处理，不因普通 admin 有 groups.manage 即放行。异步任务执行/下载再次校验角色和作用域；角色被降级后旧 JWT、导出结果和缓存不能继续放行。原平台自有资源的已授权管理能力不改变。

供应商 Handler 从可信会话取得 vendor_id，禁止客户端 owner/vendor_id/role 原样覆盖；通用资料接口不接收整包 credentials，仅专门的导入和授权流程处理经验证的字段。所有查询、count、聚合、导出及关联对象都在仓储层 scoped；非本人 ID 与不存在 ID 统一 404。

独立 VendorMiddleware/Handler 是必要的限权入口与 DTO 投影，不是第二套 CRUD 或调度器；内部应用方法复用原逻辑并显式传 scope，不通过内部 HTTP 调 admin API、不移除 lease/context 绕过 authz。

## 5. 关键流程与状态

```mermaid
flowchart LR
  A[超级管理员创建供应商与供给策略] --> B[已有用户登录与会话校验]
  B --> C[选择自己的出口代理]
  C --> D[原生 Claude / OpenAI OAuth]
  D --> E[验证身份与作用域，检查重复和限额]
  E --> F[原 accounts / proxies 与调度 outbox]
  F --> G[原生账号资格检查与调度]
  G --> H[原 HTTP / SSE / WebSocket 转发]
  H --> I[原用量记录加归属快照]
  I --> J[供应商安全统计投影]
```

实际可调度 = 原有账号/分组/模型资格成立 AND 供应商有效 AND 未被供应商暂停 AND 未删除 AND 出口符合其政策。撤销直连政策后，已有直连账号停止新供给而不清空凭证；重新绑定已授权代理后重新判定资格。供应商维度是同一资格检查的附加输入，不增加独立配额、排队、票据或准入系统。

- **新增/重授权**：同一事务复核政策版本、数量上限、分组、代理归属和账号身份；与原 outbox 一起提交。归属字段不可由通用管理导入/复制/批量修改绕过。
- **暂停/停用**：事务写状态并失效原调度快照；sticky、强制指定账号、WS 绑定账号和重试都在下一次上游派发前复核。停止接受新派发，不中止已经发出的响应流。明确记录跨实例传播目标和测量结果，不能仅凭列表变红认为停用已生效。
- **恢复**：只撤销相应暂停原因，不能覆盖其他阻断状态。授权成功也不能把 disabled 账号变回 active。
- **删除**：复用原生 deleted_at 生命周期，停止新供给，取消未完成授权并在安全处理在途后清除 token；账号不再出现在活跃池。保留供给身份指纹、历史归属和审计，不释放给其他供应商抢占。历史查询不依赖活跃 accounts join；必要的名称/平台/账号 ID 从最小墓碑或事件快照读取。
- **数量限额**：锁供应商或原子预留再检查创建；已删除根账号不占活跃容量，影子账号不重复计数。历史/身份指纹有单独保留策略，不无限复制整包凭证。
- **登录与供给**：用户停用使登录失效且供给不可调度；仅供应商停用不影响同一用户已有消费者历史，但取消其供给能力。正常刷新 token、浏览列表都必须再次检查有效状态。

## 6. 数据模型与身份去重

不建立 vendor_accounts/vendor_proxies 影子资源库，不复制已有 usage_logs。拟增加 7 张表（3 张供给身份表、4 张不可变结算及占用表），并扩展原实体；最终 SQL 编号在实施时取最新迁移序号，不预占、不改历史迁移。

账号身份仅取自受验证的 provider 身份响应/可信验证流程。Claude 使用本地原生返回的账号与组织标识；OpenAI 使用本地原生返回的账户/工作区身份及必要的用户标识。实施时逐平台确认稳定组合，不把仅解码、未验真的 JWT 或邮箱字符串当证明。无法取得可信标识时不自动合并、不开放跨归属覆盖。

identity_hash 是规范化稳定标识的服务端带密钥指纹，不能用可枚举邮箱或轮换 refresh token 作为主键。指纹唯一约束按根供给账号处理；现有合法影子账号关联 canonical account，不另占一个供给身份，也不得跨供应商派生。

同供应商同身份：未删除账号显式重授权/导入更新原 ID；已删除账号须重新核验后新建并保留旧历史；跨供应商或平台自有：返回统一“该资源已被绑定，请联系管理员”，不透露归属和邮箱。参考站允许重领他人归档账号的规则不采用。首版不转移所有权。

迁移之前的平台账号没有 claim 时，首次供应商接入必须在受控事务/身份锁内检查已有可信身份；管理员导入、复制、OAuth 新建及供应商入口都经过同一占用规则。历史重复先输出冲突清单供管理员处理，不批量删除或强行施加会破坏影子账号的全表唯一索引。尚未核实的 legacy 身份不能自动转给供应商。

索引：accounts/vendor_id + deleted_at/status + id、proxies/vendor_id + status + id、usage_logs/vendor_id_snapshot + created_at + id；模型/账号维度索引以 EXPLAIN 和实测决定，不预建大量索引。usage_logs 中 NULL 历史不自动回填给当前 owner；界面显示“供给统计自开通/明确授权接入时开始”。

## 7. OAuth、凭证和出口安全契约

1. 原生 OAuth 服务负责协议、PKCE、state 和 token 刷新；供应商范围与原 lease 一起检查。Lease 同时绑定用户、会话、vendor、policy_version、操作类型和目标账号。管理员路径保持原 accounts.authorize 检查。
2. 换码使用会话保存的 provider/client_id/redirect_uri/代理；供应商不得覆盖 profile、redirect_uri 或任意上游 URL；proxy_id 只能通过作用域验证后的会话重绑定更新。明确拒绝 Excel/BPS profile 混用。
3. 会话原子领取/消费，不能用 Get→远端换码→Delete 充当并发防重。沿用原 session store 抽象补足原子行为；多实例要有可验证的共享或粘性方案及失败语义，不承诺进程内 map 能跨实例。
4. 完成接口在服务器持有 token 并直接创建/更新账号，只返回安全 DTO；不能先向浏览器返回原 token 再要求浏览器回传入库。重复完成通过现有幂等机制返回原结果，不重复换码。
5. 开始授权、换码前、持久化前都复核 scope。暂停供应商、撤销分组、删除代理、登录会话撤销后，旧会话不得继续写入。代理替换不清除旧凭证，领取换码前可原子重绑定当前获授权出口；已领取时返回并发冲突。远端换码成功但 DB 提交失败，应显示明确重试/重新授权状态，禁止静默创建新账号。
6. 代理来源是新暴露给第三方的出站输入。校验协议、端口、解析结果；阻止 loopback、私网/链路本地、元数据地址、IPv6 等价地址和 DNS 重绑定；校验实际 dial 目的地址而不仅是输入字符串。已有管理员内网代理策略不能被供应商借用。
7. 测试/OAuth/刷新/用量采集均绑定同一个代理范围，禁止校验后替换代理的竞态。代理不可用时失败关闭，不能未经授权回退直连。用户在自己浏览器打开上游授权页的浏览器出口不由服务器代理保证，界面需说明。
8. 展示 DTO 使用字段白名单，不直接序列化 credentials/extra/内部 notes。审计只记字段名称与状态，不记 token、密码、完整回调 URL、code/state 或包含 userinfo 的代理 URL。
9. 持久化继续使用已有账号/代理安全存储链；当前 schema 的 JSONB/String 本身不是加密证明。上线前核实存储、备份、日志与管理员敏感导出的保护；若需补强，落到共享凭证机制，不能仅给 vendor 另造一套密钥系统。
10. 供应商首版的校验/刷新只走已有授权、身份、配额元数据能力；若某导入类型必须进行真实模型请求，必须沿用现有受控测试和计费语义，明确成本归属后才开放该类型，不能静默消耗下游用户余额。

## 8. 用量、成本与隐私

当前账号统计口径已在 `usage_log_repo_stats.go` / `usage_log_repo_trend.go` 使用：

```sql
SUM(COALESCE(account_stats_cost, total_cost)
    * COALESCE(account_rate_multiplier, 1))
```

新页面必须复用上述口径及其历史快照规则，不能直接取 actual_cost 冒充账号成本，也不能按今日单价重算历史。actual_cost 是另一种既有账务口径，供应商默认不获得消费者扣费。这里展示的是统计消耗，不声称订阅实付采购成本、利润、收益或应付金额。

- vendor_id_snapshot 在选定实际承载上游请求的账号时取得，并传入最终计量事件；不能在异步落库时再查当前归属。多次尝试、跨账号重试和 WS 恢复遵守现有成功/失败计量与幂等规则，不新增二次计费。
- 请求数、token、缓存和金额均从同一 scoped 数据集聚合。输入 token 是否已包含缓存依照现有平台规范化逻辑；不要再用一个统一相加公式造成 OpenAI/Claude 重复统计。
- 不新建可充值余额或自动支付渠道；供应商应付只由已确认合同规则和结算快照产生，统计页金额不是应付。账单、占用与线下付款登记是本次明确新增能力。
- Fable 与其他配额窗口继承现有能力描述及独立阈值，不静态写死模型名；OpenAI 展示其真实返回的窗口，不硬套 Claude 5h/7d。未知额度只展示未知。
- 首版统计主页有界查询：默认 7 天、最大 31 天、最大 100 行/页、按日聚合；逐账号详情的全部历史使用服务端汇总/索引与有界分页，趋势按跨度降采样，不把全部原始记录拉到浏览器；这些是设计初始上限，实施压测后可调整。缓存键含供应商、权限版本、时间区间/时区和过滤条件，禁止共享全平台结果再在浏览器过滤。
- 秒级并发等实时数据与账务统计分开，返回 collected_at、数据来源、stale/unknown 状态。上游探测不跟随每次分页触发。
- 首版提供有界同步明细 CSV；超过上限明确提示缩小区间，不截断冒充完整报表。大范围异步任务后续接入现有基础设施，创建、执行和下载均复核身份/范围；CSV 防公式注入，包含时区/口径/过滤范围，不导出下游身份或授权材料。

### 8.1 结算金额与精度契约

截图可验算：6,994.09 × 1.8 ÷ 6.7 = 1,879.01；2,036.31 × 1.6 ÷ 6.7 = 486.28；按两笔分别取两位小数后合计 2,365.29 USDT。截图没有充分说明美元标记与倍率的合同单位，因此原型**暂定**“账号统计消耗 USD × 合同系数 CNY/消耗 USD ÷ 换算价 CNY/USDT”。正式启用前必须确认合同单位；不能将 6.7 当成实时汇率或把倍率随意称为无量纲倍数。

账号统计消耗必须先按本节原 SQL 的历史 account_rate_multiplier 计算；contract coefficient 是另一字段，不能重复乘账号统计倍率。默认系数仅给后续草稿提供建议，实际单据按账期合同核定；分组覆盖优先默认。政策修改不会追溯重算已有草稿/锁账单。跨合同生效版本的账期按版本拆行或拆单，不能把今日系数默认为整个历史期的约定。

采用定点 Decimal / PostgreSQL NUMERIC；成本沿用现有精度，系数与换算价保留至少 6 位小数。原型成本以 1/10000 USD 整数表示，BigInt 做比例运算。每个“供应商×实际分组×合同版本”的行金额以 HALF_UP 保留 2 位 USDT，再求和加单独的两位调整；UI、预览、导出、锁账和付款共用这一规则。应付与累计已付的非负、上限、精度及数值溢出必须在后端校验。

CSV 分为用量明细、分组结算、本单合计三类行，各数值放对应独立列；本单应付/已付只出现在专用合计行，避免下游求和重复。每次导出包含账号/分组/日期快照、计价单位、数据时点和单号；不得回查账号现名而覆盖账单快照。

### 8.2 锁账、晚到数据和一致性

UI 日期包含首尾两日，查询转换为 Asia/Shanghai 的 [开始日 00:00, 结束日次日 00:00)，落库按 UTC。同一筛选的汇总与各维度使用同一个 cutoff/watermark；明细时区和数据新鲜度明确返回。今日未闭合禁止锁账，不承诺“昨天”必然已无晚到用量。

预览生成有限有效期的输入/策略/数据版本，保存草稿在事务中锁定供应商并预留记录；数据库对 active usage_log_id 做唯一约束，重试使用幂等键。同一用量在不同账号/日期/分组视图进入账单也不能重复占用。批量创建返回逐供应商结果；每家单独事务，部分失败可安全重试。

确认采用版本 CAS，重新校验操作者、归属、账期、合同与占用数量。锁账后金额/来源/收款档案不变。晚到用量保持原请求日期和原归属，列入“未结算”与差异提示，通过补充单/关联调整处理，不重新纳入已占用记录。用量重试依原幂等键消重。已结算源记录的最小审计快照与占用索引保留到结算保留期，清理 usage_logs 不能级联删除账单证据；具体保留期由部署政策定义。

付款登记与单据余额校验在同一事务加行锁，凭据编号/幂等键按支付渠道或全局规范化唯一；付款冲正追加反向记录并重新计算状态，不覆盖原记录。降权、停用、并发修改、重复锁账、超额付款及撤销中的下载均须服务端复核。普通管理员的旧统计/导出接口也不能泄露供应商收款或账单信息。

身份基线核验为超级管理员专用的有界手动操作，每批最多 25 个账号。迁移前根账号需从已认证上游元数据建立可信身份占用；已删除且没有可信历史证据的旧账号不会按邮箱或未验签 JWT 自动放行。核验不轮换 Token、不恢复账号、不转移归属。无法证明的旧数据须提供真实历史依据或另行确定处理政策，界面显示失败原因。

批量检测通过前端有界队列调用同一个单条原生检测入口，不新增任务表/轮询服务。结算调整和付款冲正已接入正式接口与页面；付款仅登记线下结果，没有自动转账执行路径。

独立域名设置复用现有设置管理框架的 SuperOnly 配置，不另建公开配置 API；新增配置值为 vendor_console_enabled 和 vendor_portal_origin，管理员 Origin 复用原站点地址。新建登录用户仍复用原用户 API，无公开供应商注册或第二套登录接口。

操作失败统一语义：401 未登录/会话失效；403 身份停用或不允许的能力；404 不存在/非本人资源；409 重复/引用/政策版本冲突；422 输入或上游核验失败；429 探测/刷新/批量操作限速。任何错误不带他人资源、原始凭证或内部网络细节。

## 10. 性能、迁移与发布

2026-10-16 查询优化复用现有用量服务与索引：报表使用 `GROUPING SETS` 一次扫描产生汇总及维度记录，聚合后再分页、关联当前名称/状态；统计数据 SQL 从三次减少为一次（不包含鉴权和水位查询）。5h/7d/30d/最近 60 秒窗口以过滤聚合一次完成。请求明细采用一次总计加一次有界分页查询，避免把全历史请求物化为分组。排序字段与方向仅接受服务端白名单。

供应商首页以趋势响应复用汇总，随后共享快照查询账号表，由三次报表 HTTP 请求减为两次；历史账号目录不再随页面初始化查询。本轮未新增接口、配置或数据库迁移。隔离 PostgreSQL 的 50,000 行样本中匹配 40,000 行，原三个查询累计处理 120,000 条匹配记录，合并查询处理 40,000 条；该证据不能替代生产规模容量测试。

- 首版服务端分页，静态资料和高频指标分开请求；批量请求按供应商限流，列表不逐行调用上游。复用现有 PanelRateLimiter，不新建通用任务平台。
- 设计验收目标：代表性数据规模下列表 p95 ≤ 1 秒、31 天统计 p95 ≤ 3 秒；统计刷新默认 60 秒且后台标签页暂停轮询。目标不是已测性能，数据量/并发/硬件须随测试报告记录。
- 数据迁移采用新增 nullable 列/小表，旧资源 vendor_id=NULL；不更改既有角色、消费者余额、BPS 数据和历史迁移。升级前后旧 admin/消费者路径保持行为。
- 所有实例先升级到理解新资格字段的版本，再开启功能；旧二进制可能忽略 vendor 暂停，因此不可在供应商活跃时直接滚回旧版本。回滚流程必须先关闭入口并让供应商账号全部停止新调度，等待在途结束，再回退应用；保留新列及历史。
- 共享交付依次 main → TapModels / tokensavy 普通 merge；继承品牌名称/资产/语言，禁止把参考站或另一品牌名称写成产品名。发布和生产迁移需独立授权。

## 11. 首版边界与后续产品选择

首版完成超级管理员专属开通/管理、双平台上号、分组多选、授权导入导出、专属代理快捷添加、详情/操作、删除与历史统计、多供应商结算/人工付款登记、独立域名入口与共享原生分组消费闭环。后续可按真实使用反馈新增：多成员、大范围异步报表、平台代理显式授权、管理员归属转移。这些不是首版上线的隐含依赖。

尚需在实施时验证的技术事实：各平台稳定身份组合、OAuth 多实例会话存储、现有代理校验在实际 dial 中的覆盖、跨实例暂停传播上限、各原生调度入口清单、凭证存储保护和统计执行计划。验证不足时应收紧入口或报告具体缺口，不能把方案中的目标写成现有能力。
