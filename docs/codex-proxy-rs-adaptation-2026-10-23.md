## 按顺序完成的修改

1. **普通请求减少重复工作。** `openai_gateway_scheduling.go` 复用实时账号读取来确认普通账号存在；供应商资格按最新归属核验。`Forward` 去除普通账号重复预检和 WS→HTTP 转换时的中间检查，供应商凭据准备、WS 握手及最终发送边界的必要检查保留。真实每请求减少次数依选号与传输分支而定，不能把静态调用数当固定往返数。
2. **WS 请求只准备一次最终 JSON。** 完整请求字节同时用于恢复身份和普通发送；安全增量续接另外保留其实际发送字节。删除发送阶段重新编码 map 的路径，RawMessage 验证后按原字节发送。SSE 下游首文字刷新复用同一事件解析事实。未知字段、大整数及帧顺序不通过额外转换重写。
3. **恢复编排收拢。** 同账号 WS 重连移入现有 WS 模块；HTTP Responses、Messages 和客户端 WS 复用同一个同账号等待入口。保持原请求级尝试/等待预算、取消处理、计量结果和输出屏障。重连刷新凭据后 HTTP 回退继续使用新凭据。没有增加重试层或“极速模式”。
4. **设置条件写入。** GET 返回内容版本 revision，PUT 必须提交读取时版本。通用设置、认证来源默认值、Fast 和支付配置先统一校验，再在同一 PostgreSQL 事务中加写锁比较版本并写入。返回本次提交对应版本；并发过期返回 409，缺少版本返回 428。其他设置写入仍能使旧版本失效。没有新增版本表或迁移。
5. **OpenAI 刷新提前错峰。** 在现有 refresher 中用账号 ID 的稳定散列增加提前量，最多五分钟且不晚于原刷新时机。既有强制刷新、锁、并发限制和失败退避保留，不新增 Worker 或开关。
6. **预计总费用（2026-10-23 用户后续修正）。** 已恢复 Wei-Shaw 原作者同一窗口 `window_stats.cost * 100 / utilization` 算法；删除本节此前引入的后端预测查询、采样/年龄门槛、30 天折算和提示标注。Claude/Fable 各自使用独立窗口统计。
7. **脱敏诊断导出。** 在已有 Ops 错误详情增加 `diagnostics=1` 投影并提供下载按钮。只输出请求 ID、结果、原有延迟、受限事件和调度数值；不输出正文、凭据、用户/账号名称、IP、上游地址或任意错误文本。缺失、无效和截断事实明确标注，coverage 固定为 recorded_events_only。继续使用原详情读取、监控开关和管理权限。
