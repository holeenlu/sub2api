### 审计空闲与线程交接修复（2026-10-23）

- 异步内容审计队列为空时先等待工作，再读取运行时配置；配置故障或非活动 worker 不取走任务。同步审核、白名单和数据留存不变；异步空闲唤醒最多约100ms，不新增开关。采用 ranxi2001 `8ff32b566` / `d71123389` 的修复。
- BPS 复用现有外部上下文识别器，不把 Codex 线程交接计为已执行工具历史；继续支持 create_thread、send_message_to_thread、内容数组并验证密文和元数据。另用一个内部状态保留原来的未知工具禁止重新生成保护，真实调用配对和续轮边界不变；没有复制来源的窄识别器。参考 ranxi2001 `98f7a7980` / `f79b27f48`，按用户确认融合。
- 开发 Docker Compose 与生产模板一致，可选透传 `SERVER_TRUSTED_PROXIES`；未设置时保留 `config.yaml`，显式空值禁用代理信任，不增加默认可信网段。配置路径沿用部署环境变量及 `server.trusted_proxies`，不需要数据库迁移。参考 ranxi2001 `09faea758`（作者 ranxi2001）。

### OpenAI 缓存期限与会话亲和

- 后续修复（2026-10-23）：非终态事件遗漏 TTL 组成项时保留已观测非零值，按本轮最新明确总量截断；HTTP、原生 WS 和透传 WS 共用原分桶类型的合并方法。非零终态仍整份替换，全零或缺失终态保留先前观测，不跨轮继承。参考 QuantumNous/new-api `e9d4d6353`（Calcium-Ion）的 progressive usage 思路，未导入其表达式计费产品，也未改变管理员价格、订阅/BPS 或历史账单。无新增接口、配置或迁移。

- HTTP/SSE、WS 及 Responses/Chat 转换传递上游明确报告的 30m/12h 缓存写入明细，不从请求 TTL 推断用量。公开 OpenAI API 的 12h 写入按现有短期限写入价两倍计费；管理员显式固定写入价（含零价）优先，Codex 订阅和 BPS 保持原计费契约，不重复累计总量。
- 既有使用记录、导出及共用用量表格显示 TTL 明细，支持四语言；迁移 `288_usage_log_cache_creation_ttl.sql` 新增两列，旧记录默认零且不重算历史账单。保留迁移 286 的延迟指标和迁移 287 的供应商汇率。
- 增量续轮比较缓存策略与显式断点，策略改变不复用旧锚点，未知结构保持全量转发。临时查询或单次资格拒绝不删除原账号绑定；WS 通过准入后才续期，Redis 原子校验归属，避免抢占并发或借用会话绑定。

来源：本地缓存协议审计及 Codex 已核实行为，详细实现和原验证见 [缓存审计](CACHE_PROTOCOL_AUDIT_2026-10-19.md#30m12h-缓存计量与亲和修复2026-10-22)。无需新增 HTTP 接口、用户配置或独立转发入口；新增一个内部缓存方法。升级需应用新迁移，本次只提交推送，不执行生产迁移，不承诺未经线上测量的命中率收益。

## 优化改进

- **同步与交付效率。** 四源增量筛选后固定本轮范围，独立产品候选不阻塞已批准修复；交付工具新增 `delivery-run` 协作锁，覆盖最终基点、验证、精确 lease 推送及本地对齐，锁等待可设上限。只读 `validation-status` 不再等待编译锁或创建临时目录；`validate --go-cache` 可显式复用已核验的共享 Go 缓存，前后检查 8 GiB 上限，不自动清除他人缓存，临时输出仍清理。按实际风险选测试，品牌相同输入复用证据；源码和测试通过条件没有降低。新增的是本地 CLI 模式/参数，不是业务 API、站点设置、自动发布或生产执行路径。详见 [常规同步与串行交付](CHANGE_DELIVERY.md#常规同步与串行交付2026-10-22)。

- **Claude / Codex 使用记录指标统一。** 新记录采用同一请求/WS轮次起点，包含排队与重试，区分首事件、首内容、首正文和到上游终态/中断的总耗时；元数据、心跳及空输出不充当首内容。使用记录、详情和导出显示新口径，旧记录及历史聚合明确标注；缓存占比按互斥输入分桶统一计算，覆盖明细、统计卡、仪表盘及趋势。复用现有timing并在异步记账前冻结，保护WS跨轮、恢复和授权分账。新增286号nullable JSONB迁移，不回填历史、不改变计费或推理；升级部署时按原迁移器处理，本次未执行生产迁移。见[指标契约](CODEX_RESPONSES_TRANSPORT_OPTIMIZATION.md#21-claude--codex-统一使用记录指标2026-10-22)。

- **供应商门户超管手动更新。** 独立供应商门户在左侧栏站点名称下方复用运营站版本号与更新面板，移除单独的顶部更新按钮和弹窗，分别显示门户和后端运行版本，按后端版本选择同品牌正式发布的门户镜像。复用宿主机更新器的独立门户模式与实时超管鉴权，支持分机/不同项目，保留同项目配套升级、健康校验及失败恢复；首次需安装新版宿主机更新器并接入门户 socket。

- **后端与供应商门户配套升级。** 三品牌同项目在线更新读取同一 Release 的后端/门户镜像摘要，先完成全部预检，再一起替换并验证健康；失败或中断恢复覆盖两者，保留存储和其他服务。安装器自动发现 vendor-portal，自定义服务名使用 --portal-service。分机发布新增只固定门户镜像的 compose.vendor-release.json 附件和明确升级步骤；发版前覆盖供应商创建、授权表单回归。已有主机须重新安装宿主机更新器，分机门户安装独立更新器后，可在供应商站由超管手动同步。见 [升级说明](../deploy/AUTOMATIC_RELEASE.md#供应商门户配套升级2026-10-22)。

## 升级指南

1. **先选正确分支/渠道。** main为KDAN，TapModels与tokensavy为各自独立品牌、站点及数据。对应默认值、域名、Logo、法律、文档、下载包、服务名与镜像保留；运行时已保存的站点设置优先于品牌默认值。
2. **保留现场后更新Git。** 提交或备份未完成工作，记录旧SHA；抓取目标分支，确认远端为本仓库及本轮公布的新SHA。干净且无独有工作的正式分支才能对齐新tip；自己的未交付补丁先审查再移到新基底。历史备份与标签用于追溯，勿作为合并来源恢复旧父链。
3. **部署前备份。** 数据库、配置、加密密钥与业务文件使用现有备份流程；账号JSON不是数据库备份，不含历史用量/审计/临时状态。更换站点导入账号时核对平台/组名、代理链和授权归属，不能依赖源数据库ID。备份含凭据，使用原敏感操作权限与保管措施。
