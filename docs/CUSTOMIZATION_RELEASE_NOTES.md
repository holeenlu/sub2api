# Sub2API 完整定制 Release Note

更新日期：2026-10-24。本文说明相对 `Wei-Shaw/sub2api main` 已核对基线 `37067e8e340e9440d173a92b4faa05e8ce58368f` 的全部有效定制，官方应用版本为 `0.2.17`。按当前实际代码与功能整理；官方本身已有的功能不重复列作本地新增。实际版本、源码、镜像和附件以对应品牌的 GitHub Release 为准。

main、TapModels、tokensavy 分别保留共享功能与各自品牌覆盖，每个分支直接在同一官方提交上保留一笔完整定制提交。**每次正式发版都提供本文全文**；新增、修改、优化或删除功能时，直接更新对应章节、配置与升级说明，不只追加日期记录。已经撤销或被替代的实现从有效功能中移除，历史过程仍可通过 Git、来源文档及交付记录追溯。

## 当前官方基线与同步范围

- 完整保留 Wei-Shaw 官方历史及当前基线，包含原生平台、网关、调度、计费和模型能力。最近官方改进包括按操作、分组、平台及账号类型限制的管理员访问密钥，以及 Codex 身份归一、空 SSE 判定及容量降载 Retry-After；这些属于官方能力。
- 默认检查 Wei-Shaw、ranxi2001/sub2api、QuantumNous/new-api、zyycn/codex-proxy-rs、dofastted/vm2api 五个来源。除官方完整整合外，其余按当前 Go/Vue 架构选择性适配；sub4api 仅在明确点名时核查新提交，已吸收功能及署名保留。
- 新增来源不等于整仓采用或全部历史已审查；来源提交、适用边界、未采用与待研究项由各适配记录维护。未引入独立 Rust/Node 网关、VM/guest 运行体系或来源项目的自动发布流程。

## 新增功能

### 管理员授权、用户归属与敏感操作

- 统一 `super_admin / admin / user` 角色和管理员策略，支持模块、操作与字段权限、版本冲突检查和原子审计。策略编辑由超级管理员会话执行；普通管理员不能读取受保护的超管对象，机器管理 Key 不能替代该会话权限。
- 官方受限管理员密钥适配本地三角色：仅有效超管 JWT 会话管理创建、编辑、轮换、撤销及记录删除，机器密钥不能自管或代替超管会话。按同一资源规则匹配操作/分组/平台/账号类型；完整密钥仅创建或轮换时显示，保存哈希，支持期限/IP 与即时撤销。读取脱敏、写入事务重验与供应商归属/归档保护共同生效，流式输出复核密钥与策略；原普通管理员创建人隔离不变。详见 [受限管理员密钥](admin-api-keys.md)。
- 普通管理员只创建和管理自己创建的普通用户。创建人持久保存在 `users.created_by`，不依赖审计保留周期，也不接受客户端改写；详情、Key、订阅、订单、用量、余额历史及审计读取按同一归属过滤。
- 用户列表优先显示创建人当前用户名，无名称回退 `#ID`，无可信归属显示未知。无法从旧创建审计确认归属的用户由超管管理，不猜测归属。
- 登录会话撤销、refresh family、MFA、Passkey、一次性 OAuth pending、最后超管保护及敏感数据导出继续执行后端校验。统一策略编辑不要求 TOTP，不代表全站取消二次验证。

### 资金转账、个人充值记录与支付完整性

- **充值记录列宽。** 恢复浏览器按内容自动分配全部列宽，表格最小宽度 650 像素，取消固定列宽及备注最大宽度限制；所有表头与单元格统一左对齐，实际备注保留换行，长连续文本可换行。窄屏按需在表格内横向滚动。三品牌共享，无新增接口、配置、执行入口或迁移，部署前端后生效。

- 超管授予“计费 → 调整余额”后，普通管理员可向所属用户充值或扣回未消费余额。双方余额、关联流水和审计在同一事务中完成，任一步失败全部回滚；初始余额也从管理员余额转出，不能通过编辑或 `set` 绕过资金来源。
- 用户消费扣自己的余额，管理员转出后余额为零不影响已获资金的用户；超管 Key 继续按所属角色执行个人余额豁免，但仍受 Key、窗口及平台配额约束。豁免策略进入冻结计费事件，恢复时不重复扣款或漏记用量。
- 超管、管理员、普通用户头像菜单均提供本人“充值记录”：账号、当前余额、累计充值与分页流水。只从当前 JWT 取用户身份，过滤先于分页，不返回他人记录、兑换码或管理元数据。
- 充值记录只显示实际备注；后端个人记录投影清理管理员转账系统前缀、历史未实际入金冲正的内部审计说明及管理员编号，保留真实填写的备注和换行，原账本与管理端审计不改写。累计充值按充值及管理员正向入账统计，不代表实际支付额、不扣退款、不计返佣；历史来源标签只用于识别旧账，不恢复已删除功能。
- 支付校验商户、交易身份、回调与履约一致性。退款保留预留、租约与审计；网络结果不确定时不立即释放重复退款，人工裁决不能与支付方已确认结果矛盾。

### 批量生图资金归属

- 新批次使用 v2 定价快照：整个预留额、预计消费和实际消费各按现有八位金额规则量化一次，费率与折扣不变。预留、捕获或释放在原幂等账本事务中维护批次、Key、用户、金额及持有状态；捕获与释放互斥，不能动用其他批次冻结资金。零价任务保持零资金行为。
- 释放指纹冲突保留失败，不能作为已退款证据。旧超八位金额只允许只读核对热表/归档中的原操作回执；身份、批次、金额或载荷不符拒绝，超过旧十位指纹可表达精度也拒绝。不回填旧持有凭证、不按余额池猜归属、不补扣或自动退款。

### API Key 管理与完整备份迁移

- `/keys` 支持按选择或筛选导出、逐项导入，使用 `sub2api-keys` v1，最多 1000 条。恢复原 Key、状态、额度、窗口用量、IP 限制和期限；按目标用户获准平台及组名匹配，不迁移用户或源数据库 ID，不覆盖他人 Key，供应商身份不开放此入口。
- 超管可在个人 Key 入口协作管理其他超管的 Key，由后端实时确认角色；普通用户限本人，删除用户只处理其本人 Key。跨超管改分组仍核对 Key 所属用户资格。
- 完整账号备份采用 `sub2api-data` v2，保留主凭据、独立 Excel/BPS 授权、协议与调度状态；按同一快照导出，以目标站加密密钥落库并事务恢复。
- 代理链按文件内引用恢复，分组按平台及完整名称匹配；缺组或重名明确报错。有效旧 Codex/Excel 备份继续按已支持格式读取，未知版本拒绝。账号 JSON 不包含完整数据库账务、审计或临时运行状态。

### 账号授权、资料、模型权限与用量

- Claude 提供完整 OAuth、浏览器 OAuth token、手动 Setup Token 三种授权方式。长期 Token 可直接粘贴，不要求其没有权限读取的 profile，也不伪造签发期限；表单提供真实操作步骤和失败重试说明。
- 完整 OAuth 自动获取并保存已认证邮箱、套餐、原始档位、支付方式，拒绝与兑换身份不一致的资料。Codex 补齐已认证邮箱与订阅到期查询；资料缺失不丢弃已经验证的身份，不捏造 Setup Token 的邮箱或套餐。
- 新建账号留空名称时使用已验证邮箱前缀，已有账号和重新授权保留原名称。名称入口复制完整已验证邮箱，无邮箱时复制完整名称；详情保留独立操作入口。
- Fable 保留独立全局及账号阈值，5h、7d、Fable 窗口分别更新；额度重置、兑换和通知复用现有账号能力，重置短窗口不清空周窗口。
- 模型目录、分组白名单、账号限制、映射与客户端选择遵循原生权限链；目录可见不代表账号已获能力。保留原生远程目录、模型字段和顺序，不恢复独立目录治理。
- “预计总费用”沿用官方同窗口费用 × 100 / 原始使用百分比，Claude/Fable 分别取自己的窗口；0 或无效输入不显示估算，不重新引入独立采样预测器。

### Excel/BPS、工具、图片与恢复

- 独立 Excel grant 与原生 OAuth 凭据分开，保留授权、刷新、版本 CAS 和账号归属。支持 HTTP/SSE、compact、Chat/Messages 兼容及客户端 Responses WS 桥接。
- 支持 function/custom/namespace/dynamic 工具、目录继承、工具搜索和成对调用历史；保留完整 call ID、加密上下文、compaction 与消息控制字段，不通过盲删历史恢复请求。
- 图片和附件按归属校验，在请求内去重并使用分阶段预算；BPS 后保留安全的原生机会，不从原生失败反跳 BPS，也不借原生成功冒充 BPS 恢复。
- 显式 403、cyber、429、模型拒绝分别分类；模型权限拒绝只影响对应模型，冷却不污染原生 Codex 配额。密文失败显示字段路径与账号实际设置，不回显密文或增加解密能力。BPS 上游 401/403 的终态拒绝以 503 `server_error` 回客户端，不透传鉴权状态码；BPS 本地以 4xx 答复的拒绝不计入账号调度健康；客户端 WS 桥接上的 `response.cancel` 按客户端取消记录。图片历史压缩阶段的传输失败、5xx、401 与生成阶段共用生成前恢复契约。
- 外部线程交接不被误判为已执行工具；未知工具只在完整可验证历史、未提交输出及原预算允许时执行既有受限续接，不重新生成已执行或未知副作用的工具。
- 新安装的全局 BPS 和图片支持默认开启、图片传输默认 native；所有已保存站点及账号值优先。完整边界见 [BPS 当前需求](bps/REQUIREMENTS.md) 与 [双路径契约](bps/DUAL_PATH_REVIEW.md)。

BPS 账号模型映射的 HTTP/JSON、SSE 响应复用原生模型字段还原，向客户端返回请求模型名；诊断与计费用的上游模型保持独立，工具参数和正文不做字符串替换。

### Cloud 授权与 Responses 网关

- 普通 OpenAI OAuth 账号编辑及批量编辑仅提供 Cloud 网关开关，复用原生 OAuth 单一刷新权威；不再要求单独 Cloud 登录、授权或回调。首次实际使用验证原生身份并自动建立会话/账务绑定，不复制或替换 AT/RT。Cloud 开启时账号级优先，保留 BPS 开关、授权与模型配置；关闭后恢复原生默认、BPS 全局与账号开关及映射后模型命中分流，不新增协议选择器或路由表；模型权限统一由分组与账号普通模型白名单/映射控制，无独立 Cloud 模型名单。
- 调度精简快照保留 Cloud 选择及原生客户端身份判定，旧快照经现有数据库回读重建，防止候选过滤误走 BPS/原生或拒绝 Cloud 续接。
- Cloud 的连接失败、明确推理前限流/容量/授权拒绝接入 HTTP/SSE 与客户端 WS 的统一恢复；暂存起始响应身份及失败终态，核对 owner 的未执行证明与零消费结算后，瞬时故障按原账号设置最多重试一次，再重新选号。额度/授权拒绝直接换号；共享整轮、owner、目标及等待预算，已输出、消费未知、参数/策略错误和 Cloud 续接不重放。Cloud 健康及本轮排除按模式隔离；无新增接口、配置或 SQL 迁移。
- 切至 Cloud 后，旧 BPS 请求迟到的 403 不再关闭保留的 BPS 设置或自动移组，后台探测与恢复同样遵守当前协议选择。
- 支持 `/v1/responses` JSON、SSE 和客户端 Responses WebSocket；保留角色历史、assistant phase、函数/namespace 工具、原样转发的内联用户输入与工具图片、加密 reasoning/compaction 历史、托管实时搜索和 PNG 生图。
- Cloud HTTP/SSE、WS共用原生legacy输入及工具schema修复，保留真实续接ID；接纳 `prompt_cache_key` 缓存亲和字段，映射常见summary/verbosity到Cloud RPC；参数变化、身份/账务隔离仍按原规则。接收 Codex 正常附带的 `client_metadata` 字符串映射，按大小及类型校验，作为入口信息处理；不将客户端身份或任意键转为 Cloud 认证、线程归属或工具配置，元数据逐轮变化不破坏续接。
- 验证区分模型不可用、密文证据缺失及完成后的归档失败。简单回答没有 reasoning 项时，最多补一次独立复杂推理检查，每次均须完成结果、结算与清理；仍无密文则本次手工测试失败。归档超时和上游拒绝返回明确、安全的诊断；测试选项只保留在“测试账号连接”，不参与启用、模型权限或授权状态。
- 客户端工具保留原类型与调用身份；内部执行代码不暴露为待客户端执行工具。托管工具和客户端工具交错完成时有界缓冲公开事件，重复工具结果按内容幂等，冲突拒绝。
- 原 socket 持有工具 RPC，跨实例请求经 Redis 回到原 owner；响应、工具、账号、grant、模型与 Key 归属一致。真实 Cloud ID 回原 owner 续接，本地 WS `generate:false` 预热 ID 使用当前连接缓存的完整输入。重试恢复同一结果及公开生命周期，不重新执行工具或写第二笔账，已执行或归属绑定的失败不换账号、协议重放；独立请求明确推理前失败时，复用统一预算重试或换其他合格账号，不修改原账号协议设置。
- 每个计费 root 冻结归属、价格和策略；可信最终 token、缓存、搜索次数及真实图片尺寸进入既有原子账本。明确推理前拒绝释放预留且不收按次费用；不能确认的消费保留 Unknown 事实并退出可处理结算队列，不推测为零、不扣款、不阻断账号；可信账单继续沿原原子账本幂等结算。
- 删除账号人工用量核对页面、接口、审计写入及 SQL/Redis 未决消费阻断；Cloud 开关和批量开启仅遵守原生 OAuth 资格，历史未知账不再使开关灰掉。迁移 295 更新数据库启用触发器，保留历史表和账务证据，不清除数据、不自动重新开启账号。
- 首输出受整轮期限约束，HTTP 错误状态与安全 SSE/WS 终态保留；容量压力下只回收已完成空闲会话，不关闭待工具连接。设置或授权变化仍校验已有会话归属，身份变化使旧会话失效，新请求重新核验原生授权；不要求重做能力验证。
- 补齐 Cloud HTTP流中失败的Ops记录、WS准备失败的drain清理和本地健康归因、预算错误传播、SSE心跳非语义计数与最新Codex客户端限制复核；安全策略拒绝沿用原有风控，延迟账保留安全错误码和cyber用量分类，原收费及幂等规则不变。双向HTTP/SSE↔WS工具续接覆盖同一owner与单次结算。
- 修复 Cloud 完成一轮后的完整reasoning继承、取消时误发502终态，以及HTTP/SSE缺少有界写入和Flush错误识别；下游失败沿原归因与持久账处理。使用实际Codex 0.159.3脱敏HTTP/WS报文覆盖106个工具及预热/正式请求，扩展到双工具完整历史、图片增量续接、WS切HTTP、429、部分输出后失败与取消。修复客户端默认 `detail:high` 和非 PNG 图片被 Cloud 拒绝；参考原生网关原样转发 MIME/图片字节，移除输入 PNG 解码及像素限制，不套用 BPS 格式名单；保留 base64 封装、字节/张数及请求/会话预算，托管生图输出的严格校验不变。用户图片及原始历史保留 `original`；待回复动态工具 original、low、远程 URL、file_id 等无法无损表达的形态给出具体错误，不静默降级。实际 JPEG/WebP/GIF 报文扩入原生/BPS/Cloud HTTP/SSE、WS及桥接矩阵；SVG 在本机客户端不生成图片输入；自行提交的 SVG/AVIF/TIFF 等内联格式由 Cloud 上游判断，网关接纳不等于模型支持。旧 original 工具历史与当前待回复工具按 call_id 区分，冲突历史拒绝，正常续接只结算一次。工程验收规范明确证据层级，不增加产品准入。
- Cloud HTTP/SSE 在模型映射后应用公共 Fast 策略，WS沿已有连接快照执行一次；filter、force、block与原生策略顺序一致。无法映射到 Cloud 上游的 service_tier 仍明确拒绝，不伪装支持。
- 串行工具 `parallel_tool_calls:false` 每次只公开一个待执行调用，后续 RPC 有界保留；等待间隙的文本、密文及托管事件按顺序补齐。公开引用与历史一致，原样回传不误拒；完成后的新 turn 可调整 reasoning/summary 和严格输出 schema。`store:false` 使用临时线程，移除创建后绝对15分钟截断，改为完成后空闲回收及工具等待无活动期限。严格 `json_schema` 映射上游 outputSchema；上游没有串行规划参数，网关仅保证串行交付执行。
- 迁移 296 新增内部 Cloud 账务事实归档，Unknown、坏记录和永久失败先持久保存原字节再 CAS 移出 Redis 队列；单条坏账不阻塞其他账，数据库临时错误继续重试。归档不扣款、不标记结清，不增加人工审核。延迟账保留已有观测，HTTP/SSE及WS入口复用原生 timing v2。
- 批量开关与单账号共用普通原生 OAuth 资格，提前显示不适用账号；只切换 Cloud 不重新校验原样保留的 BPS 配置；Cloud 模型目录复用原生缓存并拒绝缺失/null data。临时线程丢失保留安全的 `cloud_thread_unavailable` / 502 分类，不回显线程ID或误报密文400。Cloud 以原生公共入口为基准，HTTP/SSE与WS心跳读取原生公共配置（0关闭），BPS 既有模型规则和界面保持。
- 按 ChatGPT 桌面版内置 Codex 0.164 的真实请求补齐 Cloud 接入：接纳并发推理摘要的 `stream_options.reasoning_summary_delivery: sequential_cutoff`、输出 token 回放的 `include: output.encrypted_content`、消息及推理项的归属元数据，历史中的输出密文与元数据原样透传；推理项完成时按原生顺序补发摘要事件。Cloud 账号承载的模型在 Codex 模型目录中如实声明不支持客户端工具搜索、Responses Lite、客户端 code mode、加密多智能体消息与非缺省服务档位，客户端随之以标准 Responses 形态直接下发全部工具；混合分组按既有规则回退为保守值。`web_search` 的缓存/索引/实时访问控制映射为线程搜索模式，不再固定为实时；`custom` 语法工具映射为单字符串输入的动态工具并按 `custom_tool_call` 回传；`user`、`safety_identifier` 等中性字段与 `reasoning.effort: none/minimal` 接纳。
- 完整历史（`store:false`）续接：只有 Cloud previous ID、运行中或等待中的工具调用和以工具结果结尾的回放固定原会话；已结束会话的旧调用 ID 视为普通历史，可在任何合格账号继续。同一归属且租约有效的已完成线程仅在历史与设置完全一致时续写，编辑、重新生成、设置变化或托管结果不一致时以同一结算根另开线程注入完整历史；网关发布的搜索/生图结果可回填为历史，不重新执行或重复计费。previous 失效返回原生 `previous_response_not_found`，WS 下为单轮错误事件并保留连接；会话已不存在的工具回传返回 `cloud_tool_call_expired`。
- Cloud 支持 Codex 客户端触发的上下文压缩（远程压缩 v2：输入末尾的 `compaction_trigger`，HTTP/SSE 与客户端 WS，轮前与轮中）。网关在 Cloud 线程上用 Codex 原文压缩提示词运行一个摘要轮，并返回客户端要求的唯一 `compaction` 输出项，摘要放在该项中；之后的请求把它注入为 Codex 本地压缩安装的同一条用户消息并另开线程，后续轮次照常续写，长会话可越过压缩继续对话。线程存活且历史一致时摘要轮在原线程运行；线程等待客户端工具时（轮中压缩），先中止该轮再在同一线程摘要，工具结果作为输入，两个上游轮次仍只结算一次。摘要轮的客户端工具调用被婉拒；摘要为空返回 `cloud_compaction_failed` 并照常结算。HTTP 入口识别的压缩在 Cloud 用量记录上标记 `native_compaction_v2`。没有采用 App Server `thread/compact/start` 和调整目录阈值，原因见 [Cloud 实现与限制](OPENAI_CLOUD_DESIGN.md)。回归基于桌面版 Codex 0.164 的真实采集报文，另有真实客户端对本地网关加替身上游的端到端验证；真实 Cloud host 尚未验证。
- 旧版一元 `/responses/compact` 端点、`store:true`、远程图片/file_id、未支持的工具选项、音视频及无损映射之外的结构化输出明确拒绝。取消强制完整验证与能力证据准入；手工测试不再改动账号启用、授权或模型名单，账号编辑不展示测试按钮和已验证模型列表。普通升级、代理或模型配置变化不再要求重新验证。详见 [Cloud 实现与限制](OPENAI_CLOUD_DESIGN.md)。

### 设备资料与账号遥测

- 超管仅导入真实设备安装资料 v2。独立 Go 工具在 Windows/Linux/macOS 本地导出，不要求 Node 或账号登录；服务器不安装或初始化 Claude Code，不提供任意事件上传或样本采集。

## 优化改进

- **统一调度与额度保护。** OpenAI 先资格、真实容量、模型健康，再按优先级、订阅/成本层及层内容量选择；其他平台保留原生排名。批量快照、会话预筛、费用窗口缓存、有限 SQL/Redis 访问预算及最终复核减少无效选择，并保留后续层机会。
- **临界额度。** 复用原调度及分布式槽位，在有效停调线附近收敛并发，结合可信缓存样本处理大冷输入。Anthropic 默认/Pro 与 Max 双窗口策略、临界带、样本有效期通过原 Ops 设置管理；套餐策略默认关闭，账号覆盖及 Fable 阈值优先。
- **整轮恢复。** HTTP/SSE/WS/BPS 共用截止时间、实际发送及首语义输出预算；keepalive/元数据不延长期限。区分未发送、已接受、已提交输出及不确定工具执行，输出后不重放；可恢复 WS 失败后仍支持下一轮。
- **传输与增量准备。** 四个 OpenAI 入口复用账号准备与恢复状态；在实际发送前按最终字节及续接能力选择传输。确定未发送的大包、可选 WS 准备超时可安全走现有 HTTP 路径；缓存策略改变不复用旧锚点，未知结构全量转发。
- **压缩及 SSE。** zstd 使用有界并发与可取消等待，复用最终正文，清除重复暂存和编码；input 仅真实变化时复制。SSE 增量扫描长行、按完整帧交接，保留多行 data、换行、大小限制、EOF、取消及计费排空，删除拆行再拼帧的重复实现。
- **首文字与观测。** 第一段可见正文成功写入后立即刷新，后续仍批量输出。观测先采样后进入原 Ops worker，为关键失败留容量并提前脱敏；离线分析器严格配对同 attempt 数据，不把局部基准推断为线上首字或吞吐改善。
- **凭据及设置并发。** OpenAI OAuth 刷新按原认证 grant 条件合并，保留并发模型、代理和停用设置；旧结果不能覆盖重新授权。失败只可使用仍有效 access token，缓存不超过真实期限。设置 CAS、刷新错峰与运行快照沿用现有 owner。
- **登录隔离。** 请求、响应、401、权限恢复和 step-up 重放绑定发起时 JWT 会话；正常 token 轮换保留 sid，新登录不接收旧结果。刷新按会话合并，迟到注销不清新会话。
- **清理任务。** cron 代次可取消，在配置锁外等待，超时不启动重叠任务；各表轮转一批，零保留期每轮只清空一次。Redis 解锁绑定独立 owner 并使用有效收尾上下文。
- **后台与展示。** 账号/供应商复用可信配额快照和状态组件，费用表只显示金额及详情，未知结算不伪装零费用；Inter 字体保留原许可，表格、浮层与代理检测交互保持一致。
- **配套升级。** 同项目更新器按同一 Release 的摘要一起预检、更新和恢复后端及供应商门户；分机门户使用独立更新器或发布附件的 Compose override。门户由超管查看版本并手动更新，不访问 PostgreSQL/Redis。
- **手动发布。** 主站/门户共用一次类型与翻译检查，品牌间可并行、同品牌版本预留至晋升串行。版本分配同时核对正式 Release 与远端标签，草稿删除后不复用已占号版本；陈旧源码不能发布或晋升 latest。
- **完整说明。** 每次人工发版从被发布提交读取本文全文，不用提交标题或单次补丁说明替代；镜像摘要、附件、源码及渠道元数据由发布计划补齐。功能变化须同步修订本文，删除项更新有效功能、兼容性及升级说明。
- **Cloud 图片与请求体对齐原生（2026-10-24）。** 去掉 Cloud 网关自设的单图 3 MiB 与每条消息 8 张上限，以及协议解析层的 4 MiB 请求体检查；只保留 Cloud 协议本身的要求（内联 base64、拒绝 `file_id` / 远程 URL / `detail: low`）。官方 Codex 客户端发图前已缩到 2048 / 6000 px。请求不再经过 4 MiB + 512 KiB 的 Redis 命令封装：会话 owner 在本实例时（所有新会话，以及落在 owner 实例的续接）请求直接进入 actor 的进程内收件箱（与 Redis 命令流同样 64 条业务 + 16 条取消/关闭上限），请求体只受 `gateway.max_body_size`，与原生一致；只有 owner 在另一实例的续接才经 Redis 命令送达，单条上限 16 MiB（紧凑 JSON、不做 HTML 转义，等于每会话未消费命令预算与出站单帧），超出在派发前返回不换号的 413 `request_too_large`，完整历史命中另一实例的已完成线程而送不过去时改为本实例新开线程。owner 判定、取消 tombstone、请求截止与账务预留语义不变。仍保留的 Cloud 自身上限是每个 actor 16 MiB 会话保留量与 16 MiB 单个上游 WS 帧；真实 codex-cloud-backend 对大帧的接受情况未验证。
- **三路径共享规则收口（2026-10-24）。** SSE 行切分（CR / LF / CRLF / BOM）抽到 `internal/pkg/sse`，原生 8 处调用点与 Excel/BPS `readEvents` 共用，BPS 不再因裸 CR 流卡住；上下文超限短语规则唯一归属 `internal/pkg/openai.IsContextWindowErrorText`，原生 HTTP、BPS HTTP 400 与 BPS 流内分类三处同判。BPS HTTP 下游心跳改用 `gateway.stream_keepalive_interval`，与原生、Cloud 同键同语义。三路径硬限制/配置/管理设置/上游能力对照见 `docs/GATEWAY_PROTOCOL_LIMITS.md`。

## 删除与退役

- **SIWC 全部运行能力删除。** 独立动态注册、授权/刷新/撤销、目录、HTTP/SSE/WS、调度、预热、账号编辑、授权备份恢复、专用工具/DTO/历史筛选及文案均移除。Cloud 是独立已实现的新路径，不继承旧 grant、表或 direct scope。
- **钱包兑换与邀请返利删除。** 用户兑换、后台卡密、注册邀请码、邀请链接、返利及提现的页面、API、配置、权限和执行链路移除；在线支付、管理员原子转账及历史账务仍有效。Claude 上游重置额度等独立账号能力不受影响。
- **优惠码删除。** 管理页、路由、公开验证、注册传递及赠额逻辑、配置和专用 ORM 移除；旧链接、Cookie 或待完成注册状态不能再增加余额。普通邮箱/OAuth 注册及正常支付保留。
- **旧调度设置删除。** 旧算法选择、权重及专用 YAML 键退出运行；已有备份迁移与最终统一策略保留，不提供旧算法兼容开关。
- **旧遥测入口删除。** 服务器 CLI bootstrap、手工生成、客户端 OTLP/样本采集、事件副本/profile 回退及专属运行目录逻辑移除。旧事件入口只返回空 200，不读取或存储任意事件。
- 票据/Cookie 绑定、自动登录 Worker、Mihomo、独立目录治理、额外质量运营、CC-Switch 及旧测试平台继续退役；BPS 只保留明确恢复范围。
- 删除被替代的独立费用预测器、重复身份/重试/流解析路径、旧语言文案、失效兼容转换与专属测试；保留有真实账务或数据读取方的历史 SQL、必要模型和审计。

3. **已删除接口。** 旧兑换、邀请码、返利、优惠码和 SIWC 接口停止提供，旧配置不再恢复功能；外部调用方须移除依赖。`/admin/promo-codes`、`promo_code_enabled` 及注册 `promo_code` 无效。
4. **SIWC 数据。** 已交付迁移 290 在应用升级时删除旧私有授权/安装表及账号协议字段；原生/BPS 授权和历史账本保留。删除后不能只靠回退程序恢复，需在升级前另行备份。
5. **Cloud 启用设置。** 迁移294移除独立Cloud授权前置条件，旧authorize/callback/DELETE授权接口退出；单账号和批量编辑共用原开关，原生/BPS凭据、执行绑定及未决账保持。 迁移 293 撤销完整验证准入、旧证据列和独立模型名单，保持授权及当前启用选择，取消 Cloud/BPS 开关硬互斥并采用 Cloud 账号级优先；已被旧版本停用的账号可直接重新启用 Cloud，不自动替用户启用。手工 Cloud 兼容性测试仅在“测试账号连接”保留；迁移 295 撤销人工用量审核与旧未决消费阻断，单账号/批量启用不再受其限制；历史账务表和 Unknown 事实保留，不伪造零账。迁移 296 增加内部事实归档表，供 worker 自动搬出不可消费账务事实，不新增审核操作。
6. **Cloud 客户端形态。** Cloud 账号承载的模型在 Codex 目录中不再声明工具搜索、Responses Lite、code mode、加密多智能体与 Fast 档位；已缓存旧目录的客户端需重启刷新后才改用标准形态，刷新前发出的 `tool_search` 仍会得到明确错误。Cloud previous ID 失效的错误码由通用 400 改为 `previous_response_not_found`。 同一会话换协议（BPS、Cloud、原生之间）或换账号后，新上游读不了的推理密文与输出回放密文在推理前去掉、仍被拒再把压缩摘要换成提示，同账号各重试一次；模型看不到这部分内容，迁移来的会话每轮会先被拒一次再恢复。工具搜索与非 Cloud 执行的搜索/生图记录不进入 Cloud 线程。此前原生与 BPS 对这类历史一律返回 400 `invalid_encrypted_content`。 Cloud 签发的压缩项是网关摘要信封，原生/BPS 上游无法读取；压缩后的会话改走原生或 BPS 时，推理前恢复会把它换成其中的摘要消息继续，不丢摘要内容。
7. **遥测。** 只接受合法 v2 设备资料，不把 v1、服务器 profile、任意事件或客户端副本转换为有效来源。后续发送从固定约 10 秒改为默认 600 秒，硬件字段不再上报；设备事实与原发送开关保留。
8. **统计与计费口径。** 新供应商账使用倍率前费用和独立付款换算价，历史账不重算。新缓存 TTL 明细、延迟指标和历史记录可能存在不同精度，不能把缺失历史值补为零或据此重算旧账。用量记录 `billing_status` 新增 `lower_bound`：Cloud 轮次经上游确认中断或失败后按已测用量结算，token 与费用为下界；导出和统计按已结算行处理，不新增列或迁移。Cloud 响应的 `usage` 不再是整轮之和：工具等待响应带上一次采样，最终响应只含最后一次采样，按响应累加的客户端每个工具轮比账单少一次采样；账单与用量记录以整轮结算为准。
9. **续接与中断。** 完整共享 owner 原子保障要求全部实例升级。多实例滚动升级期间，新实例写入的 Cloud 跨实例命令可达 16 MiB，旧实例 owner 仍按 4.5 MiB 校验读取并会因此判定命令流损坏而结束该会话；超过旧上限的请求此前本就被拒绝，单实例部署不受影响。滚动升级仍校验 v1 与旧双整数键；全实例升级且最长旧 TTL 经过后才可移除旧格式。依赖虚假 interrupt 确认的客户端须改用实际上游确认，桥接取消使用 response.cancel。
10. **BPS 错误口径。** BPS 上游 401/403 的终态拒绝、压缩阶段被拒以及共享状态容量错误现以 503 返回（`basispoints_upstream_error`、`basispoints_image_compaction_failed`、`basispoints_state_capacity`），压缩流内不可重放的 429 以 429 加上游 Retry-After 返回；依赖原 401/403/400 状态码的客户端或监控需调整。自动关闭/移组、冷却与凭据处理不变。
11. **入站错误口径。** 请求体读取失败不再一律 400：超限 413、停滞 408 `request_timeout`、客户端放弃 499（最小响应体）、解码/格式 400；`server.read_body_timeout` 改为空闲续期语义，配置键与默认值不变。上游自己的终态 4xx 失败（如 `unsupported_parameter`）在 HTTP/SSE 上以原状态记录，不再被 502 "Upstream request failed" 覆盖；依赖原 400/502 口径的监控需调整。
12. **Excel/BPS 目录与附件口径。** BPS 路由模型在 Codex 目录中的窗口由 1,050,000 降为 922,000、自动压缩阈值 830,000，长会话会更早压缩；已缓存旧目录的客户端需刷新。附件上传超时的错误码由 `first_output_timeout`（或 502 附件失败）改为 504 `attachment_timeout`，首输出期限不再包含上传时间，带图请求出字前最长等待相应增加（附件阶段至多 120 秒）。附件 ID 恢复跨请求缓存（取代 2026-10-14 的不缓存规则），文件归属诊断中的复用引用数与作废条数不再固定为 0。

## 升级指南

### 批量生图财务协议升级

- **禁止新旧财务写入混跑。** 部署本版本前停止新批量接单，排空旧在途请求、批次 worker、结算与恢复写入；确认全部相关节点使用同一新协议并具备迁移 `297_batch_image_owned_money.sql` 后再恢复接单。未确认的已开始工作不能因超时而退款或重复调用模型。
- 新表只记录新 v2 持有凭证；旧高精度任务缺少准确已提交回执时需要另行审核，不推测旧冻结余额归属。回退旧程序也须有兼容新状态的构建或单独授权的排空/对账方案，不能只凭队列为空回退。本文和代码交付不执行生产排空、迁移或资金修正。

### 版本、备份与代码

- 选正确品牌渠道及同品牌发布附件，核对源码、版本、镜像摘要、`release-manifest.json` 和 `checksums.txt`。当前正式产物仅 Linux amd64；Git 提交和推送不等于已构建、发布或部署。
