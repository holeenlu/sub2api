# Sub2API 累计定制 Release Note

## 2026-10-23 四源后续修复：缓存隔离与续接归属

- **鉴权恢复。** Redis首次订阅及自动重连推进本机鉴权缓存代际；正/负缓存均不能跨代际复用，旧查询不能回填新代际，singleflight按代际隔离。保留容量、TTL、现有撤权/outbox和请求生命周期；不新增后台服务。参考 ranxi `836d89c41` 并补齐本地并发回填/合并查询边界。
- **续接归属。** 按用户确认吸收 ranxi `fa71b879e`：HTTP response归属在现有Redis中原子发布，统一读取共享记录；过期、删除、格式不一致或Redis不可用时拒绝续接，不再由本机旧缓存继续授权。删除原先两次整数读写的服务后备路径；未配置Redis时保留明确的进程内存模式。
- **调度隔离。** 已有解码快照继续按revision/TTL复用、每次读取最新last_used；只复制本次请求可变的Credentials/Extra/分组容器和模型映射，避免互相污染。保留模型映射内容变更检测；增加复制开销是隔离代价，没有宣称吞吐改善。参考 ranxi `341abde05` / `2a333f9ae`，未引入来源专属组字段。
- **错误边界。** Cloudflare1010在自定义账号规则/快速阻断之前豁免，忽略回显input中的伪造标记；真实凭据错误继续处理。Anthropic结构化安全拒绝复用原分类器和读泵，不能因前输出错误延迟而换号重放，不转发拒绝之后排队的内容。参考 `46a0519eb` / `370975f61`，没有复制第二套流实现。
- **请求与界面。** DeepSeek图片统一保留现有image_url，不再同时携带image/source重复图片；保留file_id-only及工具上下文。表格组件卸载后迟到debounce不能再发请求，迟到/已取消响应不能回写。参考 `c2612d17f` / `413bc2ae1` / `d581332fa`。
- **升级和兼容。** 无新增公开接口、用户配置或数据库迁移，部署后生效。HTTP归属的旧两个Redis整数键是当前版本数据合同，滚动升级期间仍读写并与v1记录校验；所有实例升级且旧记录最长配置TTL经过后可删除该兼容读写。旧实例仍受旧写入方式限制，完整原子发布保障需要所有实例升级；不增加永久兼容开关，不执行数据清理。新增内部共享缓存接口1个、2个方法；快照复制方法用于封装service私有缓存字段，现有GatewayCache单整数接口无法表达原子双ID归属。
- **来源边界。** 官方基线保持 `5c185c5c`；New API无增量。CPR Rust依赖/导入弹窗与ranxi独立多节点拓扑不整套导入；前轮第三方生图白名单、轮次ID改写继续暂缓。最新其他任务的账号池/授权资料/优惠码移除全部保留。详细来源与对照见 [后续同步记录](upstream-sync-2026-10-23-followup.md)。ranxi适配保留LGPL-3.0来源，官方原提交及本地需求署名继续保留。

- 修正原生 WS 中断：保留 `response.interrupt` 与 mode，上游确认才作为 accepted/failed；终帧先到仍保留用量和连接控制边界。HTTP/BPS/SIWC 桥接明确返回不支持 interrupt，原 response.cancel 保留。
- HTTP/passthrough/WS 统一已验证的 subagent、memory、timing 与父线程意图头，保留凭据和账号身份隔离；修复 WS 写失败分类漏接，继续遵守已输出、工具副作用与整轮预算保护。
- 在实际发送前按最终字节和续接能力选择传输；确定未发送的大包及可选 WS 准备超时复用 HTTP 路径。沿用既有尺寸开关/阈值和总重试预算，不重复发起生成，不丢失精确续接上下文。
- zstd 保留既有依赖与压缩级别，解除全进程单编码槽位，使用有界并发和可取消等待；复用最终正文，清理重复暂存/复制。原生 input 过滤仅在真实变化时复制和重编码。

- **行为变更与升级：**依赖网关虚假中断确认的客户端应使用实际上游确认；HTTP桥接取消使用 response.cancel。无新增入口、用户配置或数据迁移；无需升级依赖。来源与取舍见 [CPR第三批实施](codex-proxy-rs-adaptation-2026-10-23.md#协议与算法比较后的实施第三批2026-10-23)，仅借鉴固定来源设计，不宣称生产性能倍数。普通提交推送不发版、不部署。

- **Claude / Codex 使用记录指标统一。** 新记录采用同一请求/WS轮次起点，包含排队与重试，区分首事件、首内容、首正文和到上游终态/中断的总耗时；元数据、心跳及空输出不充当首内容。使用记录主行保留“首字”文案、采用首事件时间，详情和导出保留三阶段；延迟详情删除统一计时长说明，时间值与表格共用现有延迟分级和深浅色配色；缺失首事件不借用首内容或旧首字，旧记录及历史聚合明确标注；平均 TPS 恢复官方上游的输出 Token ÷ 原始记录耗时，不扣首字等待，独立于统一计时对象；缓存占比按互斥输入分桶统一计算，覆盖明细、统计卡、仪表盘及趋势。复用现有timing并在异步记账前冻结，保护WS跨轮、恢复和授权分账。新增286号nullable JSONB迁移，不回填历史、不改变计费或推理；升级部署时按原迁移器处理，本次未执行生产迁移。见[指标契约](CODEX_RESPONSES_TRANSPORT_OPTIMIZATION.md#21-claude--codex-统一使用记录指标2026-10-22)。

- **供应商门户超管手动更新。** 独立供应商门户在左侧栏站点名称下方复用运营站版本号与更新面板，移除单独的顶部更新按钮和弹窗，分别显示门户和后端运行版本，按后端版本选择同品牌正式发布的门户镜像。复用宿主机更新器的独立门户模式与实时超管鉴权，支持分机/不同项目，保留同项目配套升级、健康校验及失败恢复；首次需安装新版宿主机更新器并接入门户 socket。

- **后端与供应商门户配套升级。** 三品牌同项目在线更新读取同一 Release 的后端/门户镜像摘要，先完成全部预检，再一起替换并验证健康；失败或中断恢复覆盖两者，保留存储和其他服务。安装器自动发现 vendor-portal，自定义服务名使用 --portal-service。分机发布新增只固定门户镜像的 compose.vendor-release.json 附件和明确升级步骤；发版前覆盖供应商创建、授权表单回归。已有主机须重新安装宿主机更新器，分机门户安装独立更新器后，可在供应商站由超管手动同步。见 [升级说明](../deploy/AUTOMATIC_RELEASE.md#供应商门户配套升级2026-10-22)。

- **完整轮次恢复。** HTTP/SSE/WS/BPS 共享截止时间、实际尝试与首语义输出预算；元数据/keepalive 不重置；区分准备未发出、已接受、可见输出与不确定工具执行。跨账号只迁移可携带上下文，输出提交后不重放，WS 可恢复失败后支持下一轮。见 `gateway_turn_recovery.go`、`openai_ws_execution_scope.go`、[恢复契约](OPENAI_RESPONSES_RECOVERY.md)。

## 破坏性变更与兼容性

以下为相对官方基底及旧定制版本的**累计**差异；已经采用当前版本的站点不会因此次 Git 重排新增运行期迁移。

## 升级指南

1. **先选正确分支/渠道。** main为KDAN，TapModels与tokensavy为各自独立品牌、站点及数据。对应默认值、域名、Logo、法律、文档、下载包、服务名与镜像保留；运行时已保存的站点设置优先于品牌默认值。
2. **保留现场后更新Git。** 提交或备份未完成工作，记录旧SHA；抓取目标分支，确认远端为本仓库及本轮公布的新SHA。干净且无独有工作的正式分支才能对齐新tip；自己的未交付补丁先审查再移到新基底。历史备份与标签用于追溯，勿作为合并来源恢复旧父链。

4. **数据库升级。** 保留已有SQL字节与执行账本，沿应用原迁移器按完整文件名处理；累计定制涉及角色、Excel授权、供应商及结算、统一调度、授权模式、用量事件、遥测历史、SIWC和账号创建者快照（当前末尾为287）。不按重复数字前缀手工重排，也不删除退役功能历史SQL。数据库升级/回滚须在另行授权的部署中验收，本轮未执行。
5. **核对开关。** BPS及图片支持只在全新配置默认开启、图片默认native，已保存值优先；SIWC授权与选用分开。遥测发送默认关闭，先导入v2设备资料再按需开启。Ops套餐额度策略默认关闭，显式应用建议值后仍需保存；已有账号覆盖不被自动重置。其他修复随对应新程序部署生效，无新增操作要求。
6. **升级后检查。** 用既有入口检查登录/权限、账号授权、供应商层级、Key导入导出、HTTP/SSE/WS、BPS工具/图片、计费和Ops；真实上游授权、真实数据库升级和性能需在相应环境验证。重建本身未重新发起实际供应商请求。
7. **回滚。** 代码可按留存旧SHA/bundle或已发布镜像恢复，数据库须结合实际已执行迁移及备份制定方案，不能仅回退二进制就承诺数据兼容。历史账务、归档账号、旧表及Redis状态不因整理提交被删除。
8. **SIWC未完成授权。** 本轮保护Redis临时会话，不继续读取旧明文会话；升级前尚未完成的登录需在账号页重新发起。已有授权不失效，多实例使用同一现有加密密钥。级联API Key旧冷却记录不自动清除，必要时由管理员按实际上游状态解除。
