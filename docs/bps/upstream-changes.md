## KDAN 线上错误反馈后的恢复修正

用户在 2026-10-12 提供了模型权限 HTTP 403 和流内 `server_error` 的错误记录。初版和来源均在模型冷却后直接响应 403；此前本地为保守处理流失败，也对未提交内容的明确 500 一律结束请求。这与已有 Responses 安全恢复能力有差距。

当前采用现有账号切换循环处理模型权限明确拒绝以及可证明安全的临时 5xx。不增加第二套重试器；保留完整历史、私有上下文迁移检查、工具副作用检查、取消检查和原尝试/切换预算。HTTP/SSE、WS 与 Messages/Chat 共用 Forward。流元数据有界暂存，失败 ID 不进入已确认历史；失败前实际观察到的用量照常记录。可恢复失败不会停止整个逻辑 turn 的首输出期限，且不占用专属首输出超时切换计数。

模型权限冷却还用于 WS 固定账号的下一轮转发和模型发现缓存，避免目录继续公布已被拒绝的模型；不把模型权限拒绝当作原生账号认证失效或全账号封禁。恢复不会授予账号原本没有的模型权限，全部账号均拒绝时仍返回错误。Messages 保留模型权限 403；WS 按原账号池耗尽契约以 1013 关闭并保留正确的模型原因，不能误报客户端认证失败。

临时故障恢复不能覆盖明确的加密状态拒绝；HTTP 与流内加密签名失败附带 5xx 时也不重试。流内错误规范化会删除原始消息，故保留已识别签名错误码的拒绝语义。

转换器单独保留原始错误的限定字段，关闭并 join 后由网关复用 HTTP 错误脱敏/长度限制写入现有 Ops 事件。客户端仍收到安全消息；开关关闭时不保存原文。实际 HTTP 状态、流内语义状态和真实上游请求 ID 分开保留。现有日志不足以确认真实 BPS 500 的内部原因；本轮用进程内上游和 Redis 验证恢复，不宣称执行了真实 Excel 请求或生产部署。

错误修复代码再次复核确认了几个不能被来源覆盖的处理顺序：BPS 可恢复终态须先完成恢复判断，再停止整轮期限；原始诊断须在 Ops 首次冻结前保存；工具纠错错误应使用该次纠错的请求 ID，账单标识与之分离；心跳已提交 HTTP 200 后的账号池耗尽仍按实际失败状态和稳定错误码记入 Ops。对应回归覆盖 HTTP/SSE 与 WS 的共享处理链，详见 [再次复核记录](DUAL_PATH_REVIEW.md#错误修复代码的再次复核2026-10-12)。

## 明确过载错误的分类修正

错误 #13949 的独立诊断已经保留真实 HTTP 200，以及 SSE 错误 `code=server_is_overloaded`、`type=service_unavailable_error`。协议包此前只识别 `overloaded_error` 和 `service_unavailable`，这两个精确标识均未命中，归为未知 502，导致现有安全恢复不接收该失败。现在只在原分类表补齐两种标识并映射 503，规范化保留已识别的 `server_is_overloaded` code；不根据自由文本猜测可重试性，也不把所有未知 502 加入重试。

HTTP/SSE 与 WS 共用现有 Forward/handler 账号切换流程：尚未提交内容且请求满足执行安全检查时可在原预算内切换账号；已交付内容、未知工具副作用、取消或明确加密拒绝仍禁止透明重放。全池过载保留 503 与既有 WS 耗尽关闭语义，不降低模型、不禁用账号、不新增重试器或配置。真实 HTTP 状态、错误详情、上游请求身份与实际已报告用量继续沿用现有记录。

## 流尾与断流诊断修正（#14164）

旧记录中的 unexpected_eof 同时可能来自真实正文读错误和转换器发现缺少终态，不能据此判断网络位置、实际上游 HTTP 状态或客户端是否已经收到内容。sequence_number=0 也不能证明没有先前输出，因为网关补发失败事件此前总从 0 开始。

本轮回归确认共享 SSE 读取器在正文尾部有完整 JSON、但缺少事件结束空行且伴随读错误时，会先返回读错误而丢掉已收到的终态。现在沿用普通 EOF 时的尾帧处理规则：先处理完整 JSON；已验证终态优先于晚到读错误。截断 JSON 保留原 I/O 错误，非终态或单独 [DONE] 仍不能判成功；16 MiB 限制不变。该读取器同时用于主要流、工具纠错和图片 compact，均需保留此边界。

HTTP/SSE 与 WS 共用的失败补帧延续已交付事件序号，无 ID 的上游 response.failed 在规范化时也保留序号。没有真实响应 ID 时继续使用请求级 error，不伪造续聊锚点；实际观察用量仍经原 join/计费机制保存。未收到终态的已发送请求仍不自动重放，不引入新的账号切换策略。

原传输诊断复用现有 Ops 事件，补齐该次 HTTP 状态、请求 ID、账号及代理归属；在关闭并 join 转换器后、冻结 Ops 前记录。内部错误标记将正常正文 EOF 缺终态与真实读取错误区分，保留原 errors.Is(io.ErrUnexpectedEOF) 兼容性。限定字段记录结束类别、转换后最后事件类型及已读事件数、内容提交/语义输出/真实 ID 观察状态和耗时；事件类型采用固定白名单，不保存提示词、输出、工具参数或原始网络错误文本。transport 阶段使用实际累计尝试编号。
