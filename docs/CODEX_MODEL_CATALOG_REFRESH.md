# Codex 模型目录更新方案

## 当前行为与本次修复

`/keys` 的 Codex 默认配置立即包含 `model_catalog_json = "~/.codex/codex-models.json"`。开启弹窗、切换密钥不触发网络请求；用户手动获取、下载目录，并保存到该路径。

已补齐 GPT-6.1 Sol 的型号识别、模型描述、文本/图片输入、五档推理、上下文及官方价格兜底。上游明确声明的能力继续优先，不把本地默认值强行覆盖到第三方提供商。模型广场展示应用分组或个人倍率后的价格和独立的官方参考价；按响应模型计费的渠道保留最终费用条件说明。

GPT-6.1 Sol 的标准价格为每百万 token：输入 $2、输出 $10、缓存读取 $0.10、缓存写入 $2.50。超过 272K 输入的请求，输入及缓存费率为 2 倍，输出为 1.5 倍；Fast 为标准价格的 2 倍。动态价格字段缺失时补充已核实的官方规则，显式设置为 0 时保留零价。来源：[OpenAI 模型文档](https://developers.openai.com/api/docs/models/gpt-6.1-sol)。

## 新模型发布后的优化建议（尚未实现）

当前 `openai_codex_models_handler.go` 在已有本地模型映射时会优先调用 `BuildGroupConfiguredCodexModelsManifest` 并提前返回。该路径使用已保存的账号元数据及内置默认值，手动“获取目录”不等于实时更新所有上游能力。单纯补一个型号只能修复该型号，不能解决后续新模型的问题。

建议将模型准入与能力更新分开，保留现有白名单、映射和跨账号能力交集规则：

1. **手动刷新元数据。** 用户点击“获取目录”时，以有界超时获取可用上游的原生 Codex manifest。普通页面加载仍使用本地数据；不增加后台刷新。
2. **按字段合并。** 能力来源依次为同一模型、同一提供商的有效原生 manifest、账号元数据快照、经过核实的型号默认值。不能将普通 `/v1/models` 的 ID 列表视作完整能力声明，也不能通过型号前缀复制其他模型的推理档位、提示词或上下文。
3. **处理新型号。** 上游原生目录字段完整时，无需为新增 ID 修改程序。缺失字段仅从可独立更新、带来源与版本的能力资料补全；仍未知的字段采用保守值并在管理界面说明，避免声称“不支持推理”或凭空赋予 Ultra、图片能力。
4. **校验后发布快照。** 校验模型 ID、字段类型、默认推理档位是否在支持列表内、上下文是否合法及客户端必需字段。记录来源、获取时间和版本/ETag；失败时继续使用同一账号和分组的上次有效快照，不能用空响应覆盖成功数据。过期状态应可见。
5. **应用本地权限。** 新发现的模型先进入能力资料，最终导出的目录仍受账号限制、分组白名单和映射约束；新增上游型号不等于自动向全部密钥开放。
6. **价格独立更新。** 能力 manifest 与价格目录分别维护、验证和缓存；渠道/分组自定义价格及显式零价不会被官方资料更新覆盖。导出目录与模型广场使用相同的模型身份。

网页下载不能直接覆盖用户的 `~/.codex/codex-models.json`。用户保存并替换文件后，应重新启动 Codex 加载新目录。若需要自动写入本机文件，另行提供由用户主动执行的本地脚本或 skill：先验证 JSON，再原子替换，失败保留原文件。

验收应覆盖新型号无代码发布即可入目录、已有能力不被降级、刷新失败保留快照、权限变化不泄漏模型、切换密钥不复用其他分组数据，以及显式零价和官方价独立展示。
