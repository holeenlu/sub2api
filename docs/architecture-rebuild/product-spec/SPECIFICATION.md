# sub2api 全站总体功能规格

最终前端源码已停写并冻结为 `e5a6080563419821daef5eb96e29a95b95f8d80c722b2f8af68dca762878277d`（2009文件、18,901,651 bytes）。c2维护35路径的退休、显式模型、metadata与类型修复已应用；完整测试/双构建的真实输入保留63fe，按唯一测试类型补丁的等价证明复用于e5，五项static直接绑定e5。当前catalog为753用例、92页面、51面板、10管理设置tab，业务定义全部not_run；后端及联合Docker/UI/外部验收尚未完成。

版本 1.1；日期 2026-10-26。本文供产品评审、多人开发、接口协作和测试设计使用，描述本版前端所提供的功能及其服务端依赖。它不新建接口、不扩展角色权限，也不替代架构、协议或验收状态的权威记录。

## 1 产品范围

sub2api 提供公共接入资料、用户自助控制台、管理控制台和独立供应商门户。用户通过控制台取得接入凭据、查看服务目录与用量、购买及管理订单；管理员配置资源、访问策略、价格和运行控制；供应商在服务器授予的范围内管理资源与结算。实际生成、协议转换、调度、上游授权及账务提交由后端执行。

四种界面共用同一项目源码、身份与请求基础设施。主站与供应商构建选择功能角色；部署镜像/容器标识来自部署配置，网站 Logo、名称、展示 API 链接等来自现有网站设置。一个部署实例的一份网站配置不等于新增按 Host 切换的多租户品牌系统。

### 不在本规格中重新定义的事项

- 后端网关完整协议与恢复状态机、账本事务及多实例租约规则，继续由 [PROTOCOLS](../PROTOCOLS.md)、[CONTRACTS](../CONTRACTS.md)、[DATA_AND_CONFIG](../DATA_AND_CONFIG.md) 负责。
- 不增加微服务、微前端、另一套授权系统、通用 capability/revision API、品牌专属业务分支或新的支付/账务解释器。
- 不恢复旧在线下载升级/回滚写链、退役票据绑定/自动登录 Worker、赞助推广或额外产品准入。许可证、必要来源及已应用历史迁移保留。
- 不将真实第三方授权、付款、上游生成或生产环境结果写成当前已验收事实。

## 2 角色与访问模型

| 使用者 | 可进入的范围 | 权限来源和限制 |
| --- | --- | --- |
| 匿名访客 | 允许公开的首页、文档、登录注册、法律文件、特定支付或 Key 查询入口 | route 的 requiresAuth=false 仅决定页面入口；具体查询仍可能需要独立 proof、Key、验证码、开启的功能或待完成认证上下文 |
| 普通用户 | 自己的仪表盘、Key、用量、订阅、购买/订单、个人资料及被允许功能 | 登录态及服务端资源归属；不因可见页面获得他人的 Key、订单或账号资料 |
| 普通管理员 | 服务端 admin_pages 精确允许的页面 | 同时受 permissions、admin_write_fields、policy_version 和服务端操作校验约束；页面可读不等于字段可写 |
| 超级管理员 | 管理工作台及完整设置工作区 | 仍遵守合规确认、step-up、对象合同、幂等及后端保护，不自动取得任意第三方授权 |
| 供应商使用者 | vendor_level1 / vendor_level2 在专用 origin 下授予的资源、关系和结算范围 | 同时校验真实角色与供应商上下文；不能仅凭路径、构建开关或浏览器传入 vendor ID 扩大范围 |
| 供应商平台管理者 | super_admin 在专用门户的 platform 工作台和 profile | 供应商角色不进入 platform；一级供应商的下级管理属于 children/child-*/payables，不能与平台管理混为一谈 |

登录恢复必须先确认当前身份和有效范围。无权限时拒绝或转到合法入口；菜单隐藏只改善体验，不能代替服务器鉴权。普通 admin 的策略按现有全局策略表达，不在规格中虚构每个管理员独立保存一套权限配置。

来源：[身份判定与权限](../../../frontend/src/features/identity/model/auth.ts)、[实际应用守卫](../../../frontend/src/app/router/index.ts)、[门户页面分支](../../../frontend/src/app/compositions/vendor-portal/VendorPortalPage.vue)。实际 Router 已接入唯一供应商守卫并覆盖 session/policy 变化，见 [FR-01](../FRONTEND_REVIEW.md)；生产 Router 回归仍不等于 Docker 逐页验收。

## 4 主要业务对象

| 对象 | 前端负责 | 权威事实与特别约束 |
| --- | --- | --- |
| 身份/会话/待完成认证 | 恢复、展示、必要流程与退出清理 | 服务端身份及有效 session；令牌刷新不等于换用户，未完成 OAuth/OTP 不当作已登录 |
| API Key | 建立、编辑、使用指引、分组及限额呈现 | Key 所属用户/范围与配额由服务器决定；一次性明文与历史掩码区分 |
| Account/凭据 | 资源编辑、授权、导入导出、状态及操作 | 平台、凭据方式、执行模式、传输和操作能力分别解释；脱敏字段不能反推出秘密 |
| Proxy | 网络资源管理、检测、质量与关联账号 | URL/认证、到期、归属、检测结果按现有合同；检测失败不伪造可用 |
| Group | 组合准入、资源关联、价格和订阅字段 | 一次既有 Group 命令；字段由各领域投影，不能拆成多次不可回滚保存 |
| 模型/目录/渠道 | 列表、可用性、映射、清单与价格视图 | 请求模型、上游模型、返回模型、计价模型不能合并成一个未说明的值 |
| 订阅/套餐 | 额度、有效期、分配或购买入口 | 套餐定义、用户订阅和订单分别有自己的 ID 与状态；不因 UI 成功 toast 视为已授予额度 |
| 订单/支付意图 | 选择支付方式、恢复原订单、查状态与退款入口 | 以服务端订单状态为准；SDK 返回、popup 关闭及浏览器重定向不是付款完成证明 |
| Usage/费用 | 查询、聚合、图表、导出和获授权清理 | 未知/零/下界/结算中分别显示；浏览器不自行结算或推定免费 |
| Job/产物 | 提交、进度、取消、结果与下载 | 任务和产物归属独立校验；关页面不代表后台已取消 |
| Vendor/关系/结算 | 授权范围内的资源与往来工作台 | 父子关系、权限、结算主体由服务器给出，不能用 UI 选择替换真实归属 |
| Settings/revision | 草稿、脏字段、校验、冲突审阅 | revision 只用于已存在该合同的端点；不同独立命令不能共享一个虚构全局版本 |
| 公告/自定义页面/品牌 | 内容编辑、展示和可见条件 | Markdown/URL/iframe 遵守现有安全边界；不能携带管理令牌跨 origin |
| 审计/运行事件 | 查询和定位问题 | 观测日志、执行状态、输出交付与账务状态分别使用服务端事实 |

各对象完整字段、枚举、校验和端点定位在对应功能章节及其源 DTO 中维护。本文不将局部字段摘要冒充新的服务端 schema。

## 5 跨领域业务流程

### 5.1 用户接入

1. 访问当前站点允许的注册/登录入口，完成验证码、邮件或第三方认证所要求的真实步骤。
2. 恢复用户身份、角色和有效策略；配置尚未加载与明确关闭分别处理。
3. 在允许分组中建立 Key，按一次性明文规则保存，并从站点配置取得展示网关地址和客户端配置。
4. 客户端向网关发起请求；控制台随后展示服务器记录的用量、额度和费用。文档示例不证明真实上游请求已成功。
5. 登出、换会话或策略变化时清除关联私有状态，旧请求不能将数据写入新身份。

### 5.2 管理资源和分组

1. 在页面、操作和字段权限内建立/导入 Account 或 Proxy；每种平台/授权流程仅使用其有效字段。
2. 配置分组的准入、映射、价格和订阅字段，前端各领域校验并组装原有一次保存。
3. 需要敏感授权时，step-up 绑定原 actor、目标和 payload；取消或换目标后不继续发出旧写命令。
4. 查询、探测和运行结果按真实状态展示；配置存在不等于实际能力或上游资格成立。

### 5.3 购买、付款与权益

1. 读取当前可售套餐、充值条件、允许的支付方式和 Provider 配置。
2. 创建订单并保存当前恢复所需的最小上下文；发生结果未知时先查询原订单，不新建替代付款。
3. 根据订单真实状态进入支付 SDK、二维码、跳转或只读结果确认；取消、退款等非待付款订单不能重新进入付款流程。
4. 用户/订阅/用量视图读取服务器完成后的变化；订单、权益和账务各自保留权威状态。

### 5.4 设置变更

1. 超级管理员读取完整设置及 revision；普通管理员读取其允许的委托投影。
2. 聚合面板只形成字段级脏草稿，各领域执行真实校验，再一次 PUT 提交原 revision 与实际修改字段。
3. 409 保留草稿，读取最新值并展示差异；明确审阅后合并，不能自动用新 revision 重放旧快照。428 重新读取合法 revision。
4. 未知写结果不视为成功或未执行；允许查询核对，禁止盲目自动重发。
5. SMTP 测试、Provider 实例、角色权限、备份、插件等独立操作走各自权限和命令合同，不由全局保存重复执行。

### 5.5 供应商和异步作业

供应商使用专用 origin 和服务器确认的 scope 管理资源、下级关系与结算；切 actor、供应商或资源目标时撤销旧页面状态。异步图片任务的创建、轮询、取消和产物下载分别保留授权及结果归属，不能根据前端等待结束推断后台工作或费用已结束。

## 6 共同行为规格

下表是共同验收要求，不表示每个入口已经满足。供应商守卫、账号优先级快捷写与退款资格的源码修复和未验收边界见 [复核处置](../FRONTEND_REVIEW.md)；具体入口的现状和例外在领域章节说明，不以通用条款覆盖实际缺口。

| 编号 | 行为与验收要求 |
| --- | --- |
| FS-COM-01 | 页面必须区分加载、空数据、失败、权限拒绝、未配置和未知状态；不能把失败装作空列表或以零补未知事实 |
| FS-COM-02 | 查询捕获身份、必要业务 scope、目标及筛选；新查询、卸载和身份变化取消旧等待，并用序号/范围拒绝晚到结果 |
| FS-COM-03 | 写命令固定原始目标和输入；有界 step-up/刷新重试也只能继续该意图；相同用户的新会话、权限变化或目标失效必须重新判断 |
| FS-COM-04 | 本地 Abort 只表示不再等待/发送，不代表服务端回滚；结果不明时沿原幂等/查询合同核对，不能另起扣费或付款 |
| FS-COM-05 | 列表分页、排序、筛选及导出按实际端点合同；过滤条件改变时不能混用旧游标/ETag/选择集；大范围选择须明示并冻结范围 |
| FS-COM-06 | 数值保留 0、false、null、空串、省略字段的各自语义；金额/配额/时区按原合同处理，不统一 normalize 成默认值 |
| FS-COM-07 | 密钥、授权凭据、一次性 proof 不写日志、导航元数据或普通偏好；记录证据必须脱敏，测试凭据仅存隔离私有 fixture |
| FS-COM-08 | 管理请求、匿名订单/Key 查询、供应商请求和第三方 SDK 保持各自凭据边界；展示 api_base_url 不替换管理客户端 base URL |
| FS-COM-09 | 菜单、标题和面包屑投影消费同一导航贡献；保留有消费者的 redirect/alias，实际授权继续由服务器执行 |
| FS-COM-10 | 简体中文、繁体中文、英文、日文保持有效键与回退链；业务语言贡献由领域拥有，台湾文案沿唯一生成器处理 |
| FS-COM-11 | 键盘、label、禁用态、错误反馈、焦点环回/恢复及窄屏应覆盖实际页面；隔离基础件测试不替代全站可访问性验收 |
| FS-COM-12 | 入口/领域页面和重型面板使用现有动态加载；性能需同环境实测，不能以构建成功、文件变小或静态断言代替浏览器指标 |
| FS-COM-13 | bootstrap 拥有 HTTP、领域服务、预加载和 Pinia 生命周期；失败、重复挂载及卸载必须释放本次资源，不解除新宿主的配置 |

这些共同条款通过既有 transport/lifecycle/security/authorization/routing/i18n/accessibility/performance 等用例关联；具体追踪见附录，不重复建立测试执行平台。

## 7 错误与冲突合同

| 情况 | 用户可观察结果 | 禁止的处理 |
| --- | --- | --- |
| 401、可刷新 session | 当前有效身份下沿既有一次恢复或转登录 | 无限重试、换身份重放写请求 |
| 403/字段拒绝 | 清楚拒绝；必要时刷新策略并重新核对范围 | 自动提升权限或绕过隐藏字段 |
| STEP_UP_REQUIRED | 对原意图进行现有验证，取消保持取消身份 | 关闭/换目标后仍发旧命令；验证一个动作后自动批准任意动作 |
| 423 合规未确认 | 通过明确应用回调展示现有确认流程，保留登录态 | 自动替用户接受承诺、把该错误当作密码失效 |
| 设置 409 / 428 | 保留草稿并比较/重新读取 revision | last-write-wins 全量覆盖、虚构合法 revision |
| 字段校验失败 | 保留输入并给出可定位反馈 | 丢弃草稿或仅写 console 后显示成功 |
| 网络中断/超时/未知提交 | 保留结果未知，使用原对象查询/幂等核对 | 把取消或超时解释为服务器未执行 |
| 429/503 | 展示真实限制/暂不可用，仅按现有有界可取消策略恢复 | 对所有方法统一自动重试 |
