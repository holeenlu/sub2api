# 开发者快速接手

先确认本次收到的是开发指令；本文档包本身只完成开发准备，不自动启动代码工作。

具体起步和协作顺序见[实施启动手册](IMPLEMENTATION_PLAYBOOK.md)；语言级细则以[编码规范1.3](CODING_STANDARDS.md)为准。

## 第一小时应得到的结果

- 读README、需求表、CONTRACTS、CODING_STANDARDS、BRANDING和自己的work-items条目。
- 确认真实HEAD、当前AGENTS、相关主分支后续改动和合同版本。
- 跟踪该包一次成功与一次失败调用链，写明原入口、副作用、状态、结算及退出点。
- 确认允许写集和共享修改由谁完成，选出现有相关夹具与最小验证命令。
- 在自己的工作包写清最小完整切片和旧路径删除目标，再开始改代码。

不要先全量跑测试、全量复制依赖、创建新的调度/验证脚本，或用目录搬家代替调用链迁移。

## 当前代码中的重要提醒

1. OpenAITurnBudget已经跨模式共享，重构应收敛职责而非增加第二份总预算。
2. openai_ws_mode描述客户端入口；上游ctx_pool、http_bridge、BPS、Cloud必须分别核对。
3. Cloud最新parser与能力计划已在基线中，迁移它而不是恢复之前分散解析。
4. UsageRecordWorkerPool.Run首次在返回前执行；持久化事件恢复不能降成内存异步日志。
5. 请求/出站/返回/计价模型已部分区分，先迁移现有规则，不重复再做一套。
6. 当前authz、payment、securityaudit、frontend/features已存在，优先保留并调整边界。
7. 有效外部协议和历史数据合同可以保留；过渡wrapper与重复内核必须随切片退出。

## 资料真实性

源码存在、测试存在、测试通过、真实上游通过是四种不同事实。现有夹具需标注来源和覆盖；没有完整真实交互时，把缺口写入READINESS/对应任务，不能补一段示例并宣称已验收。

遇到不清楚的兼容项，记录调用方、输入形状、旧实现、目标模块、保留原因和退出条件。没有证据时不随意删除仍可能属于明确需求的路径，也不添加无限期兜底。

品牌相关工作先区分技术项目sub2api、部署参数和网站设置；广告清理不能触碰许可证、必要署名、账务/会话身份或仍有效的业务功能。

前端任务额外先读[FRONTEND_ARCHITECTURE](FRONTEND_ARCHITECTURE.md)。WP-21不是全src写授权；WP-28至35按JSON分离写集，shared/app/旧根出口由指定单写者接入。不要把跨域业务复制进shared，也不要将旧巨型页面整体改名为composable。
