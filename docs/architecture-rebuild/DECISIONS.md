# 架构决策记录

| ID | 状态 | 决策和原因 | 代价与替代方案 |
| --- | --- | --- | --- |
| ADR-01 | 设计已定 | Go/Vue/PG/Redis模块化单体；先改依赖与所有权 | 暂不通过微服务解决组织问题；未来拆进程需容量/隔离证据 |
| ADR-02 | 设计已定 | execution 唯一拥有预算、业务重试及生命周期；provider执行一次尝试 | 核心必须保持平台无关；不能把所有协议字段塞回核心 |
| ADR-03 | 设计已定 | 同协议保留wire，旁路facts；跨协议才纯转换 | 需要清晰内存寿命与字段保真合同，不能用万能DTO抹平语义 |
| ADR-04 | 设计已定 | 发送/交付/usage三轴独立，ambiguous默认不跨账号重放 | 某些现有恢复合同需单独证据；不能用全局新开关静默撤销 |
| ADR-05 | 保持现行 | 复用现有幂等账本、持久化恢复、价格规则及余额豁免边界 | 改领域调用，不先换表或异步事务；保持旧键和累计usage语义 |
| ADR-06 | 设计已定 | 请求快照固定策略，撤销/资格/租约在发送边界复核 | 外部发送不能与数据库撤销做全局原子事务；明确检查点和迟到撤销行为 |
| ADR-07 | 设计已定 | 会话归属、actor、共享索引、socket分开；epoch防止旧owner写入 | 不能承诺无合同的透明接管；lease失效后有界取消并保留账务事实 |
| ADR-08 | 设计已定 | Group/Account先编译领域视图，真实必要时再改存储 | 外部聚合名称可保留；旧解释器不能长期与新解释器并存 |
| ADR-09 | 保持现行 | Native/BPS/Cloud共用调度和账务，保留各自明确授权与协议合同 | 不自动进行模式降级；不恢复已撤销Cloud独立身份体系 |
| ADR-10 | 设计已定 | 文本、异步任务、双向实时使用不同窄端口 | 不建立万能provider接口；共同副作用仍受相同执行规则管理 |
| ADR-11 | 设计已定 | 每个完整切片单写路径切换，同次删除旧入口 | 纯计划可离线比较；真实业务不得双发、双记账；回退靠受验证版本和数据合同 |
| ADR-12 | 迁移期保持 | 当前官方父提交/定制历史、选择性来源和发布权限作为过渡 | 目标遵循ADR-15统一源码/制品和配置品牌；不在文档任务中删除分支或发版 |
| ADR-13 | 设计已定 | 接口和共享装配单写者，工作包按非重叠写集并行 | 集成者成为必要串行点，优先锁小范围；不以每人一套兼容层消除冲突 |
| ADR-14 | 保持现行 | 复用现有测试/工具/缓存；按实际风险补独立验证 | 文档不触发业务构建；实现时不能用单测冒充真实上游验收 |
| ADR-15 | 用户明确要求 | 技术项目统一sub2api；部署标识参数化，网站品牌与公开API链接走设置；清理无关广告/赞助 | 复用已有设置，逐部署迁移旧fallback/挂载；同角色制品跨品牌复用，必要许可与署名保留；见BRANDING |

## 决策变更格式

记录：涉及ADR/REQ/CT、当前行为证据、备选、选择、行为与数据影响、受影响消费者、必要测试、已存在授权或需要用户决定的具体问题。契约版本变更由主集成者统一发布；消费者不得私自建立CT-v2绕过评审。
