# 契约变更与消费者核对模板

本记录用于已有工程变更协作，不增加人工批准流程；普通实现选择由既定owner在授权内决定。改变明确产品/权限/计费合同才按现行规则处理。填写后更新CONTRACTS及相关工作包，不保留平行CT-v2。

- 变更关联：WP / REQ / CT / ADR / 当前合同版本。
- 问题证据：实际源码SHA、入口、输入、当前结果；说明已有合同为何不能承载需求。
- 变更范围：内部签名 / 外部API / 持久化 / 纯文档澄清，分别标明。
- 唯一写者：合同owner、实现owner、共享文件集成者及具体允许路径。
- 输入输出：类型、字段、单位、缺省/null/零值、开放/封闭枚举、敏感性。
- 调用时序：准入、发送/提交、返回、取消、重试、幂等、清理及迟到结果。
- 错误合同：稳定分类、是否可重试、是否已产生副作用、日志/观测归属。
- 资源合同：谁创建/接管/释放；失败、取消、超时、关闭的负责方。
- 数据合同：事务、版本/并发、旧读者、历史数据、回退边界；不擅自执行迁移。
- 消费者清单：每个实际调用方、工作包、修改点、验证证据与当前状态。
- 旧路径处置：保留的真实调用者及退出条件，或者同切片删除的入口/字段/helper/测试。
- 验证：受影响AT与最小命令；未运行/真实材料缺口分别标明，不填估计passed。
- 结果：采用的方案及理由、合同版本是否变化、已同步的文档/类型/消费者。

对于仅补充语言写法或任务资料、未改变输入输出语义的变化，更新相应文档版本即可，不能为了制造进度强行升级CT版本。类型声明由所属实施工作包交付并编译；此模板不是生成代码或自动修改客户端的入口。
