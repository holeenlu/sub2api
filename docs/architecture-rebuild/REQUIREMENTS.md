# 范围 需求与追踪

本文是需求编号的唯一来源。状态：开发设计基线；不是实现完成或运行验收。参考源码基线见 BASELINE.md，工作包关系见 work-items.json，验收见 VALIDATION.md。

## 本轮范围

本轮只交付工程资料：目标架构、决策、领域/接口合同、数据与协议清单、任务依赖、协作交接、迁移删除和验收资料。不新增运行代码、接口、运行配置、数据库迁移、部署或产品验证准入。资料属于三个品牌共享；技术项目统一为sub2api，网站品牌和部署标识参数化；当前分支/渠道仅作为迁移期交付安排，详见BRANDING。

目标实现保留 Go/Vue/PG/Redis，先采用模块化单体。通过依赖、状态所有权和副作用边界改造当前系统。实际开发按完整垂直切片迁移，不把另三个项目接成旁路服务，不建立长期双引擎。

## 非功能目标

- 正确性：重复账务事实最多产生一次既定账务影响；不同事实不能共用同一幂等键悄悄覆盖。只保证本地幂等，不声称上游 exactly-once。
- 安全：默认拒绝失效或不明确的授权；记录必要身份与摘要，禁止凭据明文和敏感输入扩散至公共日志。
- 可恢复性：声明每份状态的权威来源、持有者和恢复方式；owner 死亡不等于 socket 可迁移。
- 资源：继承现有有效预算、body/帧限制和缓冲上限。并发、队列、排空、保留时间没有无限默认；不凭设计假定新的数值更好。
- 性能：执行前记录相同负载、部署、协议、工具链的 TTFT、吞吐、内存、取消耗时、账务恢复与队列基线。未测得阈值标为待测，不编造提速百分比或SLO。
- 可维护性：同一业务规则只有一个权威实现；新增普通provider不改核心平台分支；差异可由独立契约测试验证。

## 明确不做

本轮不开发产品代码；目标架构不先拆微服务/数据库、不更换语言、不另建消息平台或验证系统、不引入VM/guest/自动登录Worker/Mihomo/票据治理、不把新接口或开关当作旧路径保留理由。

## 优先级与变更

身份、安全、账务、旧客户端/数据合同为阻断性不变量。部署形态、包名、界面布局可在不改变合同前提下演进。发现需要改变明确产品行为时，按 DECISIONS.md 记录证据和影响，由主集成者确认是否已有用户授权；不能以重构名义自行扩大范围。

需求变更同步修改对应契约、工作包与验收条目，删除失效描述。不要复制这张表到其他文档形成多份规则。
