## 诊断与量化

新增三种结构化事件，复用现有日志链路，无新增数据库列或 HTTP 接口：

- gateway.cache_route：独立 correlation_id、routing_fingerprint、客户端类别及实际选号结果。选号记录不表示一定已发送或已计费。
- gateway.cache_prefix_transform：在 HTTP 最终 body / WS payload 边界记录 model、system/instructions、tools、reasoning、text 的指纹。对象键顺序不影响指纹。它不覆盖完整历史，不把变化自动认定为缓存 miss；没有入站指纹的 WS 路径明确标记无法前后比较。
- gateway.cache_usage：原始用量与结算分类分列，异步记账仍保留关联上下文。零计数标记为零或未取得用量，不能据此认定上游免费。

客户端类别来自 UA，只用于诊断分组，不能作为可信客户端认证。日志只记录身份与前缀摘要，不记录完整 prompt、工具参数或凭据。日志保留时间由现有日志设施管理；没有修改历史账单，也不能从旧结算行还原被覆盖的原始 usage。

离线分析入口：

    python3 tools/analyze_gateway_cache.py --window-seconds 3600 gateway.jsonl

输出按客户端类别与入站协议分组的 token 加权缓存占比、选号切换率、路由键变化率、同账号同模型的出站前缀变化次数及换号后首个已观测请求的缓存占比。缺少显式会话或有效时间戳的样本保留为未知，不伪造连续会话。上游 request ID 相同的用量记录按账号和 API Key 去重，后到的终态快照替代早期快照。

缓存占比使用原始互斥桶：read / (uncached + read + write)，不叠加 write 的 5m/1h 子项，不用优惠后的缓存 token，不平均每条请求百分比。分母为零时输出 null。

**修正的反例：** 同一真实会话 H1/A → H2/B → H3/C，按路由键分组会算出零换号；分析器按独立 correlation_id 统计，得到两次路由变化和两次选号切换。

## 验收用例

- 连续十轮、缓存断点移动、跨 API Key、显式会话分离与 compact 后的身份稳定性。
- 普通 Responses 和兼容入口：公开 API 保留缓存字段，OAuth 继续执行端点限制。
- 非 ASCII/带引号名称的合法别名；JSON 与多行/CRLF SSE 往返；普通文本与工具参数原样保留。
- 1h 实际用量经过 JSON/SSE 后仍为 1h；强制缓存优惠与 5m 结算不修改原始 ForwardResult。
- 不同状态存储实例共享来源；同会话旧 blob 不被最近账号覆盖；同本地账号换凭证及 WS 握手归属检查。
- 异步 worker 的诊断上下文传递；分析器的变键反例、未知身份/时间、去重、加权和时间窗口。

## 线上验收边界

本轮使用本地替身、实际本地 socket 与单元/回归测试，没有消费真实供应商额度。生产费用变化仍需受控流量：固定模型、账号/凭证、effort、工具和任务；分别冷启动及热缓存；避免直连先预热代理的污染；按实际时间窗口核对供应商用量。订阅额度、API 单价估算与平台扣费是不同量，不能使用未经复核的历史拟合系数宣称普遍的 15 倍或整体 1.6 倍损失。

## 30m/12h 缓存计量与亲和修复（2026-10-22）

本次是三个品牌共享修复。沿用已核实的 Codex 源码行为：稳定 cache key / session-id、前缀验证和 previous_response_id；不新增永久缓存开关，不改变旧 TTL 默认值，也不把 WS 连接寿命等同于服务端提示词缓存寿命。

- 自动增量识别支持公开 Responses 的 prompt_cache_options（30m/12h）、旧 prompt_cache_retention（in_memory/24h）和合法 input_text 显式断点；请求策略、断点位置及内容均参与既有相等性判断。策略改变使旧锚点失效，畸形或未知结构保持原文全量转发。预热不作为普通生成轮次。
- HTTP/SSE、WS relay、Responses/Chat 转换共享缓存写入分桶规则；逐轮累计、部分使用量、授权切换及图片重试均携带 30m/12h 组成项。异常分桶限制在上游明确总量内，不从请求 TTL 猜造用量。
- 公开 API 的 12h 写入按现有 30m 写入单价的两倍计算，分桶不重复计入输入总量；Priority、长上下文及现有定价倍率继续生效。管理员渠道/区间显式固定写入价（包括 0）覆盖所有 TTL；Codex 订阅和 BPS 保留既有计费契约。
- BPS 缓存写入按输入计费时，同时清理新的客户端明细及结算分桶，原始观测仍保存在既有诊断事件。未另建日志事件、入口、用户配置或供应商转发路径。
- usage_logs 增加 cache_creation_30m_tokens / cache_creation_12h_tokens 两列（迁移 288）；保持 cache_creation_tokens 为唯一写入总量。旧行默认 0，不推断历史 TTL。所有既有插入、读取、DTO 和共用用量表格展示同步更新；SQL/Ent 的位置契约同步验证。原草稿编号 286 在交付前调整为 288，保留已发布的延迟指标 286 和供应商汇率 287。此迁移需在后续部署时执行，不在本次交付执行生产迁移。
- 账号临时查询错误、单次传输/利润不适配不再当成永久失效删除绑定；明确删除或失去分组资格仍清理。legacy/token-count 路径复用现有 TTL 解析。旧哈希兼容仍有实际迁移调用方，保持既有十分钟上限；旧读/双写关闭且迁移窗口结束后可移除该兼容，不扩成长久并行路径。
