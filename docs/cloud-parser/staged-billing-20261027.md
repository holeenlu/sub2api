## 当前实施合同

- 新根使用冻结快照version4，以客户端响应关闭时已确认、尚未归集的消费形成阶段，账本身份为cloud:<root>/<response_id>，复用现有RecordUsage/usage_billing_events/去重/余额与配额事务。
- 不是每条累计usage通知都扣费。工具交接可能早于usage；未计量响应不编造0消费，等待中出现的计量保留在root，下一次响应关闭归集。一次响应内可能有多次采样，价格按采样边界计算。
- 阶段事实随owner状态原子保存，先入Redis队列后输出完成。已发布阶段不可改写；消费者按同一身份重试。ACK比较实际读取载荷，阶段ACK不把上游turn标成已结算；单独记录阶段/预留回执，避免每次重复查询及过早释放根状态。
- 每个新客户端请求使用自己的现有预留和响应计时；不再把整轮工具等待时长套到单段记录。阶段结算成功后释放其预留；无新计量的工具交接不额外扣按次费用。实际有确认消费的客户端响应按现有按次价格结算一次，区别于旧版整个turn只收一次；同一响应内多次采样不叠加按次费。
- 整轮终态核对阶段覆盖量，不再开总量账单。确认中断的当前阶段可按已测量下界结算；未知执行尾段不转换成已确认费用，先结算以前已确认阶段，再保留未知残量证据。终态后无法确认响应归属的迟到数据仍归档，不自动补扣已结算阶段。
- v1/v2/v3既有根继续旧规则；不把旧账重新拆阶段。旧消费者不能处理version4，不支持新旧消费者混跑验收；上线须先退出旧owner/worker，再启动新消费者。没有在线迁移或历史补扣操作。
- 新增nullable sampling_details列（299迁移），按当前阶段保存真实采样和价格，沿原查询、DTO、导出提供。管理端和用户端共用组件展示，原生/BPS以及历史无证据记录保持NULL。迁移源码随交付提供，生产未执行。
- 计费金额继续采用公共8位小数量化。Token价格不因拆分人为加档；按请求的价格/策略变更按各请求快照生效。小数边界遵循原生逐请求舍入，不能宣称与旧整轮舍入永远逐分相同。
