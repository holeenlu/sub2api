## 已证实缺陷与修复

| 缺陷 | 复现与处理 |
|---|---|
| 关闭 Cloud 只发取消、不等待真实 owner 完成 | 新回归在阻塞初始化未结束时观察到 Close 已返回。复用既有 manager 注册正在准入的请求、创建操作与 actor，关闭准入后取消并等待；超时/保存失败返回未完成，而非假报成功 |
| 持久化与基础设施关闭竞态 | 在现有应用 cleanup 中先 DrainCloud，再停止并行 worker 和 Redis/Ent。actor 在退出前排空终态/迟到计量、保存阶段与账务事实，再等待命令读取、续租和上游读取任务退出。已保存终态以2秒有界上下文交付，存储仍检查请求关闭标记；非终态不允许越过取消。共享worker清理预算为20秒，与HTTP的5秒和容器30秒宽限期配套。保留本轮分阶段结算，不恢复旧整轮扣费 |
| RPC 关闭未等待读取、心跳和实际 socket 关闭 | 现有 RPC 加入可等待的退出状态，内部故障仅通知，不让读取线程等待自身。初始化晚返回不得在停机后创建新 turn。保留既有心跳参数捕获、握手凭据错误分类和大小预检 |
| 正常停机混入通用执行失败/账号恢复 | 使用明确 `cloud_gateway_stopping`；停止中的新请求不允许换账号循环，不误判为上游限流或凭据失效；公共调度健康统计与已确认终态策略均排除本地停机。预期取消不再由命令读取任务伪报路由故障。正常时期已处理的历史 cleanup 错误不污染之后的 drain |
| 容器宽限期不足 | 线上 Config.StopTimeout 为 null，通常落入 Docker 默认10秒，而应用 HTTP+worker 已有独立收尾预算。更新/回滚命令保留至少30秒，已配置更长值则保留；旧更新日志未记录该值时不覆盖其现有 Compose 设置。四份应用 Compose 模板同步默认30秒 |
| 空 reasoning 导致历史条目错位 | 无密文、无可见摘要的 reasoning 占位在比较副本中忽略，兼容客户端/公共 Messages 转换省略空占位；保留原历史。非空密文、可见摘要和其他有效历史仍必须匹配 |
| Messages 桥接的 Read 参数往返冲突 | 公共桥接已有删除 Read.pages 空字符串的行为，Cloud 原来拿未投影历史与其输出比较。实际 Messages 路径复用同一公共规范化函数，只影响比较副本；非空页码、文件路径变化仍拒绝。不凭 User-Agent 放松普通 Responses 的历史校验 |
| 超大条目发现过晚 | 原实现先创建上游 thread 才发现必然无法编码的历史。新增先失败回归后，使用同一预检在创建 thread 前拒绝；空 thread ID 作为大小下界，保证早检查不会新增错误拒绝 |
