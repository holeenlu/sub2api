# Cloud RPC 全链路复核与修复（2026-10-26）

## 范围与判定基准

审查基线为 main 1b88a4afaf5a79323c8e3170635dc07e0a55054f。以原生网关的鉴权、模型权限、调度、取消、错误和账务规则为准；Cloud 只承担上游 RPC 映射、执行归属和客户端工具等待所需状态。本轮不启用账务 v2 写入，不新增授权、模型名单、验证门禁、产品配置或自动协议切换。

按“未发送、已发送且接受未知、等待客户端工具、已确认终态”分析各副作用边界。请求可重试不等于上游执行可重放；客户端响应完成不等于 Cloud turn 已结束；用量未提供不等于零用量。

公开 RPC 契约来源：[OpenAI App Server](https://learn.chatgpt.com/docs/app-server)。公开文档不代替特定 Cloud 主机的能力实测。4 MiB 是既有真实主机探针确认的单消息解码边界，不是整个会话上限。

## 查实问题及修复

| 编号 | 问题与触发条件 | 修复与保留不变量 |

| F1 | 首次历史已分批，但等待工具后追加的消息仍单次注入，6 MiB 请求再次被拒绝 | 所有注入共用同一个分批发送函数；全批预检在回复工具前完成；原子条目过大只拒绝当前请求，保留待回复工具供修正后重试 |
| F2 | 工具执行结束后，新请求沿用已过期的首轮期限；工具目录更新的归档也受影响 | 每个已接纳请求更新当前 RPC 期限；消息注入、工具回复和目录更新沿用该期限；同请求内重试不重置预算 |
| F3 | 压缩等待中断确认期间客户端取消，确认后仍可能启动新的摘要推理 | 确认中断后再次检查请求；已确认用量按原有 lower-bound 规则保存，取消不新增推理或账务根 |

| F9 | 后台已检测 owner 失效，但主循环正在 RPC handler 内等待，下一步仍可能发送 | 既有续租检查登记首个失效，公共请求检查读取该原子状态，在下一副作用前拒绝；不增加鉴权查询、规则或持久状态 |

## 验证与证据边界

先复现大历史续接与过期首轮期限，再增加取消、依赖失败、计数门槛和请求状态故障回归。定向回归覆盖 JSON/SSE/WS、超大原子条目拒绝后的有效重试、密钥服务失败冷却、真实凭据拒绝、请求取消及已确认部分用量。

组合验证覆盖 Cloud、原生/BPS 的相关入口与桥接、共享 JWT 验证和刷新组件、服务/handler/仓储账务契约；对状态和并发改动执行定向 race。实际命令、源码指纹与执行结果由本任务验证回执记录，不以测试代码存在代替通过证据。

本机 Codex 请求与本地 RPC 替身、真实主机的无推理注入探针、生产验收是三种不同证据。真实注入探针不发 turn/start，不发送用户历史，不证明生产 SQL 扣款或真实旧会话的所有工具链均已验收。本轮不发版、不部署、不迁移。

已知且源码未变的 TestOpenAIAccountRuntimeStats_ReportAndSnapshot 计时容差问题单独记录并从组合命令精确排除，不计为通过；其余错误分类和账号调度回归仍执行。

## 清理与开放事项

删除被替代的单次工具续接注入和重复期限赋值；注入只保留一个发送实现。保留实际需要的 v1/v2 账务读取兼容；写入仍为 v1。service_tier 计费映射、D8 完整版、第三级恢复等既有后续候选不因本次复核自动启用。

## 线上搜索与独立原生入口（#62447 / #62451）
