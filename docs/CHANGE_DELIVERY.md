# sub2api 独立重构交付规范

范围：codex/sub2api-rebuild。依据2026-10-25用户新建独立项目分支、多子智能体协作及删除无用旧实现的明确指令。此规范仅作用于新重构分支；维护main及品牌分支的交付历史可在初始提交6f48d6ab6fcc29763af84410690530aeaa957403追溯，本分支不再携带其发布流程。

## 分支与授权

验证通过后默认普通增量提交并推送到holeenlu/sub2api的refs/heads/codex/sub2api-rebuild。只使用完整refspec，不改写main、TapModels或tokensavy。推送前核对实际远端；独立变化先审查，不刷新lease覆盖。提交/推送不授权Release、镜像发布、生产部署或数据库迁移。无需为已授权动作重复确认。

新项目的默认构建为根Dockerfile的独立API角色，运行模板在deploy/api；前端由另一会话负责，完整站点单独集成。不复制维护版的三品牌发布矩阵、旧二进制自更新或Compose updater。

## 工作包与并行

按architecture-rebuild/work-items.json领取明确切片。依赖完成再消费共享契约，已验收子切片不代表父工作包全部完成。前端写集独立；公共类型、路由、Wire、数据契约、根构建和Git索引由明确单一owner操作。主代理审查实际diff和测试证据后整合，不以worker文字结论代替验证。

## 删除无用实现

按完整功能和调用链确定替代范围，同次删除无效代码、路由、字段读写、配置、包装层、专属依赖/测试、构建脚本及失效说明。共享设施仍有实际消费者时保留并列出证据；不因名字含旧项目名而误删有效协议或数据身份。旧实现只在明确迁移切片中暂存，退出条件必须可验证，不能藏在常量false或永远无法开启的开关后。

历史迁移、许可证、NOTICE和必要署名继续保留。代码删除与持久数据删除分开；不自动执行生产迁移或清除历史数据库/缓存记录。用Git历史追索已删除源，不复制一份旧目录留在新项目。

## 最小充分验证

按实际影响选择检查，输入未变时复用证据，不按阶段/提交SHA重复全量。失效项只补受影响验证。

| 变化 | 默认检查 |
| --- | --- |
| 文档 | 链接、JSON/依赖一致性、实际路径及差异；不跑应用构建 |
| 局部Go | 受影响单元及消费者测试，必要静态检查 |
| 权限/账务/调度/协议 | 定向覆盖准入、失败、取消、恢复、归属及幂等，不自动全仓升级 |
| 并发/锁 | 在相关功能测试上补定向race |
| schema/SQL | 受影响真实数据库检查；未改持久化不用启动额外数据库 |
| 构建/部署 | 实际角色编译、必要镜像/启动/持久化验证，隔离实例，不触及生产 |
| 前端 | 对应会话执行实际测试/构建/浏览器验证；后端不能代报通过 |

Go按backend/go.mod选已安装SDK，复用共享依赖。现有tools/change_delivery.py的validate和validation-status可记录输入/工具链指纹并复用证据；协作编译锁为Git common-dir中的sync-upstream.lock。并发占用有界等待，不删除锁文件或杀其他任务。所有GitHub工作流保持人工workflow_dispatch；不自动触发或等待远端CI。

对于本地工具不兼容，记录具体错误与未覆盖项，完成可用的独立检查；不得把未运行检查记为passed，不能偷偷改业务语义、降低标准或升级整个项目依赖来掩盖问题。真实上游、替身、静态检查和本地部署分别描述。

## 协议变更证据

先核对客户端完整报文、入口、跨轮续接、取消/失败、输出及账务链；对照Native/BPS/Cloud既有有效合同。未知、空值、零和未收到终态分别表达。新增真实验收缺口只阻断依赖该证据的切换，不新增产品准入或额外验证平台。

## 本机编译与部署数据收尾

开始前记录本任务临时目录、缓存、二进制、容器、镜像和卷归属；SDK/源码/其他任务资源受保护。GOTMPDIR和完整日志使用任务独有目录，成功后删除临时二进制、日志、测试数据库/卷/网络和不再使用的任务镜像；保留简短证据和正在开发的源码。

共享Go编译缓存上限8 GiB，普通依赖缓存合计上限5 GiB（SDK单独保留），Docker构建缓存上限5 GiB。前后实测，未超限可复用；超限只清理确证本任务拥有且未被使用的记录，不按名称/时间猜归属、不全机prune、不删除他人缓存或SDK。不能安全清理时如实报告未完成。

删除目录前核实最近Git根和跟踪文件，不使用宽泛git clean/reset或按扩展名删除源码副本。Docker删除使用本任务明确项目/资源ID；共享缓存清理需结合真实构建命令、父记录及当前占用证据。清理后重新核对源码、临时路径及资源容量，不能只报告执行过命令。

记录源码提交与推送远端SHA、已完成切片、业务/测试增删、接口/配置/路径变化、实际测试与限制、删除清单/共享保留依据、前端交接及资源收尾。第一波通过不代表完整重构完成。历史变更与当前有效项目规则区分，不重新引入维护版发版平台。
