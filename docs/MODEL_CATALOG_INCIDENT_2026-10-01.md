## 2. 对已有分析和修复的复核

| 项目 | 判定与处理 |
| --- | --- |
| legacy 白名单在界面显示成 fixed | 真问题。最初验证了 Claude 的模式区分修复；随后按用户的新业务约定移除策略下拉框，保存统一使用表单勾选名单，不再让用户选择 legacy/follow/fixed |
| 打开/保存一定迁移了分组 | 不能这样断言。旧表单只显示错值，原状态仍可能是 legacy；选择其他模式再切回等交互会触发实际迁移。生产缺少历史操作证据，不能确定是谁何时切换 |
| OpenAI token 刷新失败回退存量 token | 保留。能避免刷新暂时失败时立刻终止发现，但存量 token 也可能已过期；最终 401/403 仍必须生效。它不解释 Anthropic 的缓存范围错误 |
| `catalogRefreshManaged.Store(true)` 应撤回 | 不改。关闭自动同步也必须关闭旧价格周期轮询；手工同步继续工作。原文档与实现矛盾已修正 |
| Admit 成功但 AccountModels 一个账号都没有 | 不是当前解析器的正常输出：只有存在账号供应路由才生成条目。之后精简缓存校验、限流、额度、票据等仍可淘汰所有候选号 |
| 将分组改为“不限制”恢复 | 不作为通用恢复方案。它会取消组白名单，扩大权限；而账号自己的 fixed/follow 仍会校验，所以还可能不能恢复 |

## 3. 本次补充修复

1. **调度缓存范围失配**：`scheduler_cache.go` 对 fixed/follow 策略账号批量加载已有完整缓存，再校验凭据范围。兼容策略保留精简路径；缺少完整缓存触发数据库回退，不用精简数据伪造获权。Anthropic/OpenAI × fixed/follow 四种回归在修复前全部失败，修复后通过。无需清空 Redis 或迁移数据库。
2. **固定声明与明确撤权的边界**：此前未提交的固定供应改动允许缺少/过期的发现快照，但也会越过 `authentication_unavailable`。现在明确认证失败仍拒绝；临时上游故障/目录过期不撤销管理员固定声明。保留已移除、停服和排除规则。
3. **普通 OpenAI 调度遗漏检查**：高级调度已有目录检查，普通调度的候选刷新与最终复核不完整。补齐新策略账号的发布/撤权检查，避免不同调度方式产生相反结果。
4. **准入报价混用新旧版本**：价格解析已固定本次版本，但就绪检查读取实时价格，更新价格时可误放行/误拒绝。改为读取同一请求的价格版本；新增“补价后旧请求不能提前放行”和“删价后旧请求保持原价”回归。
5. **配置资料中的停服日期**：手工配置型号没有发现快照时，也执行已保存的停服日期，不能把它重建成 unknown 从而重新开放。
6. **轮次隔离**：一次新的准入先清除旧轮准入上下文，兼容模式不会继承上一轮的路由限制。这是合同边界修正，未认定它是本次生产触发点。
7. **可诊断性**：细分目录读取失败、无发布路由、价格未齐；服务端保留 request ID 等非凭据字段，客户端仍使用兼容的 503。

## 4. 统一业务原则

详细页面职责、流程图和策略表见 [模型目录与价格同步](MODEL_CATALOG.md)。运营流程应为：

1. 同步上游资料，形成候选，保存能力、来源、时效和参考价。自动或手工同步都不修改管理员的权限决定。
2. 账号声明供应范围。固定列表以 `extra.model_catalog_policy.models` 为唯一权限来源，`credentials.model_mapping` 只负责别名；账号名单留空表示全部接受；存量未重新保存的 follow 才要求有效发现证明。
3. 分组决定对外开放范围。新版编辑页仅按勾选名单开放，空名单拒绝全部；所有供应商语义一致。存量 follow 是历史兼容，保存勾选结果时转换。两层名单互不替代。
4. 渠道完成名称路由与销售价卡，分组可覆盖售价，再应用有效倍率；明确零价格与缺失值分开。
5. 分组有效目录由开放权限、账号供应、路由和价格就绪共同决定。普通模型列表可包含媒体，Codex 主模型列表还要求完整对话能力，专用图片/视频模型不作为主对话模型。
6. 请求先按公开模型检查权限和价格，调度再校验完整账号范围、当前状态、票据、额度和并发，最后才调用上游。
7. 同一逻辑请求/WS 轮次使用同一价格版本；上游响应出现未知计费型号时记录待核算，不重放生成。

目录是事实与资料；账号策略是供应声明；分组策略是销售授权；调度是此刻能否承接。不可用一张候选列表替代四层判断。

## 5. 发布和恢复验证

- 先交付已审查的共享修复，按项目规范从 main 传播 TapModels；生产部署另行执行。
- 部署前后保留各分组 mode、白名单和排除项，不自动批量降级成“不限制”。管理员在新版编辑页保存时，以可见勾选结果转换对应分组；账号空名单按本次明确约定变为全部接受。
- 同一账号同时核对数据库目录和调度缓存的凭据范围，不能只测账号直连或只读广场。
- 验证 HTTP/WS 准入、Claude Messages 调度、普通/高级 OpenAI 调度；启用与关闭自动同步都不能改变固定名单。
- 分别检查可用、缺价、明确撤权、限流及模型不在名单的情况；不能以“没有 503”为代价放宽授权。
- 本次已运行 service、handler、admin、server/middleware/routes、repository 的 unit 套件；界面简化后，账号相关组件、分组表单、目录管理及创建接口共 666 项前端测试通过。此前还运行过密钥配置测试。类型检查、ESLint、前后端构建通过。新增四类服务回归在修正前失败、修正后通过。未做生产推理验收或部署。

当前残余限制：所有路由的 Codex 能力仍取交集；部分账号资料不足可能使某个型号暂时不进入 Codex 主模型目录。新型号缺价仍不发布为可销售型号。关闭自动同步后，账号 follow 快照仍会过期，需手工刷新；这些是明确保留的业务规则。

## 后续业务简化

本报告中的 fixed/follow/legacy 指故障发生时的旧实现。后续按最终需求删除运行时模式和排除规则：分组只按保存名单开放，账号按保存名单供应（空账号名单接受全部）。旧 follow 按保存名单解释，不再跟随发现自动授权；原有模式的诊断不再作为现行配置建议。现行流程、兼容范围与升级注意事项见 [MODEL_CATALOG.md](MODEL_CATALOG.md)。本次未部署或改写生产配置。
