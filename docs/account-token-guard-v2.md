# 凭证运营（已退役）

> 本文仅保留为历史设计记录。`/admin/token-guard-v2` 页面、接口、凭证守护后台任务和自动重新登录 worker 已于 2026-09-29 移除；手动账号重新授权流程继续保留。

入口：**管理侧栏 → 凭证运营**（`/admin/token-guard-v2`）。不导入、改写或自动启用退役的凭证守护配置。新安装没有巡检账号，不会自动探测全部账号。

## 本地适配范围

仅保留逐账号登记、模型列表巡检、加密登录配置、持久化任务和独立 Worker。旧外部凭证守护已经退役，本次不恢复它的路由、默认第三方地址和自动导入；不引入 Mihomo 或独立 BPS 平台。侧栏入口为“凭证运营”，路由沿用兼容的 TokenGuardV2 名称，使用现有盾牌图标。

## 使用与默认行为

1. 添加现有 OpenAI OAuth 母账号，不支持凭据影子、PAT 或 Agent Identity。
2. 选择邮箱 + 密码（可选 TOTP 长期密钥），或邮箱 + OTP 邮箱 API URL。编辑时留空保留已保存的秘密；切换登录方式会清除旧方式的秘密。
3. 自动重登默认关闭，需要管理员主动勾选。在本页账号编辑窗口分别设置“启用巡检”和“自动重登”。列表的暂停/恢复按钮控制后续自动巡检；手动巡检、手动重登仍可使用。暂停或移除巡检账号不会取消已经进入重登队列的任务。
4. 在“巡检规则”页配置间隔、阈值和冷却。默认正常巡检 30 分钟、鉴权失败复检 5 分钟、失败阈值 2 次、重登冷却 30 分钟。保存规则后已启用账号立即重新排期；后台每分钟领取一次到期账号，实际时间有调度误差。

巡检读取现有 access token，通过现有 OpenAI 模型列表请求判断凭据状态，不发送付费生成请求。401/403 或明确的令牌拒绝归为鉴权失败；其余异常归为临时失败。模型列表可访问并不能证明所有生成模型、额度或权限可用。每轮最多领取 10 个账号，轮次预算 90 秒，单次探测预算 30 秒。数据库租约防止多个实例同时巡检同一账号。

鉴权失败达到阈值且开启自动重登时，创建持久化任务，由独立 Worker 执行。活跃任务的唯一索引防止重复排队。重登成功前校验账号身份及原凭据快照；原子写回新凭据、完成任务、恢复账号调度并写入调度通知。并发手动编辑或令牌刷新后，旧任务不能覆盖新凭据。除凭据 CAS 外，本地额外要求账号 updated_at 不晚于任务创建时间；排队后的手动暂停、状态/代理修改也会阻止旧任务写回。

## Worker 与秘密

- API 必须配置固定的 `TOTP_ENCRYPTION_KEY`，用于现有 `SecretEncryptor`；未设置时拒绝保存登录秘密。密码、TOTP 和邮箱 API URL 加密落库。管理接口只返回配置标志和脱敏 URL。不要轮换密钥后直接丢弃旧密钥或备份。
- API 与 Worker 分别配置相同的 `OPENAI_REAUTH_WORKER_TOKEN`，至少 32 字符，使用随机高熵值。未配置时 Worker 路由拒绝请求。Worker 持有的此令牌可领取登录秘密，只能交给受信任的进程，不应暴露到公网。
- `SUB2API_BASE_URL` 指向 API。远端连接要求 HTTPS；仅 localhost 测试允许 HTTP。邮箱私网主机必须在 `OPENAI_REAUTH_TRUSTED_OTP_HOSTS` 中精确放行，使用 HTTPS；默认拒绝私网解析和重定向。
- 邮箱模式依赖外部 Turb 纯协议目录（`CODEX_PROTOCOL_ROOT` 或 `TURB_ROOT`）；密码/TOTP 模式另外依赖 [toSub2](https://github.com/poxiao33/toSub2) 的 `src/protocol-login.mjs`（`TOSUB2_ROOT`）和 Node.js。协议实现不包含在本仓库，部署者必须自行审核并固定兼容的提交。当前 Dockerfile 使用调用者提供的 build context，**不会自动锁定这些外部目录的版本**。
- 可选镜像构建：`docker build --build-context turb=/path/to/turb --build-context tosub2=/path/to/toSub2 -f tools/Dockerfile.openai-oauth-reauth-worker .`。命令只构建 Worker，不部署 API。运维编排与生产发布不属于此功能 PR。
- 重登出口可以跟随账号代理，或指定现有代理池中的代理；不引入新的节点管理器。静态代理支持 socks5h。
- 密码/TOTP 通过子进程环境传递；代理 URL 可能包含代理凭据并作为协议进程参数传入，因此 Worker 主机上的进程信息也必须受保护。不要记录 Worker 响应或上传临时 OAuth 文件。

## 迁移与回滚

本地新增四个凭证运维迁移（254、255、256、257），与已有同编号其他名称的文件共存；迁移按完整文件名记录，不修改已发布迁移。新表只有管理员显式配置后使用，不导入旧守护账号。

回退二进制不会撤销数据库迁移或删除已保存秘密。停用时先暂停巡检、停止 Worker，等待或处理已排队任务，再回退应用；保留加密密钥及数据库备份。
