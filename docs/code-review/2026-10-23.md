## 已确认问题

### [P2] 统一 Key 导出与超管共享管理范围
位置：审查输入 backend/internal/service/api_key_data.go:88、:94、:105。

超管 A 的个人 Key 列表已包含超管 B 的 Key，界面也允许勾选导出，但导出仍逐项硬判所有者；选中 B 的 Key 返回不存在，按筛选导出则静默漏掉共享 Key。整改复用仓储实时 apiKeyManagementScope/VerifyOwnership，筛选范围取服务端用户角色；仓储拒绝时整份导出失败。导入仍不覆盖其他用户的 Key。

### [P2] 在 Chat 入口拒绝无法解析的 Responses 会话状态
位置：审查输入 backend/internal/service/upstream_protocol_routing.go:123、openai_gateway_chat_completions.go:145。

adaptive 或按模型路由账号将 Responses 形状请求转到 Chat Completions 时，转换 DTO 丢弃 conversation、prompt、context_management，转换器也忽略 previous_response_id。即使 input 非空，它仍可能只是续轮增量，导致在不完整历史上生成并计费。原 Responses 入口已有明确拒绝，但 Chat 入口遗漏。整改抽取原检查为一份规则，两个入口均在上游调用前返回带参数名的 400；无状态完整输入继续转换。

### [P2] 修复默认测试构建对 unit 夹具的依赖
位置：审查输入 backend/internal/service/openai_unified_scheduler_test.go:145、:167。

无构建标签的两个调度测试引用只在 unit 标签下定义的 newStickyTTLCacheStub，默认 service 测试包无法编译。将这两个用例移至既有 unit 测试文件并保留断言，其余调度测试继续参与默认构建。
